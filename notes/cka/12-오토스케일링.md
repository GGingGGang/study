# 12. 오토스케일링

> 도메인: 워크로드와 스케줄링 (15%)
> 시험 포인트: 2025 개정판 신규 항목 "워크로드 오토스케일링 구성". HPA 생성(명령형 + YAML)이 핵심. metrics-server 의존성을 알아야 한다.

---

## 1. 스케일링 3종 정리

| 종류 | 대상 | 도구 |
|---|---|---|
| **수평(Horizontal)** | Pod 개수 | HPA |
| **수직(Vertical)** | Pod의 requests/limits | VPA (별도 설치) |
| **클러스터** | 노드 개수 | Cluster Autoscaler / Karpenter (클라우드) |

## 2. 사전 조건 — metrics-server

HPA는 리소스 메트릭을 **metrics-server**에서 가져온다. 없으면 HPA가 `<unknown>` 표시.

```bash
kubectl top nodes            # 동작하면 metrics-server 있음
kubectl get pods -n kube-system | grep metrics-server
kubectl get apiservices | grep metrics    # v1beta1.metrics.k8s.io
```

또한 **대상 Pod에 `resources.requests`가 설정돼 있어야** CPU/메모리 사용률(%) 계산이 가능하다.

## 3. HPA (HorizontalPodAutoscaler)

### 명령형 생성 (가장 빠름)
```bash
kubectl autoscale deployment web --min=2 --max=10 --cpu-percent=70
kubectl get hpa
kubectl describe hpa web
```

### YAML (autoscaling/v2 — 메모리/커스텀 메트릭은 v2 필수)
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization        # requests 대비 %
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: AverageValue       # 절대값 기준
        averageValue: 500Mi
```

### 동작 원리
- 기본 15초마다 메트릭 확인
- 목표 레플리카 = ceil(현재 레플리카 × 현재값 / 목표값)
- 급격한 출렁임 방지: 축소는 기본 5분 안정화 창(stabilization window)

### behavior로 스케일 속도 제어 (v2)
```yaml
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
      - type: Pods
        value: 1                  # 1분에 1개씩만 축소
        periodSeconds: 60
    scaleUp:
      policies:
      - type: Percent
        value: 100                # 1분에 최대 2배
        periodSeconds: 60
```

### 확인/테스트
```bash
kubectl get hpa web --watch
# 부하 생성 예
kubectl run load --image=busybox --restart=Never -- \
  sh -c "while true; do wget -qO- http://web; done"
```

> **주의**: HPA가 관리하는 Deployment에 `kubectl scale`을 하거나 YAML의 replicas를 고정하면 HPA가 다시 덮어쓴다. HPA 사용 시 Deployment의 replicas 필드는 제거하는 것이 정석.

## 4. VPA (VerticalPodAutoscaler) — 개념 위주

- 별도 설치하는 컴포넌트 (CRD + 컨트롤러, 즉 Operator 패턴)
- Pod의 requests/limits를 사용 이력 기반으로 추천/자동 조정
- 모드:
  - `Off` — 추천만 (recommendation)
  - `Initial` — 생성 시에만 적용
  - `Auto` / `Recreate` — Pod를 재생성하며 적용 (재시작 수반!)
- **HPA(CPU/메모리 기준)와 VPA를 같은 메트릭으로 함께 쓰면 충돌** — 같이 쓰려면 HPA는 커스텀 메트릭으로

```yaml
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: web-vpa
spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  updatePolicy:
    updateMode: "Auto"
```

## 5. Cluster Autoscaler (개념만)

- Pending Pod가 생기면 노드를 추가, 노드가 놀면 축소 — 클라우드 프로바이더 연동 필요
- CKA에서는 "노드 수준 확장은 Cluster Autoscaler" 정도의 개념만 알면 충분

## 6. 수동 스케일 (복습)

```bash
kubectl scale deploy web --replicas=5
kubectl scale statefulset db --replicas=3
kubectl scale rs web-abc123 --replicas=0
```

## 7. 체크리스트

- [ ] `kubectl autoscale deploy ... --min --max --cpu-percent`를 안 보고 친다
- [ ] HPA에 metrics-server + 대상 Pod의 requests가 필요함을 안다
- [ ] autoscaling/v2 YAML(scaleTargetRef, metrics, min/max)을 쓸 수 있다
- [ ] Utilization(%) vs AverageValue(절대값) 차이를 안다
- [ ] VPA 모드와 HPA 충돌 이슈를 개념으로 안다
