## 2. 철칙 5가지

1. **문제마다 `kubectl config use-context ...` 먼저** (문제 상단 복붙)
2. ssh로 노드 들어갔으면 **작업 후 반드시 `exit`**
3. 만들었으면 **반드시 검증** (`k get`, `k describe`, curl/wget 테스트)
4. 막히면 **flag 걸고 다음 문제로** (배점 낮은 문제에 15분 쓰지 말 것)
5. YAML은 **문서에서 복사**하거나 `$do`로 생성 — 맨손으로 치지 않는다

```bash

```

## 4. 도메인별 급소 요약

### 클러스터 관리 (25%)
```bash
# 업그레이드: 저장소버전변경 → kubeadm → (첫CP) upgrade apply / (기타) upgrade node
#            → drain → kubelet·kubectl 설치 → systemctl daemon-reload && restart kubelet → uncordon
# etcd 백업
ETCDCTL_API=3 etcdctl snapshot save /backup/snap.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
# etcd 복원: etcdutl snapshot restore snap.db --data-dir /var/lib/etcd-new
#           → /etc/kubernetes/manifests/etcd.yaml 의 hostPath 변경
kubeadm token create --print-join-command
kubeadm certs check-expiration && kubeadm certs renew all
```

### RBAC (핵심 표기)
- SA 주체: `system:serviceaccount:<ns>:<name>`
- core 리소스의 apiGroups는 `""`
- ClusterRole+RoleBinding = 권한을 ns로 좁혀 부여

### 네트워킹 (20%)
- 서비스 DNS: `<svc>.<ns>.svc.cluster.local`
- port(서비스) / targetPort(컨테이너) / nodePort(30000-32767)
- Endpoints 비면: 셀렉터 불일치 / NotReady / Pod 없음
- NetworkPolicy: from/to에서 **대시 하나로 AND↔OR 바뀜**, egress 시 **DNS 53 허용**
- Gateway API: GatewayClass → Gateway(listeners) → HTTPRoute(parentRefs/matches/backendRefs)

### 스토리지 (10%)
- 바인딩 3조건: storageClassName / accessModes / capacity
- WaitForFirstConsumer → Pod 만들기 전 PVC Pending은 **정상**
- Retain → Released → claimRef 수동 제거해야 재사용

### 트러블슈팅 (30%)
```bash
# 노드 NotReady
k describe node X → ssh X → systemctl status kubelet → journalctl -u kubelet
→ /var/lib/kubelet/config.yaml, /etc/kubernetes/kubelet.conf 확인 → restart → exit → 검증
# 컨트롤 플레인 다운 (kubectl 불통)
ssh cp → crictl ps -a → crictl logs <id> → /etc/kubernetes/manifests/*.yaml 오타 수정
# Pod 상태 반사신경
Pending→describe(리소스/taint/PVC) | ImagePullBackOff→이미지명/시크릿
CrashLoop→logs --previous, ExitCode(137=OOM) | CreateContainerConfigError→CM/Secret 참조
```

## 5. 자주 헷갈리는 것 최종 정리

| 헷갈림 | 정답 |
|---|---|
| upgrade apply vs node | apply=첫 컨트롤 플레인만, node=나머지 전부 |
| cordon vs drain | cordon=신규차단만, drain=차단+퇴거 |
| liveness vs readiness | liveness=재시작, readiness=서비스 제외 |
| requests vs limits | requests=스케줄 기준, limits=런타임 상한(mem 초과=OOM) |
| taint vs affinity | taint=노드가 거부, affinity=Pod가 선택 |
| toleration의 착각 | 허용일 뿐 배치 보장 아님 (nodeSelector 병행) |
| Role vs ClusterRole | ns 스코프 vs 클러스터 (nodes/pv는 ClusterRole만) |
| RWO의 단위 | Pod가 아니라 **노드** (RWOP가 Pod 단위) |
| ClusterIP에 ping | 안 되는 게 정상 (iptables 규칙) — curl로 검증 |
| static pod 삭제 | kubectl delete 무효 — **매니페스트 파일 삭제** |
