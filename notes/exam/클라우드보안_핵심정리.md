# 클라우드보안 시험 직전 핵심 정리

## 시험 직전 핵심 정리

클라우드보안은 **어떤 계층을 누가 관리하고, 어떤 신뢰 경계를 통해 공격이 퍼지며, 어떤 통제로 끊는가**를 연결해 공부한다. 범위는 폴더에 제공된 2~7강이다. 아래 내용은 강의의 개념·사례를 통합했으며, 최신 서비스 사양이나 현행 규정 안내가 아니라 시험 복습 자료다.

### 클라우드의 기본 구조와 서비스 모델

강의 정의의 핵심은 온디맨드 셀프서비스, 구성 가능한 자원, 신속한 프로비저닝, 최소한의 이용자 관리 노력이다. 장점은 필요할 때 자원을 확보하는 속도·확장성·운영 부담 감소, 위험은 인터넷 의존·비용 통제·벤더 락인·보안과 프라이버시·공유 인프라·장애다. 사용량이 많으면 클라우드가 항상 저렴한 것은 아니다. 강의의 3천만 원 GPU와 실행당 10만 원 예에서 단순 교차점은 **300회**이며, 실제 비교는 전력·관리·교체·운영기간 등을 포함해야 한다. 2강 [00:01:45–00:19:32].

| 서비스 모델 | 공급자가 제공·관리하는 범위 | 이용자가 중점 관리할 부분 |
|---|---|---|
| IaaS | 물리 인프라·가상화·가상 컴퓨팅 기반 | 게스트 OS, 앱, 데이터, 계정·권한, 네트워크 설정 |
| PaaS | 인프라에 더해 플랫폼·런타임 등 | 앱·데이터·계정 및 서비스 사용 설정 |
| SaaS | 완성된 애플리케이션까지 | 계정·접근 권한, 데이터 사용·분류, 사용 설정 |

이 표는 강의의 계층 구분이며 실제 책임은 서비스에 따라 세부적으로 달라진다. SaaS라도 고객 책임이 0이 되는 것은 아니다. FaaS는 함수 실행 단위, Security as a Service는 보안 기능, DaaS는 데스크톱 환경 등을 서비스로 제공한다. 2강 [00:21:04–00:32:19], 4강 [00:45:20–00:50:08].

| 배포 모델 | 구별 기준 | 고려할 점 |
|---|---|---|
| 퍼블릭 | CSP의 인프라를 서비스로 사용 | 신속한 확장·공유 환경·제공자 의존 |
| 프라이빗 | 단일 조직용 환경 | 높은 통제와 직접 관리 부담 |
| 하이브리드 | 프라이빗과 퍼블릭을 조합 | 민감 데이터 위치와 외부 자원 활용, 연결·운영 복잡성 |
| 멀티 클라우드 | 강의에서는 둘 이상의 퍼블릭 CSP 사용 | 제공자 종속 완화와 도구·정책의 복잡성 |

하이브리드와 멀티 클라우드는 서로 다른 분류 축이며 이름만으로 같은 구성이 아니다. 3강 [00:00:00–00:10:13].

### 자원과 네트워크를 구별하기

리전 안에는 물리적으로 분리된 가용 영역(AZ)이 있고, 가용성·복구를 위해 자원을 분산한다. 로드밸런서는 **트래픽 분배**, 오토스케일링은 **자원 수 증감**이다. 가용성은 필요할 때 서비스에 접근할 수 있는가, 내구성은 저장한 데이터가 손실되지 않고 유지되는가에 초점을 둔다. 2강 [00:32:19–00:49:35].

| 구분 | 정의·강의 예 |
|---|---|
| 객체 스토리지 | 객체 단위 저장, S3 |
| 파일 스토리지 | 파일·디렉터리 방식, EFS·NAS |
| 블록 스토리지 | 디스크 블록처럼 제공, EBS |
| 아카이브 | 장기 보존, S3 Glacier |
| VPN | 떨어진 위치를 공중망 위의 보호된 사설 연결로 연결 |
| VPC | 클라우드 내 가상 네트워크·서브넷·라우팅·접근 경계 |
| VLAN | L2 태그 기반 논리 분리, 강의의 사용 가능 ID 수 4,094 |
| VXLAN | L2 프레임을 UDP로 캡슐화하는 오버레이, 24비트 VNI로 약 $2^{24}$ 세그먼트 |
| SDN | 네트워크 제어·설정을 소프트웨어로 관리하는 접근 |

LVM은 물리 디스크를 논리 볼륨으로 추상화한다. 씬 프로비저닝은 논리 할당량이 실제 물리 용량보다 커질 수 있어 **실사용량을 감시**해야 한다. 실제 100GB에 VM 두 개 각각 80GB를 할당해도 동시에 많이 사용하면 공간 부족이 난다. RAID는 스트라이핑·미러링·패리티의 차이를 구별한다. 강의에서 RAID 5는 최소 3개 디스크와 1개 장애 복구, RAID 6은 최소 4개를 설명한다. 일부 RAID 번호가 자막에서 어긋나 상세 확인 목록을 참조한다. 2강 [00:49:35–00:57:35], 3강 [00:33:30–00:52:32].

### 가상화와 컨테이너

가상화는 물리 자원을 추상화·분할해 VM별로 할당한다. 핵심 요구는 **동등성·충실도, 자원 통제·격리, 성능**이다. 자원 공유로 효율을 얻어도 서로 간섭하거나 다른 고객 데이터에 접근해서는 안 된다. 3강 [00:14:46–00:22:29], 6강 [00:10:59–00:14:23].

| 구분 | 구조 | 장점과 주의 |
|---|---|---|
| Type 1 하이퍼바이저 | 하드웨어 위 직접 실행 | 서버 운영·효율에 적합한 구조. 오버헤드가 전혀 없다는 뜻은 아님 |
| Type 2 하이퍼바이저 | 호스트 OS 위에서 실행 | 설치·사용 편리, 호스트 OS 계층의 영향과 공격면 추가 |
| 완전 가상화 | 게스트 OS를 수정하지 않고 실행 | 호환성, 명령 처리·지원 방식에 따른 비용 |
| 반가상화 | 게스트 수정과 하이퍼콜로 협력 | 처리 효율과 수정·호환성 부담의 절충 |
| 컨테이너 | 호스트 커널 공유, 격리된 실행 환경 | 게스트 OS를 각각 두는 VM보다 가볍지만 커널 공유 위험 |

**Type 1·2는 배치 위치, 완전·반가상화는 구현 방식**이므로 같은 분류가 아니다. Ring 0은 커널, Ring 3은 사용자 권한이라는 CPU 권한 구분을 배우며, 가상화에서 가로채야 하는 요청은 **VM exit → 하이퍼바이저 처리 → VM entry**로 이어진다. 모든 일반 연산이 하이퍼바이저를 거친다는 뜻은 아니다. 바이너리 트랜슬레이션은 명령을 변환해 안전하게 처리하고, SR-IOV는 물리 I/O 장치를 여러 VM에 제공해 처리 경로를 줄이는 방식으로 소개된다. 6강 [00:14:42–00:41:15].

Docker 이미지는 실행 템플릿, 컨테이너는 실행 인스턴스다. 클라이언트는 명령을 요청하고 데몬이 처리하며 레지스트리는 이미지를 저장·배포한다. **cgroups는 자원 한도·사용량 회계, namespaces는 프로세스와 자원 가시성 격리**다. 3강 [00:52:34–01:02:47].

### 공격과 보안 목표

| 공격 | 강의의 주요 흐름 | 피해·방어에서 볼 점 |
|---|---|---|
| DDoS | 봇넷 구축·제어 → 표적 조사 → 다수 요청 | 가용성 저하. 정상 서비스 접근과 트래픽·자원 고갈을 연결 |
| 랜섬웨어 | 침투 → 암호화·접근 차단 → 백업 삭제 → 몸값 요구 | 원본뿐 아니라 복구 경로까지 공격. 백업 보호·복구 점검 필요 |
| APT | 초기 침투 → 발판 → 권한 상승 → 정찰 → 탈취·파괴·감시 | 장기 은밀 침투, 스피어 피싱·측면 이동·지속 감시 고려 |
| IoT 장악 | 기본 비밀번호·미패치 펌웨어·탈취 접근권한 | 한 기기의 취약점이 봇넷·내부 침투의 발판으로 확장 |
| 계정·키 유출 | 유출 자격 증명을 API·CLI로 자동 악용 | 정보 유출뿐 아니라 자원 생성·요금 피해. MFA·임시 자격 증명·최소 권한·감사 |
| 구성·운영 실수 | 잘못된 권한·방화벽 규칙·중요 리소스 삭제 | 설정 검증, 변경 관리, 승인·복구·로그를 함께 설계 |

강의 사례의 연도·피해 수치는 상세본에 보존했으며, 시험 답안에서는 공격 이름뿐 아니라 **침투 경로 → 확산 → 피해 자산 → 대응 통제**를 쓴다. 4강 [00:07:05–00:22:10], 5강 [00:01:45–00:09:10].

클라우드 보안의 다섯 원칙은 **가용성, 기밀성, 무결성, 통제, 감사**다. 데이터 위치·법규 차이, 멀티테넌트 격리, 제공자 지속성, 벤더 락인, 사고 통지·조사 협조, 재해복구·업무 연속성도 고려한다. 4강 [00:35:42–00:43:50].

### 공유 책임 모델

**Security of the Cloud**는 데이터센터·전력·물리 하드웨어·기반 네트워크·가상화 등 클라우드 자체를 보호하는 제공자 책임이다. **Security in the Cloud**는 고객 데이터·계정·권한·앱·고객이 설정하는 보안 규칙 등 사용 환경을 보호하는 고객 책임이다. 서비스 모델별 경계가 달라지는 점이 핵심이다. IaaS의 게스트 OS는 고객이, SaaS의 OS는 제공자가 관리한다는 예를 기억한다. 4강 [00:45:20–00:50:08].

계층은 **데이터 → 워크로드 → 가상 네트워크 → 가상화 관리**로 연결한다. IAM은 신원·접근 권한, 보안 그룹·ACL은 네트워크 접근, KMS·HSM은 키 보호, 로그·리소스 구성 모니터링은 변화와 사고의 관찰을 돕는다. 컨테이너·서버리스에서는 이미지·런타임·오케스트레이션·함수·이벤트의 보안도 필요하다. 4강 [00:51:04–00:56:27].

### 경계 보안과 제로트러스트

경계 모델은 외부를 불신하고 내부를 상대적으로 신뢰한다. 분산 클라우드·원격접속에서 경계가 모호하고, 한번 내부에 들어온 공격자의 측면 이동을 놓치기 쉽다. 제로트러스트는 **네트워크 위치나 과거 인증만으로 신뢰를 부여하지 않고 자원 접근마다 신원·권한·기기 상태·맥락을 평가**한다. 특정 제품을 도입하거나 모든 레거시를 폐기한다는 뜻이 아니다. 5강 [00:21:17–00:43:44].

일곱 원리의 강의상 요지는 모든 서비스·데이터를 자원으로 취급, 위치와 무관한 통신 보호, 세션별 최소 권한, 동적 정책, 자산 상태의 지속 점검, 엄격한 인증·인가와 위험 재평가, 상태·로그 수집을 통한 정책 개선이다. 원문 번호·표현이 불완전한 부분은 확인 목록에 남겼다. 5강 [00:44:10–00:47:13].

| 구성요소 | 역할 |
|---|---|
| PDP | 접근 허용 여부를 결정하는 부분. PE와 PA로 구성 |
| PE | 정책·신뢰 정보·상태로 허용·거부 판단 |
| PA | 판단 결과에 따라 경로를 설정·해제하고 집행을 관리 |
| PEP | 실제 요청을 허용·차단하는 집행 지점 |

CDM, 준수 상태, 위협 정보, 로그가 판단에 들어가며 요청 주체와 자원 사이에서 결정·집행을 분리한다. **결정은 PDP, 실제 집행은 PEP**라는 구별이 중요하다. 5강 [00:47:13–00:51:31].

예측 보안의 **VIA는 Visibility → Intelligence → Automation**이다. 로그가 있어도 관찰 가능한 정보로 만들고 분석해 대응으로 연결하지 않으면 충분하지 않다. 강의의 RMF 흐름은 **분류 → 선택 → 구현 → 평가 → 승인 → 모니터링 → 반복**이다. RMF는 위험 관리에서 무엇을 할지, ZTA는 접근 통제를 어떻게 구성할지에 초점을 두며 서로 보완한다. 5강 [00:12:50–00:15:07; 00:54:17–00:56:52].

클라우드 네이티브는 컨테이너·마이크로서비스·서비스 메시·불변 인프라·선언적 API를 활용한다. 보안은 **Cloud, Cluster, Container, Code** 네 층 전체에 적용한다. 인프라·IAM에서 시작해 클러스터 RBAC·네트워크 정책, 이미지·레지스트리·런타임, 코드·의존성·시크릿과 서비스 간 통신까지 연결한다. 5강 [00:59:15–01:04:44].

### 가상화 위협 비교

| 위협 | 출발점·핵심 원리 | 피해와 방어 |
|---|---|---|
| VM Escape | 게스트 내부에서 취약점을 통해 격리 경계를 넘어감 | 호스트·하이퍼바이저·다른 VM으로 영향. 패치·최소 기능·최소 권한·격리·모니터링 |
| Hyperjacking | 하이퍼바이저 제어권 장악. 강의는 호스트 OS가 침해된 Type 2 경로를 중심으로 설명 | VM 전반의 통제·감시 가능. 호스트·관리면 보호, 무결성·권한·패치·탐지 |
| VM Sprawl | 생성된 VM을 통제·정리하지 못해 무분별하게 증가 | 자원·비용 낭비, 미패치·미관리 자산. 소유자·목적·수명주기·자원 사용량 관리 |

### 자가 점검

아래 문항은 복습용이며 교수의 출제 예고가 아니다.

1. **SaaS를 쓰면 보안 책임은 전부 제공자에게 가는가?** 아니다. 계정·권한·데이터 사용·고객 설정 책임이 남는다.
2. **컨테이너와 VM의 핵심 격리 차이는?** VM은 게스트 OS를 포함하고, 컨테이너는 호스트 커널을 공유한다.
3. **cgroups와 namespaces를 바꾸어 설명하면 왜 틀리는가?** 자원 한도·회계와 가시성 격리라는 역할이 다르다.
4. **MFA만 도입하면 제로트러스트인가?** 인증은 일부이며 자원별 인가·최소 권한·상태·동적 정책·지속 관찰이 함께 필요하다.
5. **IDS와 IPS 차이는?** IDS는 탐지·보고, IPS는 차단·예방까지 수행한다.
6. **교차 VM 부채널과 VM Escape 차이는?** 전자는 공유 자원 흔적의 추론, 후자는 격리 경계를 넘는 침해다.
7. **마이그레이션에서 암호화 외에 필요한 것은?** 출발지·목적지 인증, 이동 권한, 관리면 보호, 격리·모니터링이다.
