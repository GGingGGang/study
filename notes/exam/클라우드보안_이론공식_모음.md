# 클라우드보안 이론공식 모음

상세 정의·기호·성립 조건과 예제 풀이는 통합 요약의 해당 강의를 함께 읽으세요.

## 클라우드보안 2

- 클라우드 컴퓨팅 정의의 네 요소: 온디맨드 셀프서비스, 구성 가능한 자원, 신속한 프로비저닝, 최소한의 관리 노력. [00:01:45–00:03:35]
- 온프레미스와 클라우드: 직접 장비 구축·소유·관리 대 원격 자원 임대·사용량 기반 지불. 클라우드는 인터넷 의존성이 있다. [00:15:07–00:16:23] [00:20:06–00:20:58]
- 비용 비교 원리: 초기 구축비와 지속 사용료의 누적 비용을 사용량·기간·교체 비용에 따라 비교한다. 교수의 예시에서 3천만 원 GPU와 1회당 10만 원 클라우드 실행은 300회가 단순 비용상 교차점이다. [00:16:23–00:19:32]
- 서비스 모델: IaaS(가상 인프라 제공, 이용자는 OS 위 관리), PaaS(개발 플랫폼·런타임까지 제공), SaaS(완성 애플리케이션 제공). [00:21:04–00:29:14]
- XaaS 예: FaaS(함수 단위 기능), Security as a Service(방화벽·IDS·IPS 등), AI 서비스, Desktop as a Service. [00:29:14–00:32:19]
- 가용 영역: 한 리전 안의 물리적으로 분리된 데이터센터 단위. 존 간 빠른 연결을 통해 통신한다는 설명. [00:36:09–00:37:48]
- 자원 관리 인터페이스: 웹 콘솔, API, CLI. [00:37:48–00:39:30]
- 컴퓨트 운영: 하이퍼바이저가 VM을 만들고, 로드 밸런서가 트래픽을 여러 VM에 나누며, 오토스케일링이 수요에 따라 자원을 증감한다. [00:43:06–00:48:15]
- 스토리지 분류: 객체(S3), 파일(EFS), 블록(EBS), 장기 아카이브(S3 Glacier). [00:49:35–00:52:12]
- VPN은 분리된 위치를 사설 연결처럼 이어 주며, VPC는 클라우드 내 가상 네트워크와 서브넷·라우팅을 통해 인스턴스 접근을 분리·통제한다. [00:53:01–00:57:35]
- DB 서비스, 리프트 앤 시프트 마이그레이션, 데이터 분석, AI·머신러닝 서비스는 각각 관리형 데이터베이스, 기존 환경의 클라우드 이전, 사용량 분석, 준비된 모델·컴퓨팅 환경의 서비스 제공이다. [00:57:35–01:01:12]

## 클라우드보안 4

1. **제로데이 취약점**: 보안 패치가 나오기 전에 악용되는 취약점. 강의 사례는 Exchange Server 관련 취약점이다. [00:00:46–00:00:59]
2. **공격 진화 축**: X축=대규모 피해 가능성, Y축=복잡성·노련함. 침입·시스템 침해·DoS에서 고도화 DDoS, 사회·정치 목적 핵티비즘으로 변화한다. [00:01:56–00:02:32]
3. **IoT 공격 경로**: 기본 비밀번호 악용, 내부 네트워크 침투, 미패치 펌웨어 취약점, 원격 접근권한 탈취 → 기기 장악·봇넷·정보 거래. [00:07:33–00:08:20]
4. **DDoS**: 다수 장치의 동시 대량 요청으로 정상 이용자의 서비스 접근을 막는 공격. 절차는 봇넷 구축→제어→표적 조사→동시 요청 실행→서비스 중단·손실. [00:10:17–00:13:56]
5. **랜섬웨어**: 침투→중요 파일 암호화/접근 차단→백업 삭제→피해 통보→몸값 요구. [00:14:03–00:15:54]
6. **APT**: 특정 조직·국가 대상 장기 지속 공격. 초기 침투→발판 구축→권한 상승→내부 정찰→탈취·파괴·감시. 스피어 피싱은 특정 개인·조직을 겨냥한 피싱이다. [00:17:22–00:19:56]
7. **웹의 구분**: 강의는 표면 웹(검색 가능한 일반 웹), 딥웹(검색에 노출되지 않는 콘텐츠), Tor 등 별도 접근 방식의 다크웹을 대비하며 다크웹의 불법 거래 사례를 강조한다. **용어 보충:** 검색 노출 여부와 합법성은 다른 기준이며 딥웹·다크웹 자체가 합법 또는 불법을 결정하는 것은 아니다. [00:22:24–00:23:28]
8. **클라우드 보안 5원칙**: 가용성(필요할 때 접근), 기밀성(데이터 비밀 유지), 무결성(승인되지 않은 손실·수정 방지), 통제(Control; 데이터 사용·노출을 관리하고 부주의·악의적 처리를 방지), 감사(Audit; 환경의 활동을 관찰·기록·모니터링). 동적 환경에서 실시간 모니터링과 로그 분석이 중요하며 원칙은 상호 연결된다. [00:35:42–00:38:29]
9. **클라우드 보안 우려**: 네트워크 가용성 및 대역폭, 제공자 지속 가능성과 벤더 락인(고유 API·구조로 이전이 어렵고 비용이 큼), 재해복구·비즈니스 연속성, 사고 통지·조사 협조, 제공자 내부 정책의 투명성 부족. [00:38:31–00:42:02]
10. **물리 통제권 상실·데이터 위치**: 제공자는 효율·가용성을 위해 데이터를 여러 센터로 옮길 수 있고, 국가별 데이터 보호 법규 차이와 준수 문제가 생길 수 있다. 멀티테넌트 공유 인프라에서는 데이터 분리·공유 인프라의 보안 영향을 고려해야 한다. 새로운 클라우드 특유 공격 표면과 제공자 구현 품질 의존도 대응을 어렵게 한다. [00:42:06–00:43:50]
11. **위협 변화 비교**: 교수 설명상 2016년에는 데이터 침해가 주요 우려였고, 2025년에는 미스컨피규레이션(구성 오류)과 변경 관리 미흡이 두드러진다. 복잡한 환경에서 관리 실수가 보안 격차를 만든다. [00:43:52–00:44:41]
12. **공유 책임 모델**: Security **of** the Cloud(클라우드 자체의 보안)는 제공자 책임: 데이터센터·건물·전력·냉각, 하드웨어, 네트워크 인프라, 하이퍼바이저, 호스트 OS 및 기본 서비스. Security **in** the Cloud(클라우드 안에서 고객이 구성·사용하는 보안)는 고객 책임: 데이터 암호화·분류·백업, 계정·접근권한, 애플리케이션 설정·취약점, 네트워크·방화벽 규칙·보안 그룹. IaaS·PaaS·SaaS에 따라 OS·네트워크 제어·애플리케이션·신원 및 인프라 책임 배분이 달라진다. 강의에서 명시한 예: IaaS의 OS는 고객, SaaS의 OS는 제공자 책임. [00:45:20–00:50:08]
13. **온프레미스와 클라우드 보안 계층**: 온프레미스는 외곽에서 안쪽으로 물리/데이터센터→네트워크→서버·DB→데이터를 방어하는 성벽형 계층 모델. 클라우드는 데이터 보안을 유지하면서 ① 워크로드(서버·DB 보안 대체) ② 가상 네트워크(물리 네트워크 대체) ③ 가상화 관리 보안을 포함한 네 계층으로 설명한다. VM·컨테이너·서버리스 관리가 추가 과제다. [00:51:04–00:52:38]
14. **클라우드 계층별 보호**: 데이터는 전송 중·저장 시·처리 중 암호화. 워크로드는 서버 외 컨테이너 이미지·런타임·오케스트레이션 및 서버리스 함수·이벤트 보호. 가상 네트워크는 SDN(Software-Defined Networking)으로 설정·접근 제어를 소프트웨어화하고 방화벽·로드밸런서·VPN 사용. 가상환경 관리에는 Infrastructure as Code, 자동 보안 검사, 컴플라이언스 모니터링 포함. [00:52:56–00:54:30]
15. **구현 구성요소 비교**: 온프레미스 자체 리소스 관리 vs 클라우드 콘솔(AWS 콘솔 예); SSO 중심 vs 클라우드 계정 기반 IAM(Identity and Access Management); 하드웨어 네트워크 보안 vs 보안 그룹·네트워크 ACL 등 소프트웨어 경계; 키 관리에 KMS(Key Management Service)·HSM(Hardware Security Module); 기존 네트워크·서비스·보안 로그 외 클라우드 리소스 구성 상태 추가 모니터링; 물리 데이터센터 보안은 클라우드 제공자 담당. [00:54:34–00:56:27]

## 클라우드보안 5

- 경계/캐슬 모델: 외부 불신·내부 신뢰, 방화벽·DMZ·IDS 등 경계 중심 방어. 클라우드 분산·원격 환경에서 경계가 모호하고 내부 침해 후 측면 이동에 취약. (00:21:17–00:23:51)
- 예측 보안의 VIA: Visibility(로그를 인사이트로 만들고 시각화) → Intelligence(통계·예측·ML/DL로 분석) → Automation(예측/사고 시 보호 조치 자동 실행). (00:13:03–00:15:07)
- 보안 기술 도입 성숙도: 하이프 사이클을 참고해 혁신 초기 기술은 파일럿으로 검증하고, 입증된 운영 기술과 성숙 예상 시점을 전략에 반영. 공식·계산식은 없음. (00:16:28–00:18:54)
- 클라우드 보안 도메인: 위험 관리, 접근 제어, 네트워크 보안, 데이터 보안, 가상화 보안. (00:19:45–00:20:59)
- 제로트러스트: Never Trust, Always Verify. 위치나 기존 신뢰 대신 매 접근·세션에서 신원·권한·기기/자산 상태를 검증하고 최소 권한과 동적 정책을 적용. (00:34:48–00:36:53, 00:44:10–00:47:13)
- ZTA 구성: PDP(PE+PA)가 정책을 판단·관리하고 PEP가 자원 앞에서 집행. CDM·준수 상태·위협 정보·로그가 판단에 입력되며 신뢰 구간을 최소화한다. (00:47:13–00:51:31)
- RMF 순환: 분류 → 선택 → 구현 → 평가 → 승인 → 모니터링 → 반복. 강의에서 NIST SP 800-37로 들리는 출처를 언급. (00:54:17–00:55:12)
- 프레임워크/아키텍처: 각각 보안을 위해 무엇을 할지(거버넌스·절차·역할·평가)와 어떻게 구현할지(구조·메커니즘)를 다룸. RMF와 ZTA는 상호 보완. (00:55:12–00:56:52)
- 클라우드 네이티브 핵심: 컨테이너, 서비스 메시, 마이크로서비스, 불변 인프라, 선언적 API. 이점은 확장성·서비스 회복성·빠른 배포·이식성. (00:59:15–01:01:34)

## 클라우드보안 6

1. **가상화·VMM**: 물리 자원을 추상화해 가상 CPU·NIC·스토리지 등을 게스트에 제공하고 VM을 관리한다. VM 파일 캡슐화는 이동·마이그레이션을 돕는다. [00:00:17]–[00:03:00]
2. **자원 풀·동적 할당·대상 분류**: 자원 풀에서 VM별로 필요한 양을 배정한다. 가상화 대상은 서버·데스크톱·애플리케이션·하드웨어다. [00:03:12]–[00:10:11]
3. **하이퍼바이저 요구사항**: fidelity(물리 환경과 기능적 동일성), isolation(안전한 격리), performance(오버헤드 최소화). [00:10:59]–[00:14:23]
4. **배치 유형**: Type 1/native/bare-metal은 하드웨어 위에서 실행, Type 2/hosted는 호스트 OS 위에서 실행. [00:14:42]–[00:18:33]
5. **구현 방식**: full virtualization(게스트 수정 불필요), para-virtualization(게스트 커널 수정·hypercall), hybrid, OS-level(컨테이너; Docker는 언급 후 상세 제외). [00:18:39]–[00:25:16]
6. **권한 링·듀얼 모드**: Ring 0 최고 권한/커널, Ring 3 사용자 권한. 사용자 모드에서 시스템 콜·트랩을 거쳐 커널 모드로 전환한다. [00:28:46]–[00:31:30]
7. **VM 특권 요청 처리 절차**: 게스트 요청 → VM exit → 하이퍼바이저 처리/에뮬레이션 → 호스트 자원 작업 → VM entry로 복귀. [00:31:34]–[00:35:27]
8. **바이너리 트랜슬레이션**: 명령을 분석해 특권 동작을 안전한 명령으로 변환한다. 소프트웨어 구현은 하드웨어 지원보다 오버헤드가 크다. [00:35:35]–[00:38:18]
9. **성능 비교·SR-IOV**: 강의상 네이티브 > 세미가상화 > 풀 가상화 > 에뮬레이션. SR-IOV는 하나의 물리 I/O 장치를 복수 VM이 공유해 처리 경로를 줄인다. [00:38:23]–[00:41:15]
10. **위협 표적·진화**: 호스트/하드웨어·VM·구성 파일·원격 관리·게스트 OS·가상 네트워크. 게스트 공격 → VM 탈출 → 하이퍼바이저 → 물리 호스트로 확대된다. [00:50:03]–[00:52:37]
11. **IDS/IPS**: IDS는 탐지·보고, IPS는 탐지·실시간 예방/차단. [00:54:03]–[00:55:23]
12. **운영 통제 원리**: 게스트 패치, 이미지 무결성, VM/테넌트 격리, 재할당 전 데이터 삭제, 가상 네트워크·방화벽 변경 관리, 실시간 모니터링, 이미지·종속 소프트웨어 패치 관리. 하이퍼바이저 침해는 다수 VM의 통제권으로 파급된다. [00:43:27]–[00:45:51], [00:52:41]–[01:01:15]
