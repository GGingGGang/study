# 클라우드보안 6강 가상화 보안

## 전체 내용

### 가상화와 클라우드 인프라

가상화는 주어진 물리 하드웨어 자원으로 실제 머신처럼 동작하는 논리적 머신을 만들고 관리하는 기술이다. 클라우드의 핵심 기반이며, 하이퍼바이저는 컴퓨팅 자원을 VM에 배분하고 VM을 생성·관리한다. 하이퍼바이저는 VMM(Virtual Machine Monitor 또는 Virtual Machine Manager)이라고도 한다. 가상화 전에는 물리 서버마다 OS와 애플리케이션이 있지만, 가상화에서는 하드웨어 위의 가상화 계층이 여러 게스트 OS에 가상 하드웨어를 제공한다. 게스트 OS는 하이퍼바이저를 통하여 물리 자원에 접근하고, VM끼리는 서로 격리되어야 한다. VCPU·VNIC는 실제 CPU·NIC가 VM마다 따로 있다는 뜻이 아니라, 하이퍼바이저가 가상 장치로 제공하는 것이다. VM 구성은 파일로 캡슐화될 수 있어 종료 후 파일을 옮기면 다른 머신에서 같은 VM을 실행(마이그레이션)할 수 있다. [00:00:17]–[00:03:00], [00:07:32]–[00:09:13]

가상화는 CPU·메모리·스토리지 등 물리 자원 풀에서 VM마다 필요한 양을 동적으로 할당해 여러 서버 역할을 한 물리 머신에 통합한다. 물리 서버를 기능마다 사는 것보다 자본지출(CAPEX)을 절감하고 중앙 집중 관리와 증설을 쉽게 할 수 있다. 다만 PCI 슬롯 같은 물리적 증설 한계는 남는다. 클라우드 인프라는 스토리지·계산·분산 콘텐츠 서버와 네트워크(라우터·스위치·AP 등)의 자원 풀을 가상화해 다수 사용자에게 제공한다. 가상화 대상에 따라 서버·데스크톱·애플리케이션·하드웨어 가상화로 분류한다. 교수 설명상 가상 스토리지 할당량은 물리 디스크 크기와 일대일로 같을 필요가 없고, 실제 용량보다 크게 할당할 수도 있다. [00:03:12]–[00:10:11]

### 하이퍼바이저의 기준과 유형

하이퍼바이저의 세 요구사항은 ① 충실도(fidelity): VM의 OS·애플리케이션이 물리 머신에서와 동일하게 작동(성능 차이는 가능) ② 안전한 격리(isolation): VM 간 및 게스트와 호스트 간 무단 접근 방지 ③ 성능(performance): 계층을 거치며 발생하는 오버헤드 최소화다. [00:10:46]–[00:14:23]

타입 1(네이티브/베어메탈)은 호스트 OS 없이 하드웨어 위에서 직접 실행되어 게스트 OS를 관리한다. 타입 2는 기존 Linux·Windows·macOS 호스트 OS 위에서 일반 애플리케이션처럼 실행된다. 강의 설명상 타입 1은 타입 2보다 오버헤드가 작지만 0은 아니며, 타입 2는 일반 사용자가 설치·관리하기 편리한 대신 호스트 OS 계층이 하나 더 있다. 타입 1 예로 Xen, KVM, VMware ESXi, Proxmox가 언급된다(일부 자막 발음 불명확). 타입 2 예는 VMware Workstation, VirtualBox, macOS용 Parallels다. [00:14:29]–[00:18:33]

### 가상화 방식과 CPU 권한 실행

가상화 방식은 풀 가상화, 반가상화, 하이브리드, OS 레벨로 소개된다. OS 레벨은 Docker 같은 컨테이너 방식이며 이번 강의의 상세 대상에서는 제외한다. 풀 가상화는 게스트 OS를 수정하지 않고 하드웨어를 완전히 가상화하여 게스트가 VM에서 실행되는지 인지하지 못하게 한다. 하드웨어 CPU가 가상화를 지원하면 성능 오버헤드가 줄어든다. 소프트웨어 기반 구현은 명령을 처리·변환하는 부담이 더 크다. Intel VT 계열과 AMD 가상화 지원 CPU가 언급되나 AMD 약어는 자막 확인이 필요하다. [00:18:39]–[00:23:34]

반가상화는 게스트 OS, 특히 커널을 수정해 하이퍼바이저와 직접 통신한다. 일반 시스템 콜 대신 하이퍼콜(hypercall)을 사용하도록 바꾸므로 하이퍼바이저가 매번 명령을 가로채 변환하는 부담을 줄여 성능을 높일 수 있다. 대신 게스트 수정이 필요하고 호환성이 낮다. Xen이 사례다. Xen은 링 0에서 하드웨어 접근을 제어하는 오픈소스 하이퍼바이저로 설명되며, 고성능 실행과 게스트 OS 수정 요구가 함께 언급된다. [00:23:38]–[00:28:42]

권한 링은 숫자가 낮을수록 권한이 높다. 링 0은 커널/최고 권한으로 시스템 제어와 특권 명령 실행이 가능하고, 링 3은 일반 애플리케이션 권한이다. 교수 설명상 링 1·2도 개념상 있지만 Linux에서는 주로 0·3을 쓴다. 일반 OS의 듀얼 모드에서 사용자 모드 애플리케이션은 하드웨어에 직접 접근하지 못한다. 시스템 콜이 트랩을 일으키면 모드 비트가 커널 모드로 전환되고, 작업 후 사용자 모드로 복귀한다. 가상화 환경에서는 게스트가 보는 커널이 가상 커널이므로, 게스트의 특권 동작은 실제 하드웨어로 바로 이어지지 않는다. 설명된 처리 순서는 게스트 요청 → VM exit → 하이퍼바이저의 트랩 처리·에뮬레이션 → 필요한 호스트 자원 작업 → VM entry를 통한 게스트 복귀다. 하이퍼바이저 관점에서 게스트 OS는 논루트 모드에서 도는 대상으로 볼 수 있다. [00:28:46]–[00:35:27]

바이너리 트랜슬레이션은 하이퍼바이저가 게스트 명령 스트림을 분석하고 권한이 필요한 명령을 안전한 명령으로 변환해 물리 자원에서 실행시키는 소프트웨어 기법이다. 하드웨어 지원 가상화보다 오버헤드가 크지만, 하드웨어 지원이 보편화되기 전 쓰였으며 성능과 호환성 최적화 과정에서 하드웨어 기능과 병행될 수 있다고 설명한다. 성능 순서는 강의에서 네이티브 > 세미 가상화 > 풀 가상화 > 에뮬레이션으로 제시한다. 가상화 오버헤드를 낮추려는 연구가 계속되며, SR-IOV(Single Root I/O Virtualization)는 하나의 물리 NIC/I/O 장치를 여러 VM이 직접 공유해 중간 처리와 하이퍼바이저 경유를 줄이는 기술로 소개된다. [00:35:35]–[00:41:15]

### 가상화 보안 위협

클라우드 계층은 물리 호스팅 플랫폼·자원, 하이퍼바이저, 게스트 OS와 VM, 클라우드 제공자 기능(예: 로드밸런싱), 사용자 애플리케이션으로 이어진다. 보안 관심사는 하이퍼바이저, VM 격리, 이미지 무결성, 인증·접근제어 등 여러 층에 있다. Ubuntu 설치 이미지를 내려받을 때도 진본성과 무결성을 확인해야 한다. 악성 VM이나 내부 애플리케이션은 다른 VM을 공격하거나 하이퍼바이저를 공격할 수 있다. 멀티테넌트에서는 한 테넌트가 다른 테넌트 데이터를 탈취할 수 있어 격리 실패의 파급이 크다. [00:41:19]–[00:45:51]

가상화는 VM 생성과 네트워크 제공을 쉽게 하여 효율성을 높이지만, 편익은 위험도 만든다. 쉽게 VM을 만들면 VM sprawl(통제되지 않은 VM 확산)이 생길 수 있다. 간편한 네트워크 프로비저닝은 오구성을 유발해 보안 존 간 분리를 무너뜨리고 공격 표면을 늘릴 수 있다. 교수는 이점·위험·피해를 연결한 다섯 항목 표를 소개했지만, 발화에서 확인되는 것은 이 두 예시뿐이다. 전체 기술 복잡성이 커질수록 구성 오류와 보안 구멍을 고려해야 한다. [00:45:55]–[00:50:01]

공격 표적은 호스트 OS·호스트 하드웨어, VM, VM 구성 파일, 원격 관리, 게스트 OS, 가상 네트워크 등이다. 위협 모델은 게스트 OS 내부 공격에서 VM 탈출, 하이퍼바이저 공격, 물리 호스트 공격으로 확대되는 흐름으로 설명된다. 보호 관점도 VM 무결성에서 VM 격리·기밀성, 하이퍼바이저 무결성으로 넓어지고, 시간에 따라 공격 영향과 복잡성이 커진다고 교수는 설명한다. [00:50:03]–[00:52:37]

주요 보안 우려는 다음과 같다. ① VM마다 게스트 OS 취약성이 들어올 수 있다. 예로 패치되지 않은 Ubuntu 20.04와 패치된 22.04를 대비한다. ② 네트워크 기반 침입 탐지에는 한계가 있다. IDS(Intrusion Detection System)는 공격을 탐지·보고하며, IPS(Intrusion Prevention System)는 탐지뿐 아니라 실시간 차단까지 한다. 교수는 이 구분을 상식으로 알아둘 사항이라고 강조한다. 가상 네트워크에서는 물리 NIC 하나를 VM별 가상 NIC로 나누고 VM 사이 트래픽이 내부에서 오갈 수 있어, 물리 네트워크만 보는 NIDS의 탐지·차단이 어려울 수 있다. ③ 관리 복잡성은 설정 실수로 서비스 중단이나 다른 VM 피해를 일으킬 수 있다. [00:52:41]–[00:57:00]

클라우드 가상화의 운영 위험은 다음과 같이 연결된다. 하이퍼바이저가 침해되면 모든 VM 제어권을 얻는 것과 같아 커널 루트 권한 침해에 비유할 정도로 영향이 크다. 테넌트가 VM을 반납한 뒤 다른 사용자에게 자원을 재할당하기 전에 이전 데이터가 완전히 삭제되지 않으면 데이터 유출이 생긴다. VM 위치 변경 등 환경 변화에 맞춰 가상 스위치·방화벽·네트워크 구성을 갱신하지 않으면 통제가 어긋난다. VM과 테넌트가 동적으로 생성·종료·이동하므로 VM 간 공격을 알아채도록 실시간 모니터링이 필요하다. VM 이미지와 종속 소프트웨어는 패치 및 구성 변경 관리를 복잡하게 한다. [00:57:08]–[01:01:15]

## 교수 강조 사항

- 가상화는 클라우드 컴퓨팅의 핵심이고, 보안의 중심에는 하이퍼바이저와 VM 격리가 있다. 하이퍼바이저 요구사항은 충실도·안전한 격리·성능이다. [00:00:11]–[00:00:58], [00:12:34]–[00:14:23]
- 타입 1/2는 실행 위치와 오버헤드·관리 편의의 차이로 구분하며, 타입 1도 오버헤드가 전혀 없는 것은 아니다. [00:14:42]–[00:18:33]
- 풀 가상화는 게스트 수정 불필요, 반가상화는 게스트 수정과 하이퍼콜이 필요하다. 성능상 이점과 호환성 저하를 함께 기억한다. [00:19:20]–[00:27:35]
- IDS는 탐지·알림, IPS는 실시간 차단까지 한다. 교수는 이 차이를 “상식적으로 알고 있으면 좋다”고 직접 강조했다. [00:54:03]–[00:55:23]
- 가상화의 효율성 증가는 기술·관리 복잡성과 보안 고려사항도 키운다. 편익에서 위험과 피해가 어떻게 파생되는지 연결한다. [00:45:55]–[00:50:01]
- 하이퍼바이저 침해, 재할당 자원의 잔존 데이터, 동적 가상 네트워크의 변경·모니터링, VM 이미지 패치 관리를 구분한다. [00:57:22]–[01:01:15]

## 이론과 공식 목록

1. **가상화·VMM**: 물리 자원을 추상화해 가상 CPU·NIC·스토리지 등을 게스트에 제공하고 VM을 관리한다. VM 파일 캡슐화는 이동·마이그레이션을 돕는다. [00:00:17]–[00:03:00]
2. **자원 풀·동적 할당·대상 분류**: 자원 풀에서 VM별로 필요한 양을 배정한다. 가상화 대상은 서버·데스크톱·애플리케이션·하드웨어다. [00:03:12]–[00:10:11]
3. **하이퍼바이저 요구사항**: fidelity(물리 환경과 기능적 동일성), isolation(안전한 격리), performance(오버헤드 최소화). [00:10:59]–[00:14:23]
4. **배치 유형**: Type 1/native/bare-metal은 하드웨어 위에서 실행, Type 2/hosted는 호스트 OS 위에서 실행. [00:14:42]–[00:18:33]
5. **구현 방식**: full virtualization(게스트 수정 불필요), para-virtualization(게스트 커널 수정·hypercall), hybrid, OS-level(컨테이너; Docker는 언급 후 상세 제외). [00:18:39]–[00:25:16]
6. **권한 링·듀얼 모드**: Ring 0 최고 권한/커널, Ring 3 사용자 권한. 사용자 모드에서 시스템 콜·트랩을 거쳐 커널 모드로 전환한다. [00:28:46]–[00:31:30]
7. **VM 특권 요청 처리 절차**: 게스트 요청 → VM exit → 하이퍼바이저 처리/에뮬레이션 → 호스트 자원 작업 → VM entry로 복귀. [00:31:34]–[00:35:27]
8. **바이너리 트랜슬레이션**: 명령을 분석해 특권 동작을 안전한 명령으로 변환한다. 소프트웨어 구현은 하드웨어 지원보다 오버헤드가 크다. [00:35:35]–[00:38:18]
9. **성능 비교·SR-IOV**: 강의상 네이티브 > 세미가상화 > 풀 가상화 > 에뮬레이션. SR-IOV는 하나의 물리 I/O 장치를 복수 VM이 공유해 처리 경로를 줄인다. [00:38:23]–[00:41:15]
10. **위협 표적·진화**: 호스트/하드웨어·VM·구성 파일·원격 관리·게스트 OS·가상 네트워크. 게스트 공격 → VM 탈출 → 하이퍼바이저 → 물리 호스트로 확대된다. [00:50:03]–[00:52:37]
11. **IDS/IPS**: IDS는 탐지·보고, IPS는 탐지·실시간 예방/차단. [00:54:03]–[00:55:23]

## 자가 점검 문항

1. 하이퍼바이저의 세 요구사항은? — 충실도, 안전한 격리, 성능 오버헤드 최소화.
2. 타입 1과 타입 2의 차이 및 절충점은? — 타입 1은 하드웨어 위에서 직접 실행해 오버헤드가 상대적으로 낮고, 타입 2는 호스트 OS 위에서 실행해 관리가 편하지만 계층이 추가된다.
3. 풀 가상화와 반가상화의 핵심 차이는? — 풀 가상화는 게스트를 수정하지 않고, 반가상화는 커널을 수정해 하이퍼콜로 통신한다. 후자는 성능 이점 가능성이 있지만 호환성이 낮다.
4. 게스트의 특권 동작은 어떻게 실제 자원 작업으로 이어지는가? — 요청, VM exit, 하이퍼바이저 처리, 실제 자원 작업, VM entry 순이다.
5. IDS와 IPS의 차이는? — IDS는 침입을 탐지·보고하고, IPS는 실시간 차단·예방까지 한다.
6. 재할당된 VM 자원에서 테넌트 간 데이터가 노출되는 이유와 예방 원리는? — 이전 데이터가 지워지지 않은 채 재할당되기 때문이며, 할당 해제 시 완전히 삭제해야 한다.
7. 가상화의 편익이 보안 위험으로 전환되는 두 사례는? — 쉬운 VM 생성은 VM sprawl, 쉬운 네트워크 설정은 오구성에 따른 보안 존 분리 붕괴를 낳을 수 있다.
