# 클라우드보안 2강 클라우드 컴퓨팅 오버뷰

## 전체 내용

### 클라우드 컴퓨팅의 정의와 작동 방식

강의는 클라우드 컴퓨팅의 핵심을 사용자가 인터넷을 통해 원할 때 필요한 컴퓨팅 자원을 원하는 사양과 양만큼 받아 쓰는 방식으로 설명한다. 교수는 미국 기관의 정의를 소개하며 네 가지 표현을 강조했다. 온디맨드 셀프서비스(on-demand self-service)는 필요할 때 요청해 자원을 받는 것, 구성 가능한 자원(configurable resources)은 사용 목적에 맞게 사양과 용량을 선택하는 것, 신속한 프로비저닝(rapid provisioning)은 요청 뒤 빠르게 할당되는 것, 최소한의 관리 노력(minimal management effort)은 자동화를 통해 이용자가 직접 해야 할 설정을 줄이는 것이다. 자원은 실제로는 원격 데이터센터의 서버·스토리지 등에 있고, 인터넷으로 연결해 이용한다. 인터넷 연결이 전제다. [00:01:45–00:04:15]

첫 슬라이드의 구름·우산 비유는 클라우드 컴퓨팅의 보안 기능이나 서비스를 이용할 때 구독료를 내는 상황을 빗댄 것이다. 데이터센터가 물리적으로 존재하므로 정전·재해 등으로 장애가 날 수 있고 작업물을 보호해야 한다는 점도 비유에서 이어진다. [00:00:12–00:01:45]

### 장점, 위험과 온프레미스 비교

장점은 유연성, 초기 비용 절감, 확장성, 백업·복구의 편의, 신뢰성과 가용성이다. 온프레미스는 서버실·랙·네트워크·보안 장비를 직접 마련하고 관리해야 하며, 하드웨어가 노후화되면 교체 비용도 든다. 클라우드는 사용한 만큼 비용을 지불하고 보안 기능을 포함한 여러 서비스를 제공받을 수 있으며, 수요에 맞춰 자원을 늘리거나 줄이기 쉽다. 여러 지역의 데이터센터를 활용하면 한 곳의 장애가 다른 곳의 서비스 제공으로 완화될 가능성도 있다. [00:05:04–00:07:26]

반면 위험과 비용상 주의점도 있다. 특정 CSP에 의존하면 다른 사업자의 기능으로 옮기기 어려운 벤더 락인이 생길 수 있다. 초기 구축비는 낮아도 사용 후 청구되는 종량 비용을 예측·관리하기 어려워질 수 있다. 클라우드 데이터도 물리적 데이터센터에 보관되므로 해킹·프라이버시 위험이 사라지지 않는다. 여러 고객이 물리 서버를 공유하므로 파티셔닝·보호가 부실하면 고객 A가 고객 B의 데이터에 접근할 위험이 있다는 것이 공유 인프라 위험(shared infrastructure risk) 사례다. 데이터센터 재해 등으로 다른 센터 연계가 작동하지 못하면 서비스 다운타임과 기업 손실이 발생할 수 있다. 따라서 클라우드가 늘 저렴하거나 안전하다고 단정할 수 없다. [00:08:16–00:11:48]

비용 비교는 초기 지출과 장기 사용량을 함께 보아야 한다. 온프레미스는 공간 임대와 서버·고성능 GPU 구매로 초기 비용이 크지만, 클라우드는 처음에는 싸게 시작해도 사용량이 늘면서 누적 비용이 커진다. 교수의 단순 예시는 GPU 카드 3천만 원을 사는 대신 AI 모델 실행 1회당 클라우드 비용이 10만 원이면, 300회까지는 클라우드 비용이 3천만 원 이하이고 301회부터는 구매한 GPU가 비용상 유리해질 수 있다는 계산이다. 실제 손익은 하드웨어 성능 저하와 교체 비용, 사용량 및 사용기간에 따라 달라진다. 하드웨어 교체 주기가 짧으면 온프레미스 비용이 다시 늘고 비용 교차 시점도 달라지므로 사업자별로 손익을 따져야 한다. 온프레미스는 직접 구축한 설비에 접근할 때 클라우드보다 인터넷 의존이 낮고, 클라우드는 서비스 이용·설정에 인터넷 연결이 필요하다. [00:16:23–00:20:58]

### 발전사와 서비스 제공 모델

교수는 발전 흐름을 1980년대 메인프레임·자체 서버실, 1990년대 클라이언트-서버 모델, 2000년대 네트워크 기반 시스템, 2010년 이후 대규모 데이터센터를 통한 클라우드 컴퓨팅으로 설명했다. 뒤로 갈수록 서버가 원격화·대형화되고 다수의 전 세계 이용자에게 자원을 제공하는 규모가 커진다. 온프레미스와 클라우드는 물리 장비를 직접 구축·소유하는 방식과 원격 데이터센터 자원을 인터넷으로 빌려 사용료를 내는 방식의 차이다. [00:11:48–00:16:23]

전통적인 서비스 모델은 온프레미스, IaaS, PaaS, SaaS 순으로 이용자가 관리하는 범위가 줄고 제공자가 관리하는 범위가 커진다.

- 온프레미스: 이용자가 하드웨어부터 직접 구축·관리한다.
- IaaS(Infrastructure as a Service): 제공자가 네트워크·스토리지·서버와 가상화까지 제공하고, 이용자는 OS부터 위쪽을 선택·관리한다. AWS EC2는 가상머신을 할당받아 Linux나 Windows 등을 설치해 쓰는 예다. Azure VMs와 Google Compute Engine도 언급됐다. [00:21:04–00:22:51] [00:24:36–00:26:00]
- PaaS(Platform as a Service): 제공자가 개발 플랫폼과 미들웨어·런타임 등을 준비하고 이용자는 주로 코드 작성과 배포에 집중한다. Java 런타임이 준비된 환경에서 Java 코드만 다루는 예가 설명됐다. Google App Engine, Azure App Service, Red Hat OpenShift가 예시다. [00:22:51–00:23:40] [00:26:00–00:27:01]
- SaaS(Software as a Service): 애플리케이션까지 제공되어 이용자는 웹 등으로 소프트웨어를 사용한다. Google Docs·Slides·Sheets, Microsoft Office 365, 웹 기반 한글이 예시다. 로컬 설치가 불필요하고 여러 사람이 한 파일을 동시에 편집해 파일을 버전별로 주고받는 번거로움을 줄인다. [00:23:40–00:24:36] [00:27:01–00:29:14]

교수는 AWS, Microsoft Azure, Google Cloud를 주요 CSP 3사로 제시하고, 경우에 따라 Alibaba Cloud를 포함해 4대 사업자로 말한다고 설명했다. AWS가 앞서 있어 서비스 기능과 명칭이 다른 CSP에도 대체로 비슷하게 적용된다는 것이 교수의 설명이며, AWS 기반 학습이나 자격증이 타 클라우드로 옮겨갈 때 도움이 될 수 있다고 평가했다. 이는 강의 중 교수의 시장·진로 설명이다. [00:24:46–00:25:26] [00:39:30–00:40:34]

IaaS는 물리 하드웨어를 직접 소유하지 않고 가상 서버를 빌리는 모델이지만 OS 설치 등은 이용자가 한다. PaaS는 개발 생산성에 초점을 두며 데이터베이스 관리 시스템, 개발 도구, 프레임워크 등의 환경을 제공한다. SaaS는 소프트웨어 설치·유지관리 부담을 줄이고 공유·협업을 편하게 한다. [00:25:26–00:29:14]

### XaaS와 데이터센터

IaaS·PaaS·SaaS 외에 XaaS(Anything/Everything as a Service)처럼 기능을 서비스 단위로 제공하는 확장 흐름도 소개됐다. Function as a Service는 개발자가 작성한 함수 단위 기능을 호출·사용량 기준으로 제공하며, 서버리스 컴퓨팅으로 이어지는 예로 설명됐다. Security as a Service는 방화벽, IDS, IPS 같은 보안 기능을 직접 구성하는 대신 구독형 서비스로 이용하는 방식이다. AI 서비스는 이미 준비된 학습 모델에 이용자 데이터를 넣어 사용하는 형태로 설명됐고 GPU 사용 때문에 비용이 더 들 수 있다고 했다. Desktop as a Service는 가상 데스크톱을 서비스로 제공하는 예다. [00:29:14–00:32:19]

데이터센터에는 서버 랙이 대규모로 설치되며 전력과 열을 많이 발생시킨다. 교수는 입지 선정 시 자연재해 가능성과 냉각 여건을 고려해야 하며, 전력·열 부담으로 데이터센터가 주거지 인근에서 기피 시설이 될 수 있다고 설명했다. Google 데이터센터 분포 지도와 한국 데이터센터 분포를 보여주며 수도권 비중을 약 58.8%라고 언급했으나, 이는 2024년 자료라는 설명과 함께 제시된 수치다. 지역 내에서 물리적으로 분리된 데이터센터 건물 단위를 가용 영역(Availability Zone)으로 설명했고, 존 사이의 빠른 데이터 전송 연결이 중요하다고 했다. [00:32:19–00:37:48]

클라우드 자원 관리 방식은 웹 콘솔, API, CLI로 구분해 소개됐다. 콘솔에서는 리전·존을 선택해 가상머신을 할당하거나 서비스를 배포할 수 있다. API는 프로그램으로 자원을 요청·배치·배포하는 방식이고, CLI는 셸/터미널에서 자원을 생성하거나 해제하는 방식이다. [00:37:48–00:40:34]

### 클라우드 서비스의 구성 요소와 예시

컴퓨트 서비스는 가상 서버 등 계산 자원을 제공한다. VMware ESXi와 오픈소스 하이퍼바이저 Proxmox가 가상머신 생성에 쓰이는 예로 언급됐다. [00:43:06–00:44:05]

로드 밸런서는 여러 VM에 들어오는 이용자 트래픽을 분산한다. 예를 들어 온라인 쇼핑 서비스에 VM 다섯 대를 운영할 때 시간대·요일·이벤트에 따라 접속량이 몰리면 부하를 나누어 과부하를 줄인다. 오토스케일링은 수요에 맞춰 자원을 자동 증설·축소한다. 티켓팅처럼 정오에 트래픽이 치솟는 경우, 하루 종일 피크 수량의 서버를 켜두면 유휴 자원에도 비용을 내지만 자동 확장·축소로 낭비를 줄일 수 있다. [00:44:05–00:48:15]

스토리지는 데이터 아카이빙·백업·파일 서버 등에 쓰이며 내구성과 가용성이 중요하다고 강조했다. AWS 사례로 S3는 객체 스토리지, EFS는 파일 기반 스토리지, EBS는 블록 스토리지이며 데이터베이스 등 가동 중 성능에 민감한 서비스에 쓰는 예로 설명됐다. S3 Glacier는 자주 열지 않지만 장기 보관해야 하는 자료에 적합한 아카이브 스토리지다. 교수는 경찰 사건 기록을 디지털화해 저장하고 필요할 때 검색하는 사례를 들었다. 세 유형은 저장 단위와 특성이 다르므로 구별해야 한다고 했다. [00:48:15–00:52:12]

네트워크 서비스 중 VPN(Virtual Private Network)은 물리적으로 떨어진 장소의 이용자나 사무실을 사설 네트워크처럼 연결하는 방식이다. 사무실 A와 B가 VPN을 사용해 같은 사무실 네트워크에 있는 것처럼 통신하는 예가 제시됐다. VPC(Virtual Private Cloud)는 클라우드 안에 가상 네트워크를 만들어 접근을 통제하는 구조다. VPC가 없으면 인터넷에서 각 EC2 인스턴스에 직접 연결할 수 있는 반면, VPC 구조에서는 먼저 해당 가상 네트워크에 들어온 뒤 그 안의 인스턴스에 접근한다. 다른 VPC에 들어간 이용자는 별도 연결·권한 없이는 다른 VPC의 인스턴스를 볼 수 없다는 접근 격리 설명도 포함됐다. [00:53:01–00:55:52]

VPC 예시에서는 하나의 리전에 네트워크 범위를 정하고 인터넷 게이트웨이와 라우터를 두며, 서브넷을 나누어 IP 범위에 따라 트래픽을 라우팅한다. 이런 네트워크 분리·접근 통제가 보안에 도움이 된다고 설명했다. CIDR 예시의 주소·마스크는 자막이 손상되어 정확한 값은 확인이 필요하다. [00:55:52–00:57:35]

데이터베이스 서비스는 MySQL 같은 DB를 로컬에 직접 설치하는 대신 서비스로 제공받고 원격 접속해 데이터를 읽고 쓰고 갱신하는 방식이다. AWS 예로 RDS, Aurora, DynamoDB가 소개됐고, 교수는 DynamoDB를 NoSQL 서비스로 설명하며 문서형 사용과 낮은 지연 성능을 언급했다. 온프레미스 시스템을 클라우드로 옮기는 리프트 앤 시프트는 호환성·설정·데이터 이전 등의 마이그레이션 작업을 서비스로 지원하는 방식으로 소개됐다. 데이터 분석 서비스는 Spark·Hadoop을 예로 트래픽·사용량을 분석해 결론을 내는 기능, AI·머신러닝 서비스는 GPU와 모델 환경을 직접 마련하지 않고 사용량에 따라 이용하는 기능으로 설명됐다. [00:57:35–01:01:12]

## 교수 강조 사항

- 클라우드 컴퓨팅의 핵심은 인터넷을 통한 온디맨드 자원 할당, 원하는 사양·규모의 선택, 빠른 프로비저닝, 이용자 관리 부담의 감소다. [00:01:45–00:04:15]

## 자가 점검 문항

※ 아래 문항은 복습을 위해 요약자가 만든 것이며 교수의 출제 예고나 실제 시험문항이 아니다.

1. 강의에서 제시한 클라우드 컴퓨팅 정의의 네 핵심 요소는?  
   답: 온디맨드 셀프서비스, 구성 가능한 자원, 신속한 프로비저닝, 최소한의 관리 노력.
2. IaaS·PaaS·SaaS를 이용자 관리 범위로 구별하면?  
   답: IaaS는 가상 인프라를 받고 이용자가 OS 위를 관리한다. PaaS는 개발 플랫폼·런타임까지 제공받아 코드 개발·배포에 집중한다. SaaS는 완성된 애플리케이션을 사용한다.
3. 클라우드가 초기에는 저렴해 보여도 온프레미스와 비용 비교가 필요한 이유는?  
   답: 사용량 기반 이용료가 누적되고, 일정 사용량 이후에는 장비 구매가 더 쌀 수 있다. 반대로 온프레미스에는 노후화·교체 비용이 있다.
4. 공유 인프라 위험은 무엇이며 강의에서 든 위험 상황은?  
   답: 한 물리 서버를 여러 고객이 공유하므로 격리·보호가 부실하면 한 고객이 다른 고객의 데이터에 접근·악용할 수 있다.
5. S3, EFS, EBS의 스토리지 유형을 각각 말하면?  
   답: S3는 객체, EFS는 파일, EBS는 블록 스토리지다.
6. 로드 밸런서와 오토스케일링의 역할은 어떻게 다른가?  
   답: 로드 밸런서는 들어오는 트래픽을 여러 VM에 분산한다. 오토스케일링은 수요 변화에 따라 VM 등 자원 규모를 자동으로 늘리거나 줄인다.
7. VPN과 VPC는 강의에서 어떤 네트워크 보안 목적과 연결됐나?  
   답: VPN은 떨어진 위치를 사설망처럼 연결하고, VPC는 가상 네트워크 경계·서브넷·라우팅을 통해 인스턴스 접근을 분리하고 통제한다.
