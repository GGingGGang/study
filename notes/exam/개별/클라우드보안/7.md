# 클라우드보안 7강 가상화 보안 위협과 대응

## 전체 내용

### 1. 가상화 공격의 범위와 위협 분류

강의는 가상화 보안 위협을 공격 벡터 기준으로 하이퍼바이저 기반, VM 이미지 기반, VM 기반 공격으로 나누어 개관한다. 가상화 기술의 등장으로 새롭게 생긴 공격과, 원래 존재했지만 가상화 환경에도 피해를 주는 일반 공격을 구분한다. 새 위협의 예로 VM Escape, Hyperjacking, VM Sprawl, Cross-VM Side-Channel Attack을 든다. 공격이 VM 안에서 시작되는지 바깥에서 시작되는지를 나타내는 Inside VM/Outside VM 구분도 소개하며, 이는 공격 유형 그 자체라기보다 범주를 나타내는 표현으로 설명한다. (00:00:00–00:04:30)

- **VM Escape(가상머신 탈출)**: VM 내부 애플리케이션을 침해한 뒤 VM 격리 경계를 넘어 하이퍼바이저나 호스트·물리 시스템에 접근하는 공격이다. VM 안에서 출발해 격리 경계를 넘는다는 점이 핵심이다. (00:01:02–00:01:49, 00:10:00–00:11:22)
- **Hyperjacking(하이퍼재킹)**: 호스트 OS 등을 먼저 침해해 하이퍼바이저의 제어 권한을 빼앗고 가상화 환경을 장악하는 공격이다. 강의는 VM Escape와 달리 공격자가 VM 내부가 아니라 외부 호스트 측에서 시작한다고 구분한다. (00:01:55–00:02:28, 00:32:15–00:34:30)
- **VM Sprawl(스프롤)**: 적절한 관리·감독 없이 VM이 급격히 많이 생성되어 통제되지 않는 상태다. 의도적 공격이 될 수도 있지만, 강의에서는 주로 관리·운영상 문제로 설명한다. (00:02:28–00:02:45, 00:51:45–00:53:30)
- **VM Footprint**: 대상 VM의 게스트 OS와 버전, 제공 중인 서비스, VMware 환경 등 VM 관련 정보를 알아내는 정찰·정보수집 행위로 소개한다. (00:02:45–00:03:18)
- **Cross-VM Side-Channel Attack(교차 VM 부채널 공격)**: 공유 하드웨어 자원에서 발생하는 부수적 신호를 관찰해 다른 VM의 비밀정보를 추론·유출한다. 직접 침투하거나 시스템을 손상시키지 않는 수동적 공격이어서 탐지가 어렵다. (00:04:27–00:05:17, 01:00:00–01:03:15)
- **패치되지 않은 게스트 OS·소프트웨어**: VM 안의 게스트 OS도 일반 OS와 같으므로 오래되었거나 패치가 빠진 OS·패키지가 공격 표면이 된다. 사용자는 업데이트를 지속하고, 복구를 위해 하이퍼바이저의 스냅샷 기능을 주기적으로 활용할 수 있다고 설명한다. (00:06:29–00:07:54)

VM은 하이퍼바이저를 통해 물리 하드웨어 자원을 공유하므로 하나의 VM 침해가 그 VM만의 문제로 끝나지 않을 수 있다. 같은 물리 서버의 다른 VM이나 하이퍼바이저로 공격이 확산될 수 있으며, 특히 여러 고객이 한 클라우드 기반을 공유하는 멀티테넌트 환경에서는 고객 간 격리와 신뢰가 걸려 있어 파급력이 크다. 강의는 Confidential VM(CVM)도 VM 자체를 더 안전하게 만들려는 기술로 언급하지만, 해당 슬라이드 표현은 자막상 확인되지 않는다. (00:08:01–00:09:52)

### 2. VM Escape의 과정, 영향 및 방어

정상적인 가상화에서는 게스트 OS의 명령이 하이퍼바이저로 전달되고, 하이퍼바이저가 이를 처리해 하드웨어 자원에 접근한다. VM Escape는 취약점을 이용해 이 격리 경계를 넘고 하이퍼바이저·호스트 측으로 접근하는 것이다. 강의 도식 설명에서는 게스트 VM에서 하이퍼바이저로 향하며 호스트 OS를 우회하는 경로를 제시한다. 성공하면 시스템 정보를 훔치거나 호스트 자원·다른 VM에 접근할 수 있다. (00:10:00–00:11:30)

강의에서 설명한 공격 흐름은 다음과 같다. 이는 공격 절차에 대한 강의 설명을 요약한 것이며, 단계명을 자막의 표현에 맞춰 정리했다. (00:11:34–00:14:47)

1. **초기 정찰**: 현재 실행 지점이 게스트 OS 안인지 확인하고, 하이퍼바이저 종류·버전을 식별하며, 호스트와 통신하는 채널을 조사한다. 네트워크 도구가 이용될 수 있다고 설명한다.
2. **취약점 조사**: 하이퍼바이저 구성요소를 분석한다. 오픈소스는 코드를 직접 분석하는 방식, 클로즈드소스는 역공학을 활용하는 방식으로 설명하며, 메모리 손상 가능 지점 등을 찾는다.
3. **익스플로잇 개발**: 발견한 취약점을 작동시키는 입력·코드를 만든다. ROP(Return-Oriented Programming)·JOP(Jump-Oriented Programming) 체인, 버퍼 오버플로와 메모리 입력 조작을 예로 든다. ASLR 같은 보안 완화 기법을 우회하는 개발도 언급한다.
4. **권한 상승**: 침해를 이용해 더 높은 권한, 예컨대 루트나 호스트 시스템 권한을 얻는다.
5. **침해 후 활동**: 확보한 권한으로 호스트 자원이나 다른 VM에 접근하고, 추가 침투를 위해 백도어를 설치할 수 있다.

VM Escape의 결과로는 호스트 시스템 장악, 다른 VM에 대한 접근 및 수평 이동, 데이터 침해와 기밀성 손실, 서비스 중단·DoS, 자원 탈취형 크립토재킹, 멀티테넌트 격리 및 규정 준수 위반, 고객 신뢰 상실을 든다. 호스트 수준의 지속성 확보 뒤에는 하이퍼바이저 수준 악성코드·백도어·루트킷 설치, 보안 도구 종료·탐지 회피, 로그 조작, 다른 물리 머신으로 확장되는 연쇄 공격(APT의 발판)이 가능하다고 설명한다. (00:15:01–00:20:00)

강의는 VM Escape 관련 취약점 사례로 VENOM(QEMU의 버퍼 오버플로, 2015년), VMware Workstation·ESXi의 메모리 관련 취약점(2018년), VirtualBox의 정수 언더플로우 등(2019년), AMD CPU를 사용하는 Linux KVM 구현에서의 레이스 컨디션(2021년)을 든다. 각 취약점의 정확한 식별번호는 강의에서 제시·판독되지 않아 여기서는 적지 않는다. (00:20:45–00:23:00)

방어는 하이퍼바이저의 최신 보안 패치 유지, 불필요한 가상 장치·기능 비활성화, 꼭 필요한 기능만 설치·사용하는 강화(hardening)에서 시작한다. VM 구성에서도 불필요한 하드웨어를 빼고 최소 권한 원칙을 적용한다. 교수는 최소 권한을 Zero Trust와 연결해 설명한다. Zero Trust는 기본적으로 누구도 신뢰하지 않고, 실제로 필요한 기능·권한만 최소 단위로 허용한다는 취지다. 가상 네트워크를 보수적으로 구성하고, 불필요한 게스트 추가 기능을 끄며, VPC 등에서 VM 간 네트워크 세그멘테이션을 세밀하게 해야 침해 후 다른 VM으로의 확산을 제한할 수 있다. VM 간 통신 패턴 모니터링, RBAC(Role-Based Access Control), 최소 권한, 다단계 인증도 제시한다. (00:23:00–00:27:47)

운영 차원의 모범 사례로 자동화된 패치 관리와 공급업체 보안 권고 추적, 정기 취약점 평가, 심층 방어(Defense in Depth), EDR(Endpoint Detection and Response) 및 하이퍼바이저를 인식하는 보안 도구의 배치, 로그 수집·분석을 든다. 예방 통제를 과도하게 적용하면 오버헤드가 커질 수 있으므로 현실적으로는 탐지를 빠르게 해 사후 대응하는 접근도 설명한다. 정상 트래픽·로그의 패턴에서 벗어나는 이상 징후를 AI로 탐지하는 시스템을 예로 들지만 정확도 문제도 남는다고 덧붙인다. 사고 시 해당 VM을 즉시 종료할지, 격리된 전용 머신으로 옮겨 관찰할지 등 대응 절차를 미리 정해야 한다. 아키텍처 차원에서는 Zero Trust 원칙, CVM과 하드웨어 기반 보호, 고보안 워크로드의 베어메탈 배치를 언급하며, 베어메탈은 비용이 더 들 수 있다고 설명한다. (00:27:47–00:32:15)

### 3. Hyperjacking의 경로, 영향 및 방어

Hyperjacking은 외부 공격자가 호스트 OS를 침해하고 권한을 높인 뒤 하이퍼바이저의 관리·제어 권한을 장악해, 그 위의 VM 전체를 통제하는 공격이다. 하이퍼바이저를 장악하는 것을 일반 OS의 루트 권한 획득에 비유한다. 교수 설명에 따르면 호스트 OS 취약점이 진입점이어서 VMware Workstation·VirtualBox 같은 호스티드 Type 2 가상화가 주요 대상이며, 호스트 OS가 손상되면 그 위에서 동작하는 하이퍼바이저도 위험해진다. (00:32:15–00:34:45)

공격 과정은 ① 호스트 OS 정찰·접근(포트 스캔, OS·버전·취약점 조사, 관리자 대상 피싱·사회공학 등) ② 호스트 OS 권한 상승과 지속성 확보(강의에서는 Windows 레지스트리 수정·예약 작업 등을 예로 들며, 탐지 회피용 루트킷도 언급) ③ 설치된 하이퍼바이저의 종류, 구성 파일·인터페이스·로그 위치 조사 ④ 구성 파일 변경, 악성 모듈·드라이버 설치 또는 인터페이스 가로채기를 통한 침해·제어 ⑤ VM 통신·데이터 흐름 모니터링, VM 생성·중지·이동·차단 등 환경 조작으로 정리된다. (00:34:45–00:38:30)

VM Escape와의 비교에서 교수는 진입점·경로를 핵심 차이로 설명한다. Hyperjacking은 외부에서 호스트 OS 취약점을 타고 들어가며 주로 Type 2를 대상으로 하고, VM Escape는 게스트 VM 내부에서 가상 장치 등의 취약점을 타고 나와 Type 1·Type 2 모두에 해당할 수 있다고 설명한다. VM Escape의 활동은 하이퍼바이저 수준에서 일어나 탐지가 더 어려울 수 있는 반면, Hyperjacking은 먼저 호스트 OS에 침투해야 하므로 호스트의 보안 소프트웨어에 탐지될 여지가 상대적으로 더 있다고 강의에서 비교한다. 영향 범위는 VM 단일 또는 호스트 접근에서 전체 가상화 환경 제어까지 커질 수 있다. (00:38:30–00:40:45)

하이퍼재킹의 영향은 포괄적 인프라 제어, 여러 VM의 연쇄 침해, 멀티테넌트 격리 붕괴, 하이퍼바이저 로그·감사 정보 조작에 따른 포렌식 곤란, 서비스 중단, VM을 무분별하게 만들어 자원 고갈, 오케스트레이션 도구 침해, 데이터 유출·스파이 활동, 장기간 은밀한 APT, 규정 위반, 공급망·신뢰 모델 침해, 백도어 설치 등이다. 교수는 개인 PC 침해와 달리 클라우드 가상화 기반을 장악하면 그 인프라를 공유하는 다수 테넌트가 함께 영향을 받을 수 있어 피해 규모가 커진다고 강조한다. (00:40:16–00:45:00)

사례로 2021년 Apache Log4j의 Log4Shell, VMware vCenter Server 원격 코드 실행(RCE), 2020년 Windows 권한 상승 취약점(자막상 “제로록”), 2019년 Pulse Secure VPN 장비의 코드 실행 취약점, 2017년 Spectre 관련 사례를 든다. 교수는 Log4Shell과 vCenter RCE를 하이퍼재킹 위험을 설명하는 취약점 사례로 언급한다. 연도·영향 관계는 강의 설명에 귀속하며, 일부 이름이나 CVE 식별번호가 자막에서 분명하지 않으므로 원문 확인 대상으로 둔다. (00:45:46–00:47:45)

대응은 호스트 OS 보안 강화와 패치, EDR 배치 및 정기 취약점 점검, 하이퍼바이저 권한의 세분화·최소화, 계정별 필요한 권한만 부여하는 최소 권한 원칙, 위협 모니터링과 로그 관리, 심층 방어 아키텍처 및 Zero Trust를 포함한다. 추가 모범 사례로 관리자 보안 인식 교육, 하이퍼바이저 인식 모니터링, IAM 권한의 실시간 점검, 안전한 백업·복구 절차를 든다. 침해를 가정한 대응 계획에서는 중요한 VM을 우선 안전한 호스트로 신속하게 마이그레이션하는 선택지를 준비한다. (00:48:01–00:51:45)

### 4. VM Sprawl의 원인, 영향 및 관리

VM Sprawl은 가상머신이 통제되지 않은 채 급증하는 현상이다. 공격자가 의도적으로 만들 수도 있지만, 강의에서는 보통 감독·수명주기 관리의 부재에서 생기는 운영 문제로 설명한다. 핵심 영향은 CPU·메모리·저장공간·네트워크 처리량 등 자원의 낭비이며, 클라우드에서는 사용량이 비용으로 이어져 불필요한 지출을 키운다. 시스템·서버 스프롤은 IT 시스템 또는 물리 서버가 통제 없이 확산되는 더 넓은 현상으로 함께 설명한다. (00:51:45–00:53:30)

구체적 예시는 테스트·개발용으로 임시 생성한 VM을 작업이 끝난 뒤 삭제하지 않고 방치하는 경우다. 애플리케이션이 Ubuntu 24.04, 22.04, 20.04, 18.04 등 여러 OS 버전에서 실행되는지 확인하려고 VM을 여럿 만들 수 있는데, 각 VM을 회수하지 않으면 백그라운드에서 자원과 비용을 계속 소비한다. (00:53:30–00:54:30)

VM Escape와 비교할 때 VM Sprawl은 하이퍼바이저·가상 장치 취약점을 이용하는 침해 공격과 성격이 다르며, 주된 문제는 자원 낭비와 관리 복잡성이다. 교수는 스프롤을 보통 그 자체로 명확한 공격이라기보다 관리 문제라고 구분한다. 자원 사용량이 설명 없이 급증하거나 예측 범위를 벗어나면 모니터링으로 탐지할 수 있다고 한다. (00:54:30–00:55:45)

VM 수가 많아질수록 구성·업데이트 추적, 보안 패치와 취약점 관리, 모니터링 및 사고 대응이 어려워진다. 자동화가 없으면 수십·수백·수천 VM을 수작업으로 관리하기 어렵고, 이상 활동 감지 지연은 피해와 비용을 키울 수 있다. 프라이빗 클라우드에서는 라이선스·전력·냉각 비용도 부담이 된다. 대응의 중심은 지속적·실시간 자원 모니터링, VM별 목적에 따른 예상 사용량 기준 설정, 기준 이탈 탐지, VM 생성부터 회수·폐기까지의 수명주기 관리다. 패치·접근통제·인증 등 기본 관리도 병행한다. (00:55:45–01:00:00)

### 5. Cross-VM Side-Channel Attack의 원리와 방어

교차 VM 부채널 공격은 같은 물리 자원을 공유하는 VM 간에 발생하는 간접 정보 유출이다. 공격 VM이 목표 VM에 직접 침투하거나 코드를 실행하지 않고, 공유 자원의 사용 흔적을 관찰해 암호 키·비밀번호·사용자 정보 등 민감 데이터를 추론한다. 이런 수동적(passive)·은밀한 공격은 기존 모니터링이 놓치기 쉽다. 멀티테넌트 환경에서 제3자 데이터에 접근하게 되어 기밀성 및 격리 보장을 침해하고, 클라우드 제공자에 대한 신뢰를 훼손할 수 있다. (01:00:00–01:04:46)

강의에서 든 관찰 채널은 다음과 같다. (01:04:46–01:07:50)

- **캐시 기반**: CPU 캐시의 공유·경합 양상을 관찰해 다른 VM의 동작·데이터를 추론한다.
- **메모리·네트워크 기반**: 메모리 버스나 네트워크 동작에서 나타나는 신호를 분석한다.
- **가상 스위치·타이밍**: 하이퍼바이저의 가상 스위치를 오가는 타이밍을 살펴 다른 VM의 데이터 사용 양상을 짐작한다.
- **성능·자원 관찰**: CPU 스케줄링, 성능 카운터, CPU·메모리 사용량, 지연시간(latency) 등을 측정해 정보를 추론한다.
- **전력 소비 패턴**: 자원 사용·전력 패턴을 비교해 실행 중인 하이퍼바이저 종류나 버전을 식별할 수 있다는 예를 든다. 강의 예에서는 VMware Workstation과 VirtualBox가 서로 다른 사용·지연 패턴을 보일 수 있다고 설명한다.

방어의 중심은 하드웨어·VM 간 파티셔닝과 강한 격리다. 추가로 자원 사용 양상을 무작위화하고 노이즈를 주입해 공격자의 추론을 어렵게 만들 수 있다. 민감도에 맞춰 더 안전한 물리 머신에 VM을 배치하고, 중요 데이터는 암호화하며 키를 안전하게 관리한다. 암호화는 성능 오버헤드를 낼 수 있지만 정보 유출 위험과 비교해 선택해야 한다고 설명한다. 하드웨어 기반 격리, 보안이 강화된 하이퍼바이저, 모니터링·탐지도 권고하며, 교수는 여러 대책 가운데 격리가 특히 중요하다고 반복한다. (01:07:50–01:10:22)

### 6. VM Migration의 활용, 위협 및 보호

VM Migration은 한 물리 호스트에서 다른 호스트로 VM을 옮기는 과정이다. VM이 실행 중인 채 옮기면 **Live Migration**, 전원이 꺼진 상태에서 옮기면 **Cold Migration**이다. 부하 분산과 워크로드 재배치에 쓰이며, 침해가 의심되는 VM을 안전한 곳으로 옮기는 사후 대응, 재해 복구와 비즈니스 연속성에도 활용될 수 있다. (01:10:22–01:11:52)

이동 중의 공격 표면은 세 부분으로 설명된다. ① 관리 통신·오케스트레이션을 겨냥하는 제어 영역(control plane), ② 전송 중 VM 메모리·상태 정보를 가로채는 데이터 영역, ③ 마이그레이션 모듈 자체다. 대표 공격은 다음과 같다. (01:11:55–01:13:30)

- **마이그레이션 하이재킹**: 공격자가 VM 이동을 가로채 안전하지 않거나 악성인 호스트로 보낸다. 겉으로는 이동이 성공한 듯 보여도 실제 목적지가 손상되었을 수 있다.
- **마이그레이션 도청(eavesdropping)**: 전송 트래픽을 수동적으로 분석해 VM 정보나 암호 키 등 민감 정보를 엿본다.
- **강제·무단 마이그레이션 또는 중단, 서비스 거부(DoS)**: 자원 고갈·네트워크 플러딩 등으로 전송을 늦추거나 방해하고, 데이터 손상으로 이어질 수 있다. 공격명 일부는 자막이 불명확하다.

대응책은 모든 마이그레이션 트래픽의 종단 간 암호화(TLS 예시), 양 끝점의 강력한 인증·접근 제어, 이동 경로의 네트워크 보안·격리, 전송 중 악성 행위 모니터링 및 규정 준수 점검이다. 핵심은 제어 영역과 데이터 전송을 함께 보호하고, 허가된 출발지·목적지 사이에서만 이동하도록 관리하는 것이다. (01:14:08–01:15:17)

## 교수 강조 사항

- VM 하나의 침해가 같은 하이퍼바이저·물리 서버의 다른 VM으로 확산될 수 있으며, 멀티테넌트 클라우드에서는 다수 고객의 데이터·서비스에 영향을 주므로 VM 격리는 핵심 보안 경계다. (00:09:00–00:09:52, 00:16:00–00:18:16)
- VM Escape는 게스트 VM 내부에서 시작해 격리 경계를 넘고, Hyperjacking은 호스트 OS 쪽에서 시작해 하이퍼바이저 제어권을 빼앗는다는 차이를 구분할 것. (00:32:15–00:34:30, 00:38:30–00:40:00)
- 최소 권한 원칙·Zero Trust, 세분화된 네트워크 격리, 하이퍼바이저·호스트 OS의 지속적 패치와 모니터링을 여러 대응에서 반복해서 강조한다. (00:24:15–00:27:47, 00:48:01–00:50:31)
- VM Sprawl은 취약점 기반 침해와 같은 공격 유형이라기보다 관리 실패로 생길 수 있는 통제되지 않은 확산이며, 비용·자원 낭비와 패치·대응의 복잡성을 낳는다. 자원 모니터링과 사용 목적·예상량 설정, 수명주기 관리가 중요하다. (00:51:45–00:55:45, 00:58:00–01:00:00)
- 교차 VM 부채널 공격은 직접 침투가 없는 수동 공격이라 탐지가 특히 어렵고, 강의가 가장 중요하게 꼽은 방어는 격리·파티셔닝이다. (01:02:16–01:04:15, 01:07:50–01:10:22)
- VM 이동은 운영·복구에 유용하지만 전송 중 제어 영역, 데이터, 모듈이 각각 공격받을 수 있다. 암호화, 강한 인증, 네트워크 격리와 모니터링을 갖춰야 한다. (01:11:55–01:15:17)
- 강의 중 “교과서적인 내용”이라고 짧게 언급한 패치·보안 구성·모니터링 등은 중요도를 낮춘다는 뜻이 아니라 기본 방어를 반복 적용하라는 맥락으로 정리했다. 교수는 별도의 시험 출제 예고를 하지 않았다.

## 확인이 필요한 부분

- 취약점 사례의 CVE 고유 식별번호는 자막에 나오지 않거나 판독할 수 없어 기록하지 않았다. VENOM, VMware·VirtualBox·Linux KVM 사례의 정확한 번호와 일부 세부 취약점 설명은 원문 슬라이드 확인이 필요하다. (00:20:45–00:23:00)
- Hyperjacking 사례 중 Windows 권한 상승 취약점 명칭은 자막에 “제로록”으로 들린다. 정확한 고유명사와 강의 슬라이드의 표기를 확인할 필요가 있다. (00:47:00–00:47:30)
- Pulse Secure VPN·Spectre 사례는 Hyperjacking과의 구체적 연결 및 취약점 식별번호가 자막만으로 충분히 특정되지 않는다. 교수의 사례 언급으로만 기록했다. (00:47:16–00:47:45)
- VM Escape·Hyperjacking 비교 슬라이드의 표 일부(예시 아키텍처·탐지 난이도 등)는 교수의 구두 설명만 남아 있어 표의 정확한 열 제목과 표현은 슬라이드 확인이 필요하다. (00:38:30–00:40:00)
- 마이그레이션 공격 중 세 번째 공격명은 자막상 “퍼스트 마이그레이션”처럼 들리며 뜻이 불명확하다. 본문에는 무단 마이그레이션·중단 및 DoS라는 설명만 반영했다. (01:13:15–01:14:08)
- 강의 말미 01:15:24 이후는 수업 종료 발화 뒤 자막이 훼손되어 의미를 확인할 수 없다. 본문 요약에서 제외했다. (01:15:17–01:15:50)

## 자가 점검 문항

아래 문항은 요약 내용을 복습하기 위해 새로 만든 문제이며, 교수의 출제 예고나 실제 시험문제가 아니다.

1. VM Escape와 Hyperjacking의 시작 위치와 주요 침해 경로는 어떻게 다른가?  
   **답:** VM Escape는 게스트 VM 내부에서 시작해 취약점을 이용해 격리 경계를 넘는다. Hyperjacking은 외부에서 호스트 OS를 침해하고 권한을 높여 하이퍼바이저 제어권을 장악한다. (00:32:15–00:34:30)
2. VM Escape가 멀티테넌트 클라우드에서 특히 위험한 이유는 무엇인가?  
   **답:** VM들이 같은 하이퍼바이저와 물리 자원을 공유하므로 한 VM 침해가 다른 VM·테넌트로 확산되어 정보 유출, 서비스 중단, 격리·신뢰 위반을 일으킬 수 있기 때문이다. (00:09:00–00:09:52, 00:16:00–00:18:16)
3. VM Sprawl을 침해 공격과 구분하고, 핵심 관리책 두 가지를 말하라.  
   **답:** 스프롤은 흔히 관리 부실로 VM이 통제 없이 늘어나는 현상이며, 핵심은 자원 사용량의 지속 모니터링과 목적이 끝난 VM을 회수하는 수명주기 관리다. (00:51:45–00:55:45, 00:58:00–01:00:00)
4. 교차 VM 부채널 공격이 수동적이고 탐지하기 어려운 이유는 무엇이며, 강의가 우선 강조한 방어는 무엇인가?  
   **답:** 직접 침투·코드 실행 없이 캐시·메모리·타이밍 등 공유 자원의 흔적만 관찰해 정보를 추론하므로 눈에 띄는 손상을 남기기 어렵다. 핵심 방어는 VM·하드웨어 자원의 강한 격리와 파티셔닝이다. (01:02:16–01:04:15, 01:07:50–01:10:22)
5. Live Migration과 Cold Migration의 차이 및 이동 중 대표 위험 하나를 설명하라.  
   **답:** Live는 VM이 실행 중인 상태에서, Cold는 VM을 끈 상태에서 이동한다. 전송 중에는 하이재킹으로 악성 호스트에 보내거나 도청으로 민감 정보를 빼내는 위험 등이 있다. (01:10:22–01:11:03, 01:12:20–01:13:15)
6. 마이그레이션 전송을 보호하는 강의의 대응책을 세 가지 말하라.  
   **답:** TLS 등을 이용한 종단 간 암호화, 양 끝점의 강력한 인증·접근 통제, 네트워크 격리·보안 및 전송 중 모니터링이다. (01:14:08–01:15:17)
