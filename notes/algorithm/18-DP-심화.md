# DP 심화 (Advanced Dynamic Programming)

> 알고리즘 · DP · 학습내용: 플래티넘 구간에서 요구되는 DP 유형 — 비트마스크 DP(외판원 순회 형태 dp[mask][i]), 트리 DP(서브트리 기준 점화와 자식→부모 병합, 트리 최대 독립집합), 구간 DP(dp[i][j] — 행렬 곱셈 순서·팰린드롬 분할), 자릿수 DP(digit DP), DP 최적화(누적합으로 전이 줄이기, 슬라이딩 윈도우 최댓값으로 전이 O(1)), 메모리 토글링, 파이썬 DP 성능 튜닝

## 1. 비트마스크 DP — 집합을 정수 하나로 ★★★

**"어떤 원소들을 이미 처리했는가"가 상태의 일부일 때** 그 집합을 정수 비트로 압축한다. 원소가 n개면 상태 수는 2^n이므로 **n ≤ 20~22가 사실상 상한**이다(2^20 ≈ 100만).

**외판원 순회(TSP) 형태**가 대표적이다.

- 상태: `dp[mask][i]` = **방문한 도시 집합이 mask**이고 **현재 i번 도시에 서 있을 때**의 최소 비용
- 점화식: `dp[mask | (1<<j)][j] = min(..., dp[mask][i] + dist[i][j])`
- 답: `min(dp[full][i] + dist[i][0])`

**출발지를 0번으로 고정**하는 게 핵심이다. 순환 경로라 어디서 출발하든 같고, 고정하면 상태가 n배 줄어든다. 복잡도는 **O(2^n · n^2)** — n=16이면 약 1,600만 연산으로 아슬아슬하게 통과하고, n=20(4억)이면 도달 불가 상태를 건너뛰는 가지치기가 필수다.

```python
INF = float('inf')

def tsp(dist):
    """dist[i][j] == 0 이면 i->j 길이 없다는 뜻. 0번에서 출발해 전부 돌고 복귀."""
    n, full = len(dist), (1 << len(dist)) - 1
    dp = [[INF] * n for _ in range(1 << n)]
    dp[1][0] = 0                                  # 0번만 방문, 0번에 서 있음
    for mask in range(1 << n):
        if not mask & 1: continue                 # 0번을 안 거친 상태는 불가능
        for i in range(n):
            cur = dp[mask][i]
            if cur == INF or not mask >> i & 1: continue
            for j in range(n):
                if mask >> j & 1 or dist[i][j] == 0:
                    continue                      # 이미 방문했거나 길이 없음
                nxt = mask | (1 << j)
                if cur + dist[i][j] < dp[nxt][j]:
                    dp[nxt][j] = cur + dist[i][j]
    return min((dp[full][i] + dist[i][0]
                for i in range(n) if dist[i][0] and dp[full][i] < INF), default=-1)

d = [[0, 10, 15, 20], [10, 0, 35, 25], [15, 35, 0, 30], [20, 25, 30, 0]]
print(tsp(d))     # 80   (0 -> 1 -> 3 -> 2 -> 0)
```

> ★★★ **핵심**: 비트마스크 DP의 두 형태를 구분해야 한다. **"밀어주기(forward)"**는 현재 상태에서 다음 상태로 값을 갱신하고(위 코드), **"당겨오기(pull)"**는 `dp[mask][i]`를 `mask`에서 i를 뺀 상태들로부터 계산한다. 밀어주기는 도달 불가 상태를 `INF`로 건너뛸 수 있어 **실전에서 더 빠른 경우가 많다.**

## 2. 트리 DP — 자식에서 부모로 병합 ★★★

트리에는 사이클이 없으므로 **각 정점을 루트로 하는 서브트리**가 자연스러운 부분 문제가 된다. 점화식은 항상 **"자식들의 답을 모아 부모의 답을 만든다"** 꼴이다.

**트리 최대 가중 독립집합**은 인접한 두 정점을 동시에 고를 수 없을 때 가중치 합의 최대를 구한다. 상태를 **"이 정점을 고르느냐 마느냐"** 두 개로 쪼갠다.

- `dp1[v]` = v를 **고르는** 경우 v의 서브트리 최댓값 = `w[v] + sum(dp0[c])`
- `dp0[v]` = v를 **안 고르는** 경우 = `sum(max(dp0[c], dp1[c]))`

```python
def tree_max_independent_set(n, edges, w):
    adj = [[] for _ in range(n)]
    for a, b in edges:
        adj[a].append(b); adj[b].append(a)
    # 1) 반복 DFS로 방문 순서와 부모를 구한다 (재귀 깊이 회피)
    parent, order, visited, stack = [-1] * n, [], [False] * n, [0]
    visited[0] = True
    while stack:
        v = stack.pop(); order.append(v)
        for u in adj[v]:
            if not visited[u]:
                visited[u] = True; parent[u] = v; stack.append(u)
    # 2) 방문 순서의 역순 = 자식이 항상 부모보다 먼저 처리되는 순서
    dp0, dp1 = [0] * n, [0] * n
    for v in reversed(order):
        dp1[v] += w[v]
        for u in adj[v]:
            if u == parent[v]: continue
            dp0[v] += max(dp0[u], dp1[u])   # v를 안 고르면 자식은 자유
            dp1[v] += dp0[u]                # v를 고르면 자식은 못 고름
    return max(dp0[0], dp1[0])

edges, w = [(0, 1), (0, 2), (1, 3), (1, 4), (2, 5)], [10, 20, 30, 40, 50, 60]
print(tree_max_independent_set(6, edges, w))                       # 160 (0,3,4,5)
print(tree_max_independent_set(3, [(0, 1), (1, 2)], [1, 10, 1]))   # 10
```

> ★★★ **핵심**: 파이썬에서 트리 DP를 재귀로 짜면 **일자 트리(선형)에서 깊이가 정점 수만큼 되어 터진다.** 위처럼 **반복 DFS로 방문 순서(order)를 먼저 뽑고, 그 역순으로 순회**하면 자식이 부모보다 항상 먼저 계산되어 재귀 없이 같은 결과를 얻는다. 이 패턴은 트리 DP 전반에 그대로 재사용되므로 통째로 외워두는 게 좋다.

## 3. 구간 DP — dp[i][j]와 분할점 k ★★

**"구간 [i, j]를 어떻게 쪼개느냐"**가 문제일 때 쓴다. 공통 골격은 **길이가 짧은 구간부터 채우고, 분할점 k를 순회**하는 것이며 시간 복잡도는 보통 **O(n^3)**이다.

```python
def matrix_chain(p):
    """p = [d0, d1, ..., dn] 일 때 행렬 A_i 는 p[i] x p[i+1].
    곱셈 연산 횟수를 최소로 만드는 괄호 묶기."""
    n = len(p) - 1
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):              # 짧은 구간부터
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = min(dp[i][k] + dp[k + 1][j] + p[i] * p[k + 1] * p[j + 1]
                           for k in range(i, j))   # 분할점 k 순회
    return dp[0][n - 1]

def min_palindrome_pieces(s):
    """문자열을 팰린드롬 조각으로 나눌 때 최소 조각 수."""
    n = len(s)
    pal = [[False] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):              # i를 역순으로 → pal[i+1][j-1] 선계산 보장
        for j in range(i, n):
            if s[i] == s[j] and (j - i < 2 or pal[i + 1][j - 1]):
                pal[i][j] = True

    dp = [float('inf')] * (n + 1); dp[0] = 0    # dp[i] = s[:i]의 최소 조각 수
    for i in range(1, n + 1):
        for j in range(i):
            if pal[j][i - 1] and dp[j] + 1 < dp[i]:
                dp[i] = dp[j] + 1
    return dp[n]

print(matrix_chain([10, 20, 30, 40, 30]), matrix_chain([5, 10, 3, 12, 5, 50, 6]))
# 30000 2010
print([min_palindrome_pieces(x) for x in ("ABACABA", "aab", "abcde")])   # [1, 2, 5]
```

> **함정**: 구간 DP에서 **반복 순서를 인덱스 i, j로 잡으면 거의 항상 틀린다.** `dp[i][j]`는 자기보다 **짧은** 구간에 의존하므로 **바깥 루프는 반드시 구간 길이(length)**여야 한다. 팰린드롬 판정표처럼 `i`를 역순으로 돌아 안쪽 구간이 먼저 채워지게 하는 방식도 같은 원리다.

## 4. 자릿수 DP (Digit DP) ★★

**"1 이상 N 이하 정수 중 조건을 만족하는 개수"**처럼 N이 10^18급이라 셀 수 없을 때 쓴다. N을 문자열로 보고 **한 자리씩 채워 나가는** DP다.

상태는 거의 항상 아래 셋 + 문제별 추가 정보다.

| 상태 | 의미 |
|---|---|
| `pos` | 지금 정하려는 자릿수 위치 |
| `tight` | 여기까지 N과 **완전히 같게** 왔는가 (True면 이번 자리는 `N[pos]` 이하만 가능) |
| `started` | **유효 숫자가 시작됐는가** (앞의 0들은 실제 자릿수가 아님) |

```python
from functools import cache

def count_no_adjacent_equal(N):
    """0 이상 N 이하 정수 중, 이웃한 두 자리가 같지 않은 수의 개수."""
    s, n = str(N), len(str(N))
    @cache
    def go(pos, prev, tight, started):
        if pos == n: return 1
        hi, total = (int(s[pos]) if tight else 9), 0
        for d in range(hi + 1):
            if started and d == prev: continue   # 앞자리와 같으면 불가
            total += go(pos + 1, d, tight and d == hi, started or d > 0)
        return total
    result = go(0, -1, True, False)
    go.cache_clear()                       # 다음 호출에 캐시가 새면 안 된다
    return result

def brute(N):                              # 브루트포스로 정확성 검증
    return sum(all(t[i] != t[i + 1] for i in range(len(t) - 1))
               for t in map(str, range(N + 1)))

print([(N, count_no_adjacent_equal(N), brute(N)) for N in (9, 10, 99, 1234, 5000)])
# [(9, 10, 10), (10, 11, 11), (99, 91, 91), (1234, 923, 923), (5000, 3736, 3736)]

print(count_no_adjacent_equal(10 ** 18))   # 168856464709124011 (브루트포스로는 불가능)
```

> **함정**: `tight`를 상태에서 빼먹으면 N을 초과하는 수까지 세고, `started`를 빼먹으면 **앞자리 0을 실제 자릿수로 취급**해 답이 어긋난다. 그리고 `@cache`를 쓴 뒤 **`cache_clear()`를 안 하면** 다른 N으로 부를 때 이전 문자열 `s`를 기준으로 만든 값이 그대로 반환된다(위 코드에서 `s`가 클로저 변수라 캐시 키에 안 들어가기 때문). 자릿수 DP 사고의 90%가 이 지점에서 난다.

## 5. DP 최적화 (1) — 누적합으로 전이 줄이기 ★★

`dp[i] = sum(dp[j] for j in 구간)` 꼴이면 **구간합을 매번 다시 계산하지 말고 굴려서 O(1)로** 만든다(**O(nk) → O(n)**). **"구간에 대한 합/최대"가 전이에 등장하면 최적화 여지가 있다**는 신호이며, 합이면 누적합, 최대·최소면 다음 절의 단조 덱이다.

```python
MOD = 1_000_000_007

def steps_naive(n, k):
    """1 ~ k 칸씩 오를 때 n칸을 오르는 방법의 수. O(n*k)"""
    dp = [0] * (n + 1); dp[0] = 1
    for i in range(1, n + 1):
        for j in range(1, min(k, i) + 1):
            dp[i] = (dp[i] + dp[i - j]) % MOD
    return dp[n]

def steps_prefix(n, k):
    """같은 문제를 '굴러가는 구간합'으로. O(n)"""
    dp = [0] * (n + 1); dp[0] = 1
    window = 1                       # dp[i-k] ~ dp[i-1] 의 합
    for i in range(1, n + 1):
        dp[i] = window % MOD
        window += dp[i]              # 오른쪽 편입
        if i - k >= 0: window -= dp[i - k]   # 왼쪽 이탈
    return dp[n] % MOD

print(steps_naive(10, 3), steps_prefix(10, 3))       # 274 274
print(steps_naive(1000, 7) == steps_prefix(1000, 7)) # True
```

## 6. DP 최적화 (2) — 슬라이딩 윈도우 최댓값 ★★

`dp[i] = max(dp[j] for j in [i-k, i-1]) + a[i]` 꼴은 **단조 감소 덱**으로 전이를 **분할상환 O(1)**에 처리한다. 덱에는 **"앞으로 최댓값이 될 가능성이 있는 인덱스만"** 감소 순서로 남긴다.

```python
from collections import deque

def max_sum_naive(a, k):
    """연속으로 k칸 넘게 건너뛸 수 없을 때 얻는 값의 최댓값. O(n*k)"""
    dp = [0] * len(a); dp[0] = a[0]
    for i in range(1, len(a)):
        dp[i] = max(dp[max(0, i - k):i]) + a[i]
    return dp[-1]

def max_sum_deque(a, k):
    """같은 점화식을 단조 덱으로. O(n)"""
    dp = [0] * len(a); dp[0] = a[0]
    dq = deque([0])                       # dp값이 감소 순인 인덱스들
    for i in range(1, len(a)):
        while dq and dq[0] < i - k:       # 창 밖으로 나간 인덱스 제거
            dq.popleft()
        dp[i] = dp[dq[0]] + a[i]          # 창 안의 최댓값은 항상 맨 앞
        while dq and dp[dq[-1]] <= dp[i]: # 나보다 작은 뒤쪽은 영원히 쓸모없다
            dq.pop()
        dq.append(i)
    return dp[-1]

import random
random.seed(42)
for _ in range(200):
    a = [random.randint(-20, 20) for _ in range(random.randint(2, 30))]
    k = random.randint(1, 5)
    assert max_sum_naive(a, k) == max_sum_deque(a, k)
print("랜덤 200케이스 일치")
a = [1, -50, 3, -50, 5, -50, 7]
print(max_sum_naive(a, 2), max_sum_deque(a, 2))   # 16 16 (1 -> 3 -> 5 -> 7)
```

## 7. 메모리 최적화 — 토글링 ★★

`dp[i][*]`가 **`dp[i-1][*]`에만 의존**하면 전체 표를 들고 있을 이유가 없다. **2행만 유지**하고 번갈아 쓰거나(토글링), 아예 1행으로 덮어쓴다.

```python
def knapsack_full(items, cap):
    """정석 2차원: 메모리 O(n * cap)"""
    n = len(items)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        w, v = items[i - 1]
        for c in range(cap + 1):
            dp[i][c] = dp[i - 1][c]
            if c >= w: dp[i][c] = max(dp[i][c], dp[i - 1][c - w] + v)
    return dp[n][cap]

def knapsack_toggle(items, cap):
    """토글링: 2행만 유지. 메모리 O(cap). i&1 로 현재/이전 행을 번갈아 가리킨다."""
    dp = [[0] * (cap + 1) for _ in range(2)]
    for i, (w, v) in enumerate(items, start=1):
        cur, prev = i & 1, (i - 1) & 1
        for c in range(cap + 1):
            dp[cur][c] = dp[prev][c]
            if c >= w: dp[cur][c] = max(dp[cur][c], dp[prev][c - w] + v)
    return dp[len(items) & 1][cap]

items = [(6, 13), (4, 8), (3, 6), (5, 12), (2, 5), (9, 20)]
print(knapsack_full(items, 15), knapsack_toggle(items, 15))   # 33 33
```

| 방식 | 메모리 | 역추적(실제 선택 복원) |
|---|---|---|
| 전체 표 | O(n · cap) | **가능** |
| 토글링(2행) | O(cap) | 불가 |

> **함정**: **"몇 번째 물건을 담았는지 복원하라"는 요구가 있으면 토글링을 쓸 수 없다.** 메모리 최적화는 **답의 값만 필요할 때** 쓰는 기법이다. 역추적이 필요한데 메모리도 부족하면 Hirschberg 알고리즘처럼 분할정복으로 복원하는 별도 기법이 필요하다.

## 8. 파이썬 DP 성능 팁 ★★

파이썬은 상수가 크다. **같은 O(n^2)라도 어떻게 쓰느냐로 3~10배가 갈린다.**

```python
import time
N = 2000

# 1) 배열 생성: 리스트 컴프리헨션이 append 루프보다 빠르다
t = time.perf_counter(); a = [[0] * N for _ in range(N)]
t1 = time.perf_counter() - t
t = time.perf_counter()
b = []
for _ in range(N):
    row = []
    for _ in range(N): row.append(0)
    b.append(row)
t2 = time.perf_counter() - t
print(f"컴프리헨션 {t1:.3f}s / append 루프 {t2:.3f}s")

# 2) 지역변수 캐싱: 전역 조회는 매번 딕셔너리 조회다
arr = list(range(200000))
def slow_sum():
    s = 0
    for i in range(len(arr)): s += arr[i]   # arr 은 전역 조회 + 인덱싱
    return s
def fast_sum(arr=arr):                      # 인자 기본값으로 지역 바인딩
    s = 0
    for x in arr: s += x                    # 인덱싱 대신 직접 순회
    return s

t = time.perf_counter(); slow_sum(); t3 = time.perf_counter() - t
t = time.perf_counter(); fast_sum(); t4 = time.perf_counter() - t
print(f"전역+인덱싱 {t3:.3f}s / 지역+순회 {t4:.3f}s")
```

실전 체크리스트는 다음과 같다.

| 항목 | 권장 |
|---|---|
| DP 표 생성 | `[[0] * m for _ in range(n)]` — `[[0]*m]*n`은 **얕은 복사 버그** |
| 재귀 메모이제이션 | 상태 수가 크면 `@cache` 대신 **리스트 배열 + 반복문** |
| 반복문 안 전역 참조 | 루프 밖에서 지역 변수에 담아 쓰기 (`dp_local = dp`) |
| 입력 읽기 | `input = sys.stdin.readline`, 대량이면 `sys.stdin.buffer.read().split()` |
| 모듈러 | 매 연산마다 `% MOD` 하지 말고 **필요한 지점에서만** |

> ★★★ **핵심**: `@cache`는 편하지만 **호출당 튜플 생성 + 해시 + 함수 호출** 비용이 붙는다. 상태 수가 10^6을 넘으면 캐시 오버헤드만으로 시간 초과가 난다. **상태를 정수 인덱스로 사상해 리스트에 직접 저장하고 반복문으로 채우는 것**이 파이썬 DP 성능의 최종 형태다.

---

### 한 줄 요약
플래티넘 DP는 **상태에 무엇을 넣을지**로 갈린다 — 처리한 집합이면 **비트마스크(`dp[mask][i]`, n ≤ 20)**, 서브트리면 **트리 DP(반복 DFS로 순서를 뽑고 역순 병합)**, 구간 쪼개기면 **구간 DP(바깥 루프는 반드시 길이)**, 10^18급 카운팅이면 **자릿수 DP(pos·tight·started)**다. 여기에 **전이가 구간합이면 누적합, 구간 최대면 단조 덱**으로 O(1)까지 눌러주고, 값만 필요하면 **토글링으로 메모리를 한 차원 줄이며**, 파이썬에서는 마지막에 **`@cache`를 배열 반복문으로 갈아끼우는 것**이 통과와 시간 초과를 가른다.
