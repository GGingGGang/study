## 1. 그리디란 무엇인가

**그리디(탐욕법)는 매 단계에서 "지금 당장 가장 좋아 보이는 것"을 고르고 절대 되돌아보지 않는 방법이다.** 완전탐색이 모든 경우를 펼쳐 보는 것과 달리 각 단계에서 선택지를 하나로 확정하므로, 보통 **정렬 한 번(`O(N log N)`) 또는 힙 연산 한 번씩**으로 끝난다.

| | 완전탐색/백트래킹 | DP | 그리디 |
|---|---|---|---|
| 한 단계에서 보는 선택지 | 전부 | 전부 (단 메모) | **딱 하나** |
| 전형적 복잡도 | 지수 | `O(상태 수 × 전이 수)` | `O(N log N)` |
| 항상 정답인가 | 예 | 예 | **구조가 맞을 때만** |
| 틀렸을 때 증상 | 시간 초과 | 메모리 초과 | **조용히 오답** |

마지막 줄이 그리디의 무서운 점이다. 완전탐색이 틀리면 시간 초과로 티가 나지만 **그리디는 틀려도 답을 뱉는다.** 그래서 "짤 줄 아느냐"보다 **"이 문제에 써도 되는지 판단할 줄 아느냐"** 가 훨씬 중요하다.

> ★★★ **핵심**: 그리디 문제의 대부분은 **"무엇을 기준으로 정렬할 것인가"** 를 정하는 순간 끝난다. 코드는 정렬 뒤 for 루프 10줄이다. 어려운 건 구현이 아니라 **정렬 기준의 정당성**이다.

## 2. 성립 조건과 교환 논법 ★★★

그리디가 전체 최적을 보장하려면 **두 성질이 동시에** 필요하다.

| 성질 | 의미 | 확인하는 질문 |
|---|---|---|
| **탐욕적 선택 속성** (greedy choice property) | 지금의 국소 최적 선택을 포함하는 전체 최적해가 **반드시 존재한다** | "이걸 고른 뒤에도 최적에 도달할 길이 남아 있나?" |
| **최적 부분 구조** (optimal substructure) | 선택 후 남은 문제도 **같은 형태**이고, 그 최적해를 붙이면 전체 최적이 된다 | "선택 후 남은 게 원래 문제의 축소판인가?" |

**교환 논법(exchange argument)** 은 탐욕적 선택 속성을 증명하는 표준 도구이고, 논리는 세 문장이다. ① 내 그리디가 첫 번째로 고른 원소 `g`를 포함하지 **않는** 최적해 `OPT`가 있다고 **가정**한다. ② `OPT`에서 원소 하나 `o`를 빼고 `g`를 넣는 **교환**이 해를 절대 나쁘게 만들지 않음을 보인다. ③ 그러면 `g`를 포함하는 최적해가 존재하므로 그리디의 첫 선택은 안전하고, 나머지는 귀납으로 반복한다.

회의실 배정이라면 그리디는 **가장 먼저 끝나는 회의 `g`** 를 고르고, `OPT`의 첫 회의를 `o`라 하면 `g.end <= o.end`다. `o`를 빼고 `g`를 넣어도 **`g`가 더 일찍 끝나므로 뒤의 회의들과 새로 겹칠 일이 없고** 개수도 그대로다.

> ★★★ **핵심**: 교환 논법이 실전 도구인 이유는 **비교 규칙을 그대로 정렬 키로 옮길 수 있기 때문**이다. "인접한 두 원소 a, b의 순서를 바꿨을 때 어느 쪽이 이득인가"를 판단하는 함수가 곧 정렬 비교 함수다.

```python
from functools import cmp_to_key

def best_concat(nums: list[int]) -> str:
    # "a를 b 앞에 두는 게 이득인가?"라는 교환 논법 질문을 그대로 비교 함수로 옮긴다
    def cmp(a: str, b: str) -> int:
        if a + b > b + a:
            return -1                 # a를 앞에
        return 1 if a + b < b + a else 0
    s = sorted(map(str, nums), key=cmp_to_key(cmp))
    return str(int("".join(s)))       # 앞이 전부 0인 "000" -> "0"

print(best_concat([3, 30, 34, 5, 9]), best_concat([0, 0]))   # 9534330 0
```

> **함정**: `cmp_to_key`는 C 레벨 `key` 대신 래퍼 객체를 끼워 넣기 때문에 **일반 `key=`보다 눈에 띄게 느리다.** `N`이 수십만이면 시간 초과 요인이다. 가능하면 `key=lambda x: (-x[1], x[0])` 같은 **튜플 키로 환원**하고, 환원이 불가능한 "쌍 비교"에서만 쓴다.

## 3. 정렬 기준 설계가 곧 풀이 ★★★

### 3-1. 회의실 배정형 — 끝나는 시간 오름차순

**최대 몇 개의 겹치지 않는 구간을 고를 수 있는가.** 정답은 **끝나는 시간이 이른 것부터** 고르는 것이다. 회의를 하나 고르는 순간 남는 자원은 "그 회의가 끝난 뒤의 시간"뿐이므로, **끝이 이를수록 뒤에 남는 시간이 길다** — 남은 문제를 가장 크게 남기는 선택이다.

```python
def max_meetings(meets: list[tuple[int, int]]) -> int:
    meets.sort(key=lambda t: (t[1], t[0]))   # 끝나는 시간, 같으면 시작 시간
    cnt, last_end = 0, -float("inf")         # last_end = 직전에 고른 회의가 끝난 시각
    for s, e in meets:
        if s >= last_end:                    # 겹치지 않으면 무조건 고른다
            cnt, last_end = cnt + 1, e
    return cnt

print(max_meetings([(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (6, 10), (8, 11)]))   # 3
```

| 잘못된 기준 | 반례 | 그리디 / 정답 |
|---|---|---|
| **시작 시간 오름차순** | `(0,8) (1,7) (3,3) (3,4) (6,6) (8,9)` | 2 / 4 |
| **소요 시간 짧은 순** | `(1,4) (3,5) (4,8) (10,10) (10,10)` | 3 / 4 |

> **함정**: `s >= last_end`인지 `s > last_end`인지는 **문제가 "끝나자마자 바로 시작"을 허용하는가**에 달렸다. 회의실은 보통 허용(`>=`), "쉬는 시간 필요"면 `>`다. **길이 0짜리 구간(`(3,3)`)이 입력에 들어오는지**도 꼭 확인한다.

### 3-2. 마감 있는 작업 스케줄링 — 정렬 + 힙 되돌리기

각 작업은 **1시간**이 걸리고 **마감 이내**에 끝내야 이득을 얻는다. 이득 합의 최댓값을 구한다.

```python
import heapq

def max_profit_with_deadline(jobs: list[tuple[int, int]]) -> int:
    jobs.sort()                       # jobs: (마감, 이득) -> 마감 오름차순
    heap: list[int] = []              # 지금까지 선택한 작업들의 이득 (최소 힙)
    for deadline, profit in jobs:
        heapq.heappush(heap, profit)  # 일단 넣고 본다
        if len(heap) > deadline:      # 마감을 못 지키게 됐으면
            heapq.heappop(heap)       # 가장 이득이 작은 것을 버린다
    return sum(heap)

print(max_profit_with_deadline([(4, 20), (1, 10), (1, 40), (1, 30)]))            # 60
print(max_profit_with_deadline([(2, 100), (1, 19), (2, 27), (1, 25), (3, 15)]))  # 142
```

**"일단 넣고, 넘치면 최악을 버린다"** 는 그리디의 대표적 변형이다. 순수 그리디는 되돌아보지 않지만 여기서는 **최소 힙이 "버릴 후보"를 항상 `O(log N)`에 알려주므로** 되돌리기가 가능하다. 전체 `O(N log N)`.

### 3-3. 분수 배낭 — 단위 가치 내림차순

**물건을 쪼갤 수 있으면** 단위 무게당 가치(`v/w`)가 큰 것부터 담는 게 항상 최적이다.

```python
def fractional_knapsack(items: list[tuple[int, int]], cap: int) -> float:
    items.sort(key=lambda wv: wv[1] / wv[0], reverse=True)   # items: (무게, 가치)
    total = 0.0
    for w, v in items:
        if cap >= w:
            cap, total = cap - w, total + v
        else:
            total += v * (cap / w)    # 남은 용량만큼만 쪼개 담고 끝
            break
    return total

print(fractional_knapsack([(10, 60), (20, 100), (30, 120)], 50))   # 240.0
```

> ★★★ **핵심**: **쪼갤 수 있으면 그리디, 쪼갤 수 없으면 DP다.** 0/1 배낭에서 단위 가치 그리디가 깨지는 이유는 "용량이 애매하게 남는" 상황을 쪼개서 메울 수 없기 때문이다. 그리디와 DP를 가르는 가장 선명한 예다.

## 4. 우선순위 큐 결합 그리디 ★★

정렬은 **처음 한 번 정하는 순서**지만 힙은 **매 순간 바뀌는 상태에서 최선을 뽑는다.** 선택 결과가 다시 후보로 들어오는 문제라면 힙이다.

```python
import heapq

def min_merge_cost(nums: list[int]) -> int:
    # 두 묶음을 합칠 때 (a+b) 비용이 든다. 전부 합칠 때의 최소 비용.
    heap = nums[:]
    heapq.heapify(heap)               # 리스트 -> 힙, O(N)
    cost = 0
    while len(heap) > 1:
        a = heapq.heappop(heap)       # 항상 가장 작은 두 개를 합친다
        b = heapq.heappop(heap)
        cost += a + b
        heapq.heappush(heap, a + b)   # 합친 결과가 다시 후보가 된다
    return cost

print(min_merge_cost([10, 20, 40]), min_merge_cost([1, 2, 3, 4]), min_merge_cost([7]))
# 100 19 0
```

**정당성**: 어떤 원소가 총비용에 더해지는 횟수 = 병합 트리에서의 깊이다. 따라서 **큰 값일수록 얕은 곳(늦게 합쳐지는 곳)에 두어야** 하고, 이는 매번 가장 작은 둘을 합치는 것과 같다(허프만 코딩과 같은 논리). `O(N log N)`.

| heapq 관용구 | 코드 |
|---|---|
| 최소 힙 만들기 | `heapq.heapify(lst)` — `O(N)` |
| 넣기 / 빼기 | `heapq.heappush(h, x)` / `heapq.heappop(h)` |
| **최대 힙 흉내** | 부호를 뒤집어 넣고 뺄 때 다시 뒤집기 (`-x`) |
| 튜플로 넣기 | `(우선순위, 순번, 객체)` — 두 번째 원소로 **동점 처리** |
| 넣고 바로 빼기 | `heapq.heappushpop(h, x)` (재정렬 한 번으로 끝) |

> **함정**: 힙에 `(비용, 객체)`를 넣을 때 비용이 같으면 파이썬은 **두 번째 원소끼리 비교한다.** 객체에 `<`가 없으면 `TypeError`다. **`(비용, 고유 순번, 객체)`처럼 절대 겹치지 않는 tie-breaker를 중간에 끼워 넣는 게 안전하다.**

## 5. 구간 문제 3종 ★★

구간(interval) 문제는 **목표에 따라 정렬 기준이 달라진다.** 최대 개수 선택은 3-1에서 다뤘고, 나머지 둘을 본다.

| 유형 | 정렬 기준 | 유지하는 상태 |
|---|---|---|
| **최대 개수 선택** (겹치지 않게) | **끝점** 오름차순 | 직전에 고른 구간의 끝 |
| **최소 개수로 덮기** | **시작점** 오름차순 | 현재 도달점 + 후보 중 최대 도달점 |
| **겹치는 것 병합** | **시작점** 오름차순 | 현재 병합 중인 구간의 끝 |

```python
def min_intervals_to_cover(intervals: list[tuple[int, int]], target: int) -> int:
    intervals.sort()                  # 시작점 오름차순
    reach, best, cnt, i, n = 0, 0, 0, 0, len(intervals)
    while reach < target:
        while i < n and intervals[i][0] <= reach:   # 도달 가능한 후보를 전부 훑어
            best = max(best, intervals[i][1])       # 가장 멀리 가는 것을 고른다
            i += 1
        if best <= reach:             # 더 못 뻗으면 덮을 수 없다
            return -1
        reach, cnt = best, cnt + 1
    return cnt

print(min_intervals_to_cover([(0, 3), (2, 5), (4, 9), (8, 10)], 10))   # 4
print(min_intervals_to_cover([(0, 1), (3, 5)], 5))                     # -1
```

`i`가 되돌아가지 않으므로 정렬 이후 루프는 `O(N)`, 전체 `O(N log N)`이다. **덮을 수 없는 경우(`-1`)를 반드시 처리**해야 무한 루프에 빠지지 않는다.

```python
def merge_intervals(intervals: list[tuple[int, int]]) -> list[tuple[int, int]]:
    out: list[list[int]] = []
    for s, e in sorted(intervals):              # 시작점 오름차순
        if out and s <= out[-1][1]:             # 닿기만 해도 붙인다
            out[-1][1] = max(out[-1][1], e)     # max 필수: 포함 관계 대비
        else:
            out.append([s, e])
    return [tuple(x) for x in out]

print(merge_intervals([(1, 3), (2, 6), (8, 10)]), merge_intervals([(1, 4), (4, 5)]))
# [(1, 6), (8, 10)] [(1, 5)]
```

> **함정**: `out[-1][1] = e`로 쓰면 **`(1, 10)` 다음에 `(2, 3)`이 오는 포함 관계에서 끝점이 10에서 3으로 줄어든다.** 반드시 `max`를 씌운다. 또 `s <= end`(닿으면 병합)와 `s < end`(진짜 겹칠 때만)는 **서로 다른 문제다.**

## 6. 스위핑 (sweep line) ★★★

**스위핑은 좌표축을 따라 가상의 선을 왼쪽에서 오른쪽으로 훑으면서, 선이 만나는 "이벤트"마다 상태를 갱신하는 기법이다.** 2차원 문제를 "정렬 + 1차원 스캔"으로 낮춘다. 절차는 세 단계다.

1. **이벤트 추출** — 각 객체를 `(좌표, 우선순위, 변화량)` 튜플로 분해한다. 구간 하나는 보통 **시작 이벤트 + 끝 이벤트 두 개**가 된다.
2. **정렬** — 좌표 오름차순. **동일 좌표에서의 처리 순서를 정렬 키로 강제한다.**
3. **스캔** — 순서대로 보며 상태(카운터·집합·힙)를 갱신하고 답을 모은다.

**같은 좌표에서 "끝"과 "시작"이 만날 때 어느 쪽을 먼저 처리하느냐로 답이 갈린다.** `if`문으로 예외 처리하지 말고 **정렬 키 안에 규칙을 박아 넣어야** 실수가 없다.

```python
def max_overlap(intervals, touching_overlaps: bool = False) -> int:
    # 이벤트 = (좌표, 우선순위, 변화량). 같은 좌표에서는 우선순위가 작은 쪽이 먼저다.
    # touching_overlaps=True  -> 닫힌 구간 [s, e]: 끝점이 닿으면 겹침  -> 시작 먼저
    # touching_overlaps=False -> 반열림 [s, e):   끝점이 닿으면 안 겹침 -> 끝 먼저
    start_pri, end_pri = (0, 1) if touching_overlaps else (1, 0)
    ev = sorted([(s, start_pri, +1) for s, _ in intervals]
                + [(e, end_pri, -1) for _, e in intervals])
    cur = best = 0
    for _, _, delta in ev:
        cur += delta
        best = max(best, cur)
    return best

print(max_overlap([(1, 4), (2, 4), (3, 4)]), max_overlap([]))            # 3 0
print(max_overlap([(1, 5), (5, 9)]), max_overlap([(1, 5), (5, 9)], True))  # 1 2
```

> ★★★ **핵심**: 이벤트 튜플의 **두 번째 원소는 "동점일 때의 우선순위"를 표현하는 자리다.** 먼저 처리할 타입에 더 작은 수를 준다. **문제를 읽자마자 "끝점이 닿는 걸 겹친다고 보나?"를 확인하고 그 답을 정렬 키에 반영**하는 게 스위핑의 절반이다.

깊이를 세는 대신 **덮인 길이**를 구할 수도 있다. `depth > 0`인 구간의 폭만 더하면 구간 합집합의 총 길이다.

```python
def union_length(intervals: list[tuple[int, int]]) -> int:
    ev = sorted([(s, +1) for s, _ in intervals] + [(e, -1) for _, e in intervals])
    total, depth, prev = 0, 0, 0
    for x, delta in ev:
        if depth > 0:                 # 직전 지점부터 여기까지 덮여 있었다면
            total += x - prev
        depth, prev = depth + delta, x
    return total

print(union_length([(1, 5), (3, 8), (10, 12)]), union_length([(0, 10), (2, 3)]))  # 9 10
```

## 7. 좌표 압축 + 스위핑 ★

좌표 범위가 `10**9`처럼 크지만 **실제 등장하는 값은 `N`개뿐**일 때, 값을 "몇 번째로 작은가"로 바꿔 배열 인덱스로 쓰는 게 **좌표 압축**이다 — `xs = sorted(set(values))`와 `idx = {v: i for i, v in enumerate(xs)}` 두 줄이면 끝난다. 직사각형 합집합의 넓이는 **x좌표를 압축해 세로 띠(strip)로 자르고, 각 띠 안에서 y구간을 병합**하면 구할 수 있다.

```python
def union_area(rects: list[tuple[int, int, int, int]]) -> int:
    xs = sorted({x for r in rects for x in (r[0], r[2])})   # rects: (x1, y1, x2, y2)
    area = 0
    for x_lo, x_hi in zip(xs, xs[1:]):                      # 세로 띠를 하나씩
        # 이 띠를 완전히 덮는 사각형들의 y구간만 모아 합집합 길이를 잰다
        ys = sorted((y1, y2) for (a, y1, b, y2) in rects if a <= x_lo and b >= x_hi)
        covered, end = 0, -float("inf")
        for y1, y2 in ys:
            covered += max(0, y2 - max(y1, end))            # 이미 덮인 부분은 빼고 더한다
            end = max(end, y2)
        area += (x_hi - x_lo) * covered
    return area

print(union_area([(0, 0, 2, 2), (1, 1, 3, 3)]), union_area([(0, 0, 2, 2)] * 2))  # 7 4
```

이 구현은 띠마다 전체 사각형을 훑어 `O(N^2 log N)`이라 `N`이 수천 이하일 때 쓴다. **`N`이 더 크면 y도 압축한 뒤 "구간에 +1/-1 하고 덮인 길이를 물어보는" 세그먼트 트리**로 각 이벤트를 `O(log N)`에 처리해 `O(N log N)`으로 낮춘다 — 직사각형 넓이 합의 정석 풀이다.

## 8. 그리디 vs DP ★★★

**그리디가 깨지는 전형적 구조는 "지금의 이득이 나중의 선택지를 파괴할 때"다.** 동전 거스름돈이 교과서적인 예다.

```python
def coin_greedy(coins: list[int], target: int) -> int:
    cnt, left = 0, target
    for c in sorted(coins, reverse=True):   # 큰 동전부터
        cnt, left = cnt + left // c, left % c
    return cnt if left == 0 else -1

def coin_dp(coins: list[int], target: int) -> int:
    INF = float("inf")
    dp = [0] + [INF] * target
    for v in range(1, target + 1):
        dp[v] = min((dp[v - c] + 1 for c in coins if c <= v), default=INF)
    return dp[target] if dp[target] != INF else -1

print(coin_greedy([1, 4, 5], 8), coin_dp([1, 4, 5], 8))         # 4 2  <- 그리디 오답
print(coin_greedy([1, 10, 50], 60), coin_dp([1, 10, 50], 60))   # 2 2  <- 우연히 일치
```

`[1, 4, 5]`로 8을 만들 때 그리디는 `5+1+1+1 = 4개`, 최적은 `4+4 = 2개`다. **5를 쓰는 순간 남은 3을 1원으로만 메워야 하는 상황에 갇힌다.** 한국 화폐(`1, 10, 50, 100, ...`)처럼 **큰 단위가 작은 단위의 배수인 구조**에서만 그리디가 성립한다.

| 신호 | 그리디 | DP |
|---|---|---|
| 원소를 **쪼갤 수 있다** | O | 불필요 |
| **정렬 순서만 정하면 답이 결정**된다 | O | — |
| 큰 단위가 작은 단위의 **배수 관계** | O | — |
| 선택이 **뒤의 선택지를 제한**한다 | X | O |
| **"경우의 수를 세라"** | X | O |
| 상태가 `(위치, 남은 자원)`처럼 **2개 이상** | 대개 X | O |

> ★★★ **핵심**: **애매하면 DP다.** 그리디가 맞는지 확신이 없는데 DP로도 시간 안에 들어온다면 무조건 DP를 택한다. 그리디는 **"DP로는 시간·메모리가 안 될 때 구조를 증명하고 쓰는" 최적화**로 접근하는 게 안전하다.

## 9. 그리디 정당성을 검증하는 법 ★★★

교환 논법으로 증명이 안 서면 **실험으로 반례를 찾는다.** ① **아주 작은 랜덤 입력**을 만들고(`N <= 6`, 값 범위 `<= 15`), ② 같은 입력을 **그리디**와 **완전탐색/DP(느리지만 확실한 정답)** 에 각각 넣고, ③ 답이 다른 첫 입력을 **반례**로 잡는다. 수천 번 돌려도 안 나오면 그리디를 **믿을 근거**가 된다. ④ **시드를 고정**해 반례를 재현 가능하게 만든다.

```python
import random

def greedy(coins, target):                          # 검증하고 싶은 빠른 풀이
    cnt, left = 0, target
    for c in sorted(coins, reverse=True):
        cnt, left = cnt + left // c, left % c
    return cnt if left == 0 else -1

def brute(coins, target):                           # 느리지만 확실한 정답
    INF = float("inf")
    dp = [0] + [INF] * target
    for v in range(1, target + 1):
        dp[v] = min((dp[v - c] + 1 for c in coins if c <= v), default=INF)
    return dp[target] if dp[target] != INF else -1

def stress(trials: int = 3000, seed: int = 0):
    rnd = random.Random(seed)                       # 시드 고정 -> 반례 재현 가능
    for _ in range(trials):
        coins = [1] + rnd.sample(range(2, 15), 2)   # 1을 포함 -> 항상 해가 존재
        target = rnd.randint(1, 40)
        g, b = greedy(coins, target), brute(coins, target)
        if g != b:                                  # 반례 발견 즉시 반환
            return {"coins": sorted(coins), "target": target, "greedy": g, "optimal": b}
    return None                                     # None이면 반례를 못 찾음

print(stress())   # {'coins': [1, 6, 10], 'target': 32, 'greedy': 5, 'optimal': 4}
```

같은 하네스를 **정렬 기준 검증**에도 그대로 쓴다. 회의실 배정에서 "끝나는 시간 순"과 "시작 시간 순"을 각각 완전탐색과 대조하면, **끝나는 시간 순은 수천 번을 돌려도 반례가 안 나오고 시작 시간 순은 몇십 번 만에 반례가 나온다.** 이 차이가 정렬 기준 선택의 실전 근거가 된다.

| 스트레스 테스트 설계 원칙 | 이유 |
|---|---|
| **입력을 최대한 작게** (`N <= 6`) | 반례를 사람이 손으로 검산할 수 있어야 한다 |
| **값 범위도 좁게** (`0 ~ 15`) | 좁아야 경계·중복·동점이 자주 발생한다 |
| **경계값을 일부러 섞기** | 길이 0 구간, 같은 좌표, 중복 원소가 진짜 함정이다 |
| **시드 고정 / 반례 즉시 중단** | 재현이 되어야 고치고 다시 확인할 수 있고, 작은 반례부터 봐야 원인이 보인다 |

> **함정**: 반례가 안 나온다고 **증명이 된 건 아니다.** 랜덤 생성기가 반례가 되는 구조를 애초에 못 만들고 있을 수 있다(예: 동전 값을 배수 관계로만 뽑으면 반례가 영원히 안 나온다). **생성기가 만드는 입력이 문제의 극단 케이스를 포함하는지** 눈으로 확인하는 습관이 필요하다.

### 한 줄 요약
그리디는 **"어떤 기준으로 정렬할 것인가"** 를 정하는 순간 코드가 끝나는 기법이고, 그 기준의 정당성은 **교환 논법 — 최적해에서 원소 하나를 내 선택으로 바꿔도 나빠지지 않음을 보이는 것** 으로 세운다. 실전에서는 **끝나는 시간 오름차순(구간 선택)·시작 시간 오름차순(덮기·병합)·단위 가치 내림차순(분수 배낭)** 세 기준과 **heapq로 "일단 넣고 넘치면 최악을 버리는"** 패턴만 손에 붙여도 상당수가 풀린다. 스위핑은 **구간을 `(좌표, 우선순위, 변화량)` 이벤트로 쪼개 정렬한 뒤 상태를 들고 훑는 것**이며, 승패는 거의 항상 **동일 좌표에서 시작과 끝 중 무엇을 먼저 처리할지를 정렬 키에 박아 넣었는가**에서 갈린다. 마지막으로 **확신이 안 서면 DP를 쓰고**, 그래도 그리디를 써야 한다면 **작은 랜덤 입력으로 완전탐색과 대조하는 스트레스 테스트**로 반례를 먼저 사냥하라.
