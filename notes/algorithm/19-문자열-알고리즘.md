## 1. 파이썬 문자열 기초 — 불변성이 성능을 지배한다 ★★

파이썬 문자열은 **불변(immutable)**이다. `s += x`는 기존 문자열을 수정하는 게 아니라 **매번 새 문자열을 통째로 복사해 만든다.** 반복문 안에서 이걸 하면 O(n^2)가 된다. 출력도 마찬가지라, 수만 줄을 `print()`로 하나씩 찍으면 I/O에서 시간 초과가 난다.

```python
import time, sys
n = 60000

t = time.perf_counter(); s = ''
for _ in range(n):
    s += 'a'                       # 매번 전체 복사 → O(n^2)
slow = time.perf_counter() - t

t = time.perf_counter(); buf = ['a' for _ in range(n)]      # 리스트에 모았다가
s2 = ''.join(buf)                  # 마지막에 한 번만 합친다 → O(n)
fast = time.perf_counter() - t
print(s == s2, f"+= {slow:.4f}s / join {fast:.4f}s")

sys.stdout.write('\n'.join(str(i) for i in range(3)) + '\n')  # 출력도 한 번에
print('-'.join(['a', 'b', 'c']), list("abc"))     # a-b-c ['a', 'b', 'c']
print("abcabc".find("ca"), "abcabc".count("bc"))  # 2 2
print("Hello"[::-1], ord('a'), chr(98), [ord(c) - ord('a') for c in "cab"])
# olleH 97 b [2, 0, 1]      마지막은 알파벳을 0..25 인덱스로 바꾸는 관용구
```

> **함정**: `in` 연산자(`if pat in text`)와 `str.find`는 CPython 내부에서 **Crochemore-Perrin 기반의 빠른 알고리즘**을 쓰므로 실무 입력에서는 직접 짠 KMP보다 훨씬 빠르다. **"포함 여부"나 "첫 위치"만 필요하면 내장 기능이 정답**이다. KMP를 직접 짜는 이유는 **모든 출현 위치, pi 배열 자체, 문자열 주기·경계(border) 정보**가 필요하기 때문이다.

## 2. KMP — 실패 함수로 되돌아가기 ★★★

단순 비교는 불일치가 나면 텍스트 포인터를 **되돌린다**(O(nm)). KMP는 **텍스트 포인터를 절대 되돌리지 않고** 패턴 포인터만 앞으로 당겨 **O(n + m)**을 만든다. `pi[i]`는 **`p[0..i]`의 접두사이면서 동시에 접미사인 가장 긴 문자열의 길이**(자기 자신 제외)다.

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| p | a | b | a | b | a | c | a |
| pi | 0 | 0 | 1 | 2 | 3 | 0 | 1 |

`pi[4] = 3`은 `"ababa"`의 접두사 `"aba"`가 접미사이기도 하다는 뜻이다. 그래서 5번째에서 불일치가 나도 **앞의 3글자는 이미 맞춰진 상태**라 처음부터 다시 볼 필요가 없다.

```python
def build_pi(p):
    """실패 함수. 패턴을 자기 자신과 매칭시키는 것과 같다."""
    m, pi, j = len(p), [0] * len(p), 0      # j = 현재까지 일치한 접두사 길이
    for i in range(1, m):
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]                   # 불일치 → 더 짧은 경계로 후퇴
        if p[i] == p[j]:
            j += 1; pi[i] = j
    return pi

def kmp_search(text, pat):
    """pat이 text에 나타나는 모든 시작 인덱스."""
    if not pat: return []
    pi, m, result, j = build_pi(pat), len(pat), [], 0
    for i, ch in enumerate(text):
        while j > 0 and ch != pat[j]:
            j = pi[j - 1]                   # 텍스트 포인터 i는 절대 안 돌아간다
        if ch == pat[j]:
            j += 1
            if j == m:                      # 완전 일치
                result.append(i - m + 1)
                j = pi[j - 1]               # 겹치는 다음 후보로 이어간다
    return result

def min_period(s):
    """s가 완전한 반복 구조일 때의 최소 주기 길이."""
    cand = len(s) - build_pi(s)[-1]
    return cand if len(s) % cand == 0 else len(s)

print(build_pi("ababaca"), build_pi("aaaa"))            # [0,0,1,2,3,0,1] [0,1,2,3]
print(kmp_search("ABABDABACDABABCABAB", "ABABCABAB"))   # [10]
print(kmp_search("aaaaa", "aa"))                # [0, 1, 2, 3] (겹치는 매칭도 잡음)
print([min_period(x) for x in ("abcabcabc", "aaaa", "abcd", "abcabca")])
# [3, 1, 4, 7]   (마지막은 완전한 반복이 아니라 자기 길이)

import random                               # 내장 find 결과와 대조 검증
random.seed(7)
def all_occ(t, p):
    out, k = [], t.find(p)
    while k >= 0: out.append(k); k = t.find(p, k + 1)
    return out
for _ in range(300):
    t = ''.join(random.choice('ab') for _ in range(random.randint(1, 30)))
    p = ''.join(random.choice('ab') for _ in range(random.randint(1, 4)))
    assert kmp_search(t, p) == all_occ(t, p)
print("KMP 랜덤 300케이스 통과")
```

> ★★★ **핵심**: pi 배열은 매칭 말고도 그 자체로 강력하다. **문자열 `s`의 최소 주기는 `len(s) - pi[-1]`**이다(단, `len(s) % 그 값 == 0`일 때만 실제 반복 구조). "어떤 부분 문자열의 반복인가", "접두사이자 접미사인 것을 모두 구하라" 같은 유형이 전부 pi 배열 하나로 풀린다.

## 3. 라빈-카프 — 롤링 해시 ★★

패턴과 텍스트 창(window)을 **숫자 하나로 바꿔 비교**한다. 창을 한 칸 옮길 때 **앞 글자를 빼고 뒤 글자를 더해 O(1)에 갱신**하는 게 롤링 해시다: `H(s) = s[0]*B^(m-1) + ... + s[m-1] (mod M)`.

```python
def rabin_karp(text, pat, base=131, mod=(1 << 61) - 1):
    n, m = len(text), len(pat)
    if m == 0 or m > n: return []
    ph = 0
    for ch in pat:
        ph = (ph * base + ord(ch)) % mod
    pw = pow(base, m, mod)                 # base^m (모듈러 거듭제곱)
    h, result = 0, []
    for i, ch in enumerate(text):
        h = (h * base + ord(ch)) % mod     # 뒤 글자 편입
        if i >= m:
            h = (h - ord(text[i - m]) * pw) % mod    # 앞 글자 이탈
        if i >= m - 1 and h == ph and text[i - m + 1:i + 1] == pat:
            result.append(i - m + 1)       # ★ 해시가 같아도 실제 비교는 필수
    return result

print(rabin_karp("ABABDABACDABABCABAB", "ABABCABAB"),
      rabin_karp("aaaaa", "aa"), rabin_karp("hello world", "o w"))  # [10] [0,1,2,3] [4]

import random
random.seed(11)
for _ in range(300):
    t = ''.join(random.choice('abc') for _ in range(random.randint(1, 40)))
    p = ''.join(random.choice('abc') for _ in range(random.randint(1, 5)))
    exp, k = [], t.find(p)
    while k >= 0: exp.append(k); k = t.find(p, k + 1)
    assert rabin_karp(t, p) == exp
print("라빈-카프 랜덤 300케이스 통과")
```

| 기준 | KMP | 라빈-카프 |
|---|---|---|
| 최악 복잡도 | **O(n + m) 보장** | O(nm) (해시 충돌 시) |
| 다중 패턴 | 패턴마다 따로 | **길이가 같으면 집합 비교로 한 번에** |
| 부분 문자열 비교 | 불가 | **임의 구간 해시로 O(1) 비교 가능** |

**라빈-카프의 진짜 가치는 "임의의 두 부분 문자열이 같은지 O(1)에 판정"**하는 데 있다. 접두사 해시 배열을 만들어 두면 `hash(s[l..r])`을 상수 시간에 뽑을 수 있어, 이분탐색과 결합해 "가장 긴 공통 접두사" 같은 문제를 로그 시간에 푼다.

## 4. 트라이 (Trie) — 접두사 트리 ★★★

문자열 집합을 **글자 단위 트리**로 저장한다. 길이 L인 문자열의 삽입·검색이 **저장된 단어 수와 무관하게 O(L)**이라 접두사 질의에 특히 강하다.

```python
class Trie:
    """dict 기반 트라이. 노드 = dict, 단어 끝은 특수 키 '$'로 표시."""
    END = '$'
    def __init__(self):
        self.root = {}
    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})           # 없으면 만들고 내려간다
        node[self.END] = node.get(self.END, 0) + 1   # 같은 단어 중복 카운트
    def _walk(self, s):
        node = self.root
        for ch in s:
            if ch not in node: return None
            node = node[ch]
        return node
    def search(self, word):                 # 정확히 이 단어가 있는가
        node = self._walk(word)
        return node is not None and self.END in node
    def starts_with(self, prefix):          # 이 접두사로 시작하는 단어가 있는가
        return self._walk(prefix) is not None
    def count_with_prefix(self, prefix):    # 서브트리의 END 값을 모두 더한다
        node = self._walk(prefix)
        if node is None: return 0
        total, stack = 0, [node]
        while stack:
            for k, v in stack.pop().items():
                if k == self.END: total += v
                else: stack.append(v)
        return total
    def longest_prefix_of(self, s):
        """s의 접두사 중 트라이에 저장된 가장 긴 것 (사전 매칭·라우팅용)"""
        node, best = self.root, ''
        for i, ch in enumerate(s):
            if ch not in node: break
            node = node[ch]
            if self.END in node: best = s[:i + 1]
        return best

t = Trie()
for w in ["apple", "app", "application", "apply", "banana", "app"]:
    t.insert(w)
print(t.search("app"), t.search("appl"))             # True False
print(t.starts_with("appl"), t.starts_with("bx"))               # True False
print(t.count_with_prefix("app"), t.count_with_prefix("ban"))   # 5 1
print(repr(t.longest_prefix_of("applesauce")), repr(t.longest_prefix_of("ap")))
# 'apple' ''
```

> ★★★ **핵심**: 트라이의 진짜 용도는 "단어가 있냐"가 **아니다**(그건 `set`이 더 빠르고 가볍다). 트라이를 쓰는 이유는 **접두사 기반 질의** — 자동완성, 접두사 개수 세기, **주어진 문자열의 접두사 중 사전에 있는 가장 긴 것 찾기**, 그리고 **XOR 최댓값(이진 트라이)** 때문이다.

> **함정**: 파이썬 dict 노드는 **노드 하나당 수백 바이트**를 먹는다. 단어 총 길이가 10^6을 넘으면 메모리 초과 위험이 크다. 알파벳이 26종으로 고정이면 **리스트 기반 노드 배열**(`children`을 인덱스로 관리)로 바꾸거나 정렬 + 이분탐색으로 우회한다.

## 5. 팰린드롬과 매니커 알고리즘 ★

**모든 위치를 중심으로 양옆으로 확장**하면 O(n^2)다. 매니커는 **이미 구한 팰린드롬 정보를 대칭으로 재활용**해 **O(n)**에 각 중심의 반지름을 전부 구한다. 홀짝 길이를 통일하려고 `#`을 끼워 넣는 게 관용구이며, 이때 `p[i]`가 **원본에서의 팰린드롬 길이와 정확히 같아진다.**

```python
def manacher(s):
    """t = #a#b#a# 형태로 변환 후, p[i] = i를 중심으로 한 팰린드롬 반지름."""
    t = '#' + '#'.join(s) + '#'
    n, p, center, right = len(t), [0] * (2 * len(s) + 1), 0, 0
    for i in range(n):
        if i < right:
            p[i] = min(right - i, p[2 * center - i])   # 대칭 위치 값 재활용
        while (i - p[i] - 1 >= 0 and i + p[i] + 1 < n
               and t[i - p[i] - 1] == t[i + p[i] + 1]):
            p[i] += 1                                  # 확장
        if i + p[i] > right:
            center, right = i, i + p[i]
    return p

def longest_palindrome(s):
    if not s: return ''
    p = manacher(s)
    k = max(range(len(p)), key=lambda i: p[i])
    length = p[k]
    return s[(k - length) // 2:][:length]    # 변환 좌표를 원래 좌표로 되돌린다

def brute_longest(s):
    subs = (s[i:j] for i in range(len(s)) for j in range(i + 1, len(s) + 1))
    return max((x for x in subs if x == x[::-1]), key=len, default='')

print(manacher("aba"))                                          # [0,1,0,3,0,1,0]
print(longest_palindrome("babad"), longest_palindrome("cbbd"),
      longest_palindrome("abacdfgdcaba"))                       # bab bb aba

import random
random.seed(3)
for _ in range(300):
    s = ''.join(random.choice('ab') for _ in range(random.randint(1, 18)))
    assert len(longest_palindrome(s)) == len(brute_longest(s))
print("매니커 랜덤 300케이스 통과")
```

## 6. Z 알고리즘과 아호-코라식 개념 ★

`z[i]` = **`s`와 `s[i:]`의 최장 공통 접두사 길이**. KMP의 pi 배열과 정보량이 사실상 같고, **"패턴 + 구분자 + 텍스트"**를 이어 붙여 매칭에 그대로 쓴다.

```python
def z_function(s):
    n, z, l, r = len(s), [0] * len(s), 0, 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])       # 이미 아는 구간 재활용
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    z[0] = n
    return z

def z_search(text, pat):
    """구분자는 text/pat에 절대 안 나오는 문자여야 한다."""
    joined, m = pat + '\x00' + text, len(pat)
    z = z_function(joined)
    return [i - m - 1 for i in range(m + 1, len(joined)) if z[i] >= m]

print(z_function("aabxaab"))                          # [7, 1, 0, 0, 3, 1, 0]
print(z_search("ABABDABACDABABCABAB", "ABABCABAB"))   # [10]
print(z_search("aaaaa", "aa"))                        # [0, 1, 2, 3]
```

**패턴이 k개인데 텍스트를 한 번만 훑고 전부 찾아야 하면 아호-코라식**이다. 한 줄로 말하면 **트라이 + KMP의 실패 함수**다.

1. 모든 패턴을 **트라이**에 넣는다.
2. 각 노드에 **실패 링크**를 단다 — "여기서 불일치가 나면, 지금까지 읽은 접미사 중 트라이에 존재하는 가장 긴 것"으로 점프. KMP의 `pi[j-1]`과 정확히 같은 역할이다.
3. 실패 링크는 **BFS(레벨 순)**로 계산한다. 부모의 링크를 따라가며 같은 글자 자식을 찾으므로 부모가 먼저 확정돼야 한다.
4. **출력 링크**로 "이 노드에서 끝나는 다른 패턴"도 함께 보고한다(`he`와 `she`처럼 한 위치에서 여러 패턴이 동시에 끝날 수 있음).

| 상황 | 선택 |
|---|---|
| 패턴 1개 | KMP 또는 내장 `find` |
| 패턴 여러 개, 길이 같음 | 라빈-카프 (해시 집합 비교) |
| 패턴 여러 개, 길이 제각각 | **아호-코라식** — O(패턴 총길이 + 텍스트 길이 + 매칭 수) |

## 7. 문자열 해싱 — 충돌과 모듈러 선택 ★★

해싱은 **틀릴 수 있는 알고리즘**이다. 다른 문자열이 같은 해시를 갖는 **충돌**을 얼마나 억제하느냐가 전부다.

```python
def poly_hash(s, base, mod):
    h = 0
    for ch in s:
        h = (h * base + ord(ch)) % mod
    return h

def count_collisions(mod):
    seen, c = set(), 0
    for x in range(20000):
        h = poly_hash(str(x), 131, mod)
        if h in seen: c += 1
        seen.add(h)
    return c

print("mod=10007 충돌:", count_collisions(10007))          # 약 1만 건 — 못 쓴다
print("mod=2^61-1 충돌:", count_collisions((1 << 61) - 1)) # 0 (메르센 소수)

def double_hash(s):                          # 더 안전하게: 모듈러 2개를 묶는다
    return (poly_hash(s, 131, (1 << 61) - 1), poly_hash(s, 137, 998244353))

print(double_hash("hello") == double_hash("hello"),
      double_hash("hello") == double_hash("hellp"))     # True False
```

| 선택 | 권장 값 | 이유 |
|---|---|---|
| base | 문자 집합 크기보다 큰 소수 (31, 131, 137) | 자릿수가 고루 섞이도록 |
| mod | **큰 소수** (10^9+7, 998244353, 2^61-1) | 충돌 확률 ≈ n^2 / (2·mod) |
| 안전도 | 모듈러 2개 조합(더블 해싱) | 충돌 확률이 곱으로 줄어듦 |

> **함정**: 파이썬 내장 `hash()`를 문자열 해싱 알고리즘에 쓰면 안 된다. **실행할 때마다 시드가 바뀌어(PYTHONHASHSEED) 결과가 달라지고**, 값의 범위·분포도 보장되지 않는다. 반드시 base와 mod를 직접 정한 다항식 해시를 쓰고, **해시가 같아도 실제 문자열을 한 번 비교**하는 게 정석이다(라빈-카프 코드의 슬라이스 비교 부분).

---

### 한 줄 요약
문자열 문제는 **단순 포함 여부면 내장 `in`·`find`가 가장 빠르고**, 모든 출현 위치나 **주기·경계 정보가 필요하면 pi 배열(KMP)**, 임의 구간을 O(1)에 비교하려면 **롤링 해시(큰 소수 모듈러 + 실제 비교)**, 접두사 질의·자동완성이면 **트라이**, 다중 패턴이면 **아호-코라식(트라이 + 실패 링크)**으로 갈린다. 그리고 파이썬에서는 무엇보다 **`s += x` 대신 `''.join(list)`** — 이 한 가지가 시간 초과의 가장 흔한 원인이다.
