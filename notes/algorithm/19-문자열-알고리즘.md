## 1. 파이썬 문자열 기초 — 불변성이 성능을 지배한다 ★★

파이썬 문자열은 **불변(immutable)**이다. `s += x`는 기존 문자열을 수정하는 게 아니라 **매번 새 문자열을 통째로 복사해 만든다.** 반복문 안에서 이걸 하면 O(n^2)가 된다.

```python
import time

n = 60000

t = time.perf_counter()
s = ''
for i in range(n):
    s += 'a'                       # 매번 전체 복사 → O(n^2)
slow = time.perf_counter() - t

t = time.perf_counter()
buf = []
for i in range(n):
    buf.append('a')                # 리스트에 모았다가
s2 = ''.join(buf)                  # 마지막에 한 번만 합친다 → O(n)
fast = time.perf_counter() - t

print(s == s2, f"+= {slow:.4f}s / join {fast:.4f}s")

# 자주 쓰는 관용구
print('-'.join(['a', 'b', 'c']))        # a-b-c
print(list("abc"))                      # ['a', 'b', 'c']
print("abcabc".find("ca"), "abcabc".count("bc"))   # 2 2
print("Hello"[::-1])                    # olleH  (슬라이스 뒤집기)
print(ord('a'), chr(98))                # 97 b
print([ord(c) - ord('a') for c in "cab"])   # [2, 0, 1]  알파벳 인덱싱
```

**출력도 마찬가지다.** 수만 줄을 `print()`로 하나씩 찍으면 I/O에서 시간 초과가 난다.

```python
import sys
lines = [str(i) for i in range(5)]
sys.stdout.write('\n'.join(lines) + '\n')   # 한 번에 flush
```

> **함정**: `in` 연산자(`if pat in text`)와 `str.find`는 CPython 내부에서 **Crochemore-Perrin 기반의 빠른 알고리즘**을 쓰기 때문에 실무 입력에서는 직접 짠 KMP보다 훨씬 빠르다. **단순히 "포함 여부"나 "첫 위치"만 필요하면 내장 기능을 쓰는 게 정답**이다. KMP를 직접 짜는 이유는 **모든 출현 위치, 실패 함수(pi 배열) 자체, 문자열 주기·경계(border) 정보**가 필요하기 때문이다.

## 2. KMP — 실패 함수로 되돌아가기 ★★★

단순 비교는 불일치가 나면 텍스트 포인터를 **되돌린다**(O(nm)). KMP는 **텍스트 포인터를 절대 되돌리지 않고**, 대신 패턴 포인터만 앞으로 당겨 **O(n + m)**을 만든다.

### pi 배열(실패 함수)의 정의

`pi[i]` = **`p[0..i]`의 접두사이면서 동시에 접미사인 가장 긴 문자열의 길이** (자기 자신 제외).

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| p | a | b | a | b | a | c | a |
| pi | 0 | 0 | 1 | 2 | 3 | 0 | 1 |

`pi[4] = 3`은 `"ababa"`의 접두사 `"aba"`가 접미사이기도 하다는 뜻이다. 그래서 5번째에서 불일치가 나도 **앞의 3글자는 이미 맞춰진 상태**라 처음부터 다시 볼 필요가 없다.

```python
def build_pi(p):
    """실패 함수. 패턴을 자기 자신과 매칭시키는 것과 같다."""
    m = len(p)
    pi = [0] * m
    j = 0                                  # 현재까지 일치한 접두사 길이
    for i in range(1, m):
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]                  # 불일치 → 더 짧은 경계로 후퇴
        if p[i] == p[j]:
            j += 1
            pi[i] = j
    return pi


def kmp_search(text, pat):
    """pat이 text에 나타나는 모든 시작 인덱스."""
    if not pat:
        return []
    pi = build_pi(pat)
    m = len(pat)
    result, j = [], 0
    for i, ch in enumerate(text):
        while j > 0 and ch != pat[j]:
            j = pi[j - 1]                  # 텍스트 포인터 i는 절대 안 돌아간다
        if ch == pat[j]:
            j += 1
            if j == m:                     # 완전 일치
                result.append(i - m + 1)
                j = pi[j - 1]              # 겹치는 다음 후보로 이어간다
    return result


print(build_pi("ababaca"))                 # [0, 0, 1, 2, 3, 0, 1]
print(build_pi("aaaa"))                    # [0, 1, 2, 3]
print(kmp_search("ABABDABACDABABCABAB", "ABABCABAB"))   # [10]
print(kmp_search("aaaaa", "aa"))           # [0, 1, 2, 3]  (겹치는 매칭도 잡는다)
print(kmp_search("abcabcabc", "abcabc"))   # [0, 3]

# 무작위 검증: 내장 find 를 반복해 얻은 결과와 일치해야 한다
import random
random.seed(7)
for _ in range(300):
    t = ''.join(random.choice('ab') for _ in range(random.randint(1, 30)))
    p = ''.join(random.choice('ab') for _ in range(random.randint(1, 4)))
    expect, start = [], 0
    while True:
        k = t.find(p, start)
        if k < 0:
            break
        expect.append(k)
        start = k + 1
    assert kmp_search(t, p) == expect
print("KMP 랜덤 300케이스 통과")
```

> ★★★ **핵심**: pi 배열은 매칭 말고도 그 자체로 강력한 정보다. **문자열 `s`의 최소 주기는 `len(s) - pi[-1]`**이다(단, `len(s) % (len(s) - pi[-1]) == 0`일 때만 실제로 반복 구조). "이 문자열이 어떤 부분 문자열의 반복인가", "접두사이자 접미사인 것을 모두 구하라" 같은 유형이 전부 pi 배열 하나로 풀린다.

```python
def build_pi(p):
    m = len(p)
    pi = [0] * m
    j = 0
    for i in range(1, m):
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]
        if p[i] == p[j]:
            j += 1
            pi[i] = j
    return pi


def min_period(s):
    """s가 완전한 반복 구조일 때의 최소 주기 길이."""
    pi = build_pi(s)
    cand = len(s) - pi[-1]
    return cand if len(s) % cand == 0 else len(s)

print(min_period("abcabcabc"))    # 3
print(min_period("aaaa"))         # 1
print(min_period("abcd"))         # 4
print(min_period("abcabca"))      # 7  (완전한 반복이 아님)
```

## 3. 라빈-카프 — 롤링 해시 ★★

패턴과 텍스트 창(window)을 **숫자 하나로 바꿔 비교**한다. 창을 한 칸 옮길 때 해시를 **O(1)에 갱신**하는 게 롤링 해시다.

```
H(s) = s[0]*B^(m-1) + s[1]*B^(m-2) + ... + s[m-1]   (mod M)
한 칸 이동:  H = (H - s[i-m]*B^m) * ... 형태로 앞을 빼고 뒤를 더한다
```

```python
def rabin_karp(text, pat, base=131, mod=(1 << 61) - 1):
    n, m = len(text), len(pat)
    if m == 0 or m > n:
        return []

    ph = 0
    for ch in pat:
        ph = (ph * base + ord(ch)) % mod
    pw = pow(base, m, mod)                 # base^m (모듈러 거듭제곱)

    h, result = 0, []
    for i, ch in enumerate(text):
        h = (h * base + ord(ch)) % mod     # 뒤 글자 편입
        if i >= m:
            h = (h - ord(text[i - m]) * pw) % mod   # 앞 글자 이탈
        if i >= m - 1 and h == ph:
            if text[i - m + 1:i + 1] == pat:        # ★ 해시 일치 후 실제 비교
                result.append(i - m + 1)
    return result


print(rabin_karp("ABABDABACDABABCABAB", "ABABCABAB"))   # [10]
print(rabin_karp("aaaaa", "aa"))                        # [0, 1, 2, 3]
print(rabin_karp("hello world", "o w"))                 # [4]

def all_occurrences(t, p):
    """검증용 기준 구현 (내장 find 반복)"""
    out, start = [], 0
    while True:
        k = t.find(p, start)
        if k < 0:
            return out
        out.append(k)
        start = k + 1

import random
random.seed(11)
for _ in range(300):
    t = ''.join(random.choice('abc') for _ in range(random.randint(1, 40)))
    p = ''.join(random.choice('abc') for _ in range(random.randint(1, 5)))
    assert rabin_karp(t, p) == all_occurrences(t, p)
print("라빈-카프 랜덤 300케이스 통과")
```

| 기준 | KMP | 라빈-카프 |
|---|---|---|
| 최악 복잡도 | **O(n + m) 보장** | O(nm) (해시 충돌 시) |
| 평균 복잡도 | O(n + m) | O(n + m) |
| 다중 패턴 | 패턴마다 따로 | **길이가 같으면 집합 비교로 한 번에** |
| 2차원 매칭 | 어려움 | **행 해시 → 열 해시로 확장 쉬움** |
| 부분 문자열 비교 | 불가 | **임의 구간 해시로 O(1) 비교 가능** |

**라빈-카프의 진짜 가치는 "임의의 두 부분 문자열이 같은지 O(1)에 판정"**하는 데 있다. 접두사 해시 배열을 만들어 두면 `hash(s[l..r])`을 상수 시간에 뽑을 수 있어서, 이분탐색과 결합해 "가장 긴 공통 접두사" 같은 문제를 로그 시간에 푼다.

## 4. 트라이 (Trie) — 접두사 트리 ★★★

문자열 집합을 **글자 단위 트리**로 저장한다. 길이 L인 문자열의 삽입·검색이 **저장된 단어 수와 무관하게 O(L)**이다. 접두사 질의에 특히 강하다.

```python
class Trie:
    """dict 기반 트라이. 노드 = dict, 단어 끝은 특수 키로 표시."""
    END = '$'

    def __init__(self):
        self.root = {}

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})    # 없으면 만들고 내려간다
        node[self.END] = node.get(self.END, 0) + 1   # 같은 단어 중복 카운트

    def _walk(self, s):
        node = self.root
        for ch in s:
            if ch not in node:
                return None
            node = node[ch]
        return node

    def search(self, word):
        """정확히 이 단어가 있는가"""
        node = self._walk(word)
        return node is not None and self.END in node

    def starts_with(self, prefix):
        """이 접두사로 시작하는 단어가 있는가"""
        return self._walk(prefix) is not None

    def count_with_prefix(self, prefix):
        """이 접두사로 시작하는 단어 개수 (서브트리의 END 합)"""
        node = self._walk(prefix)
        if node is None:
            return 0
        total, stack = 0, [node]
        while stack:
            cur = stack.pop()
            for k, v in cur.items():
                if k == self.END:
                    total += v
                else:
                    stack.append(v)
        return total

    def longest_prefix_of(self, s):
        """s의 접두사 중 트라이에 저장된 가장 긴 것 (라우팅·사전 매칭용)"""
        node, best = self.root, ''
        for i, ch in enumerate(s):
            if ch not in node:
                break
            node = node[ch]
            if self.END in node:
                best = s[:i + 1]
        return best


t = Trie()
for w in ["apple", "app", "application", "apply", "banana", "app"]:
    t.insert(w)

print(t.search("app"), t.search("appl"))            # True False
print(t.starts_with("appl"), t.starts_with("bx"))   # True False
print(t.count_with_prefix("app"))                   # 5  (app 2회 + apple + application + apply)
print(t.count_with_prefix("ban"))                   # 1
print(t.longest_prefix_of("applesauce"))            # apple
print(t.longest_prefix_of("ap"))                    # (빈 문자열)
```

> ★★★ **핵심**: 트라이의 진짜 용도는 **"단어가 있냐"가 아니다**(그건 `set`이 더 빠르고 가볍다). 트라이를 쓰는 이유는 **접두사 기반 질의** — 자동완성, 접두사 개수 세기, **주어진 문자열의 접두사 중 사전에 있는 가장 긴 것 찾기**, 그리고 **XOR 최대값(이진 트라이)** 같은 문제 때문이다.

> **함정**: 파이썬 dict 노드는 **노드 하나당 수백 바이트**를 먹는다. 단어 총 길이가 10^6을 넘으면 메모리 초과 위험이 크다. 이럴 땐 알파벳이 26종으로 고정된 경우 **리스트 기반 노드 배열**(`children = [[-1]*26]` 형태로 인덱스를 관리)로 바꾸거나, 정렬 + 이분탐색으로 우회한다.

## 5. 팰린드롬과 매니커 알고리즘 ★

**모든 위치를 중심으로 양옆으로 확장**하면 O(n^2)다. 매니커는 **이미 구한 팰린드롬 정보를 대칭으로 재활용**해 **O(n)**에 "각 중심의 팰린드롬 반지름"을 전부 구한다. 홀짝 길이를 통일하려고 `#`을 끼워 넣는 게 관용구다.

```python
def manacher(s):
    """t = #a#b#a# 형태로 변환 후, p[i] = i를 중심으로 한 팰린드롬 반지름."""
    t = '#' + '#'.join(s) + '#'
    n = len(t)
    p = [0] * n
    center = right = 0
    for i in range(n):
        if i < right:
            p[i] = min(right - i, p[2 * center - i])   # 대칭 위치 값 재활용
        while (i - p[i] - 1 >= 0 and i + p[i] + 1 < n
               and t[i - p[i] - 1] == t[i + p[i] + 1]):
            p[i] += 1                                  # 확장
        if i + p[i] > right:
            center, right = i, i + p[i]
    return p


def longest_palindrome(s):
    if not s:
        return ''
    p = manacher(s)
    k = max(range(len(p)), key=lambda i: p[i])
    length = p[k]
    start = (k - length) // 2          # 변환된 좌표를 원래 좌표로 되돌린다
    return s[start:start + length]


def brute_longest(s):
    best = ''
    for i in range(len(s)):
        for j in range(i, len(s)):
            sub = s[i:j + 1]
            if sub == sub[::-1] and len(sub) > len(best):
                best = sub
    return best


print(manacher("aba"))                 # [0, 1, 0, 3, 0, 1, 0]
print(longest_palindrome("babad"))     # bab
print(longest_palindrome("cbbd"))      # bb
print(longest_palindrome("abacdfgdcaba"))   # aba

import random
random.seed(3)
for _ in range(300):
    s = ''.join(random.choice('ab') for _ in range(random.randint(1, 18)))
    assert len(longest_palindrome(s)) == len(brute_longest(s))
print("매니커 랜덤 300케이스 통과")
```

`p[i]`는 **변환 문자열에서의 반지름이자 원본에서의 팰린드롬 길이**와 정확히 같다는 점이 이 구현의 편리한 성질이다.

## 6. Z 알고리즘 ★

`z[i]` = **`s`와 `s[i:]`의 최장 공통 접두사 길이**. KMP의 pi 배열과 정보량이 사실상 같고, **"패턴 + 구분자 + 텍스트"**를 이어 붙여 매칭에 그대로 쓴다.

```python
def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i < r:
            z[i] = min(r - i, z[i - l])   # 이미 아는 구간 재활용
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] > r:
            l, r = i, i + z[i]
    z[0] = n
    return z


def z_search(text, pat):
    """구분자는 text/pat에 절대 안 나오는 문자여야 한다."""
    joined = pat + '\x00' + text
    z = z_function(joined)
    m = len(pat)
    return [i - m - 1 for i in range(m + 1, len(joined)) if z[i] >= m]


print(z_function("aabxaab"))                # [7, 1, 0, 0, 3, 1, 0]
print(z_search("ABABDABACDABABCABAB", "ABABCABAB"))   # [10]
print(z_search("aaaaa", "aa"))                        # [0, 1, 2, 3]
```

| 기법 | 배열 의미 | 강점 |
|---|---|---|
| KMP (pi) | 접두사 = 접미사 최장 길이 | **주기·경계(border) 분석**, 온라인 처리 |
| Z | `s`와 `s[i:]`의 최장 공통 접두사 | **구현이 짧고 직관적**, 접두사 비교 질의 |

## 7. 아호-코라식 — 다중 패턴 매칭 ★

**"패턴이 k개인데 텍스트를 한 번만 훑고 전부 찾아라"**가 요구되면 아호-코라식이다. 한 줄로 말하면 **트라이 + KMP의 실패 함수**다.

1. 모든 패턴을 **트라이**에 넣는다.
2. 각 노드에 **실패 링크(failure link)**를 단다 — "여기서 불일치가 나면, 지금까지 읽은 접미사 중 트라이에 존재하는 가장 긴 것"으로 점프. KMP의 `pi[j-1]`과 정확히 같은 역할이다.
3. 실패 링크는 **BFS(레벨 순)**로 계산한다. 부모의 실패 링크를 따라가며 같은 글자 자식을 찾는 방식이라, 부모가 먼저 확정돼야 하기 때문이다.
4. **출력 링크(output link)**로 "이 노드에서 끝나는 다른 패턴"을 함께 보고한다(`he`와 `she`처럼 한 위치에서 여러 패턴이 동시에 끝날 수 있음).

전체 복잡도는 **O(전체 패턴 길이 + 텍스트 길이 + 매칭 개수)**. 텍스트를 한 글자씩 읽으며 **되돌아가지 않는다**는 점이 KMP와 똑같다.

| 상황 | 선택 |
|---|---|
| 패턴 1개 | KMP 또는 내장 `find` |
| 패턴 여러 개, 길이 같음 | 라빈-카프 (해시 집합 비교) |
| 패턴 여러 개, 길이 제각각 | **아호-코라식** |
| 텍스트가 고정, 질의가 여러 번 | 접미사 배열 / 접미사 자동자 |

## 8. 문자열 해싱 — 충돌과 모듈러 선택 ★★

해싱은 **틀릴 수 있는 알고리즘**이다. 다른 문자열이 같은 해시를 갖는 **충돌**을 얼마나 억제하느냐가 전부다.

```python
def poly_hash(s, base, mod):
    h = 0
    for ch in s:
        h = (h * base + ord(ch)) % mod
    return h

# 나쁜 모듈러: 작으면 생일 문제로 금방 충돌한다
bad_mod = 10007
seen = {}
collisions = 0
for x in range(20000):
    s = str(x)
    h = poly_hash(s, 131, bad_mod)
    if h in seen and seen[h] != s:
        collisions += 1
    seen[h] = s
print("mod=10007 충돌 수:", collisions)      # 약 1만 건 — 사실상 못 쓴다

# 좋은 모듈러: 큰 소수 (2^61 - 1 은 메르센 소수)
good_mod = (1 << 61) - 1
seen2, c2 = set(), 0
for x in range(20000):
    h = poly_hash(str(x), 131, good_mod)
    if h in seen2:
        c2 += 1
    seen2.add(h)
print("mod=2^61-1 충돌 수:", c2)             # 0

# 더 안전하게: 서로 다른 모듈러 2개를 묶는다 (더블 해싱)
def double_hash(s):
    return (poly_hash(s, 131, (1 << 61) - 1),
            poly_hash(s, 137, 998244353))

print(double_hash("hello") == double_hash("hello"))    # True
print(double_hash("hello") == double_hash("hellp"))    # False
```

| 선택 | 권장 값 | 이유 |
|---|---|---|
| base | 문자 집합 크기보다 큰 소수 (31, 131, 137, 1000003) | 자릿수가 섞이도록 |
| mod | **큰 소수** (10^9+7, 998244353, 2^61-1) | 충돌 확률 ≈ n^2 / (2·mod) |
| 안전도 | 모듈러 2개 조합(더블 해싱) | 충돌 확률이 곱으로 줄어듦 |

> **함정**: 파이썬의 내장 `hash()`를 문자열 해싱 알고리즘에 쓰면 안 된다. **실행할 때마다 시드가 바뀌어(PYTHONHASHSEED) 결과가 달라지고**, 값의 범위와 분포도 보장되지 않는다. 반드시 위처럼 base와 mod를 직접 정한 다항식 해시를 쓴다. 그리고 **해시가 같아도 반드시 실제 문자열을 한 번 비교**하는 게 정석이다(라빈-카프 코드의 `text[i-m+1:i+1] == pat` 부분).

### 한 줄 요약
문자열 문제는 **단순 포함 여부면 내장 `in`·`find`가 가장 빠르고**, 모든 출현 위치나 **주기·경계 정보가 필요하면 pi 배열(KMP)**, 임의 구간을 O(1)에 비교하려면 **롤링 해시(큰 소수 모듈러 + 실제 비교)**, 접두사 질의·자동완성이면 **트라이**, 다중 패턴이면 **아호-코라식(트라이 + 실패 링크)**으로 갈린다. 그리고 파이썬에서는 무엇보다 **`s += x` 대신 `''.join(list)`** — 이 한 가지가 시간 초과의 가장 흔한 원인이다.
