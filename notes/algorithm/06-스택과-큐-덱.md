# 스택과 큐, 덱 (Stack, Queue, Deque)

> 알고리즘 · 자료구조 · 학습내용: LIFO/FIFO 개념과 파이썬 구현, 큐를 `list`로 만들면 안 되는 이유(`pop(0)` O(n)), `collections.deque`의 양끝 O(1) 연산, 모노톤 스택(Next Greater Element)으로 O(n)에 다음 큰 원소 찾기, 괄호 짝 검사, 후위 표기법 계산, 덱을 이용한 슬라이딩 윈도우 최대·최소

---

## 1. 스택 (Stack) ★★★

**마지막에 넣은 것이 먼저 나온다(LIFO, Last In First Out).** 파이썬에서는 별도 클래스를 만들 필요 없이 **`list`를 그대로 스택으로 쓴다.**

| 연산 | 파이썬 | 시간복잡도 |
|---|---|---|
| push | `stack.append(x)` | 평균 O(1) |
| pop | `stack.pop()` | O(1) |
| top(peek) | `stack[-1]` | O(1) |
| empty | `not stack` | O(1) |
| size | `len(stack)` | O(1) |

```python
stack = []
stack.append(1)          # push
stack.append(2)
print(stack[-1])         # top -> 2 (pop 하지 않고 확인)
print(stack.pop())       # 2
print(stack.pop())       # 1
print(bool(stack))       # False (비어 있음)
```

> **함정**: 빈 리스트에 `pop()`을 하면 `IndexError`가 난다. 문제에서 "비어 있으면 -1을 출력" 같은 요구가 흔하므로 **꺼내기 전에 `if stack:`으로 반드시 확인**한다.

```python
def safe_pop(stack):
    # 비어 있으면 -1, 아니면 top을 꺼내 반환
    return stack.pop() if stack else -1

s = []
print(safe_pop(s))       # -1
s.append(10)
print(safe_pop(s))       # 10
```

`list.append`는 **분할상환(amortized) O(1)**이다. 내부 배열이 꽉 차면 더 큰 배열로 복사하지만, 그 비용을 전체 연산 수로 나누면 상수라 실전에서는 O(1)로 봐도 된다.

## 2. 큐를 list로 만들면 안 되는 이유 ★★★

큐는 **먼저 넣은 것이 먼저 나온다(FIFO)**. `list`로 흉내내면 `append`로 넣고 `pop(0)`으로 뺄 텐데, **`pop(0)`은 뒤의 모든 원소를 한 칸씩 앞으로 당기므로 O(n)이다.**

n개를 넣고 빼면 **O(n²)** 이 되어, n이 10만만 넘어가도 시간 초과가 난다. `insert(0, x)`도 같은 이유로 O(n)이다.

```python
import time
from collections import deque

N = 50000

lst = list(range(N))
t0 = time.perf_counter()
while lst:
    lst.pop(0)               # O(n) -> 전체 O(n^2)
t1 = time.perf_counter()

dq = deque(range(N))
t2 = time.perf_counter()
while dq:
    dq.popleft()             # O(1) -> 전체 O(n)
t3 = time.perf_counter()

print(f"list.pop(0)  : {t1 - t0:.4f}s")
print(f"deque.popleft: {t3 - t2:.4f}s")
print("deque가 더 빠른가?", (t3 - t2) < (t1 - t0))
```

> ★★★ **핵심**: 파이썬에서 **큐가 필요하면 무조건 `collections.deque`**다. BFS, 위상 정렬, 시뮬레이션 문제에서 `list.pop(0)`을 쓰는 순간 시간 초과라고 생각하면 된다.

## 3. collections.deque ★★★

**덱(deque, double-ended queue)은 양쪽 끝에서 삽입·삭제가 모두 O(1)**인 자료구조다. 내부적으로 이중 연결 리스트 형태의 블록 배열이라 양끝 연산이 상수 시간이다.

| 연산 | 메서드 | 시간복잡도 |
|---|---|---|
| 오른쪽 추가 | `dq.append(x)` | O(1) |
| 왼쪽 추가 | `dq.appendleft(x)` | O(1) |
| 오른쪽 제거 | `dq.pop()` | O(1) |
| 왼쪽 제거 | `dq.popleft()` | O(1) |
| **중간 인덱싱** | `dq[i]` | **O(n)** |
| 회전 | `dq.rotate(k)` | O(k) |
| 최대 길이 제한 | `deque(maxlen=k)` | 넘치면 반대쪽 자동 제거 |

```python
from collections import deque

dq = deque([2, 3])
dq.appendleft(1)             # [1, 2, 3]
dq.append(4)                 # [1, 2, 3, 4]
print(list(dq))

print(dq.popleft(), dq.pop())    # 1 4
print(list(dq))                  # [2, 3]

dq2 = deque([1, 2, 3, 4, 5])
dq2.rotate(2)                # 오른쪽으로 2칸 회전
print(list(dq2))             # [4, 5, 1, 2, 3]
dq2.rotate(-2)               # 되돌리기
print(list(dq2))             # [1, 2, 3, 4, 5]

# maxlen: 최근 3개만 유지하는 윈도우
recent = deque(maxlen=3)
for x in range(6):
    recent.append(x)
print(list(recent))          # [3, 4, 5]
```

> **함정**: 덱은 **랜덤 접근이 O(n)** 이다. `dq[i]`를 반복문 안에서 쓰면 O(n²)가 된다. 인덱스로 마구 접근해야 하면 `list`가 맞다. **양끝만 건드릴 때 덱을 쓴다.**

BFS의 기본형은 항상 이 모양이다.

```python
from collections import deque

graph = {1: [2, 3], 2: [4], 3: [4], 4: []}

def bfs(start):
    visited = {start}
    q = deque([start])
    order = []
    while q:
        cur = q.popleft()        # O(1)
        order.append(cur)
        for nxt in graph[cur]:
            if nxt not in visited:
                visited.add(nxt) # 큐에 넣을 때 방문 처리 (중복 삽입 방지)
                q.append(nxt)
    return order

print(bfs(1))                    # [1, 2, 3, 4]
```

## 4. 모노톤 스택 — 다음 큰 원소 (Monotonic Stack / NGE) ★★★

"각 원소의 **오른쪽에서 처음으로 자기보다 큰 값**을 찾아라"가 대표 유형이다. 이중 반복문이면 O(n²)지만, **스택 안의 값이 항상 감소(또는 증가) 순서를 유지하도록** 관리하면 **O(n)** 에 끝난다.

원리는 이렇다. 스택에는 **아직 답을 못 찾은 인덱스**만 넣는다. 새 값 `arr[i]`가 들어올 때, 스택 top이 가리키는 값보다 크면 **그 값의 답이 바로 `arr[i]`**이므로 꺼내며 답을 채운다. **각 인덱스는 스택에 한 번 들어가고 한 번 나오므로 전체 연산이 2n번**, 즉 O(n)이다.

```python
def next_greater(arr):
    n = len(arr)
    ans = [-1] * n           # 없으면 -1
    stack = []               # 값이 감소하도록 유지되는 '인덱스' 스택
    for i, x in enumerate(arr):
        # top이 가리키는 값보다 현재 값이 크면, 그 원소의 답은 x다
        while stack and arr[stack[-1]] < x:
            ans[stack.pop()] = x
        stack.append(i)
    return ans

print(next_greater([3, 5, 2, 7]))      # [5, 7, 7, -1]
print(next_greater([9, 5, 4, 8]))      # [-1, 8, 8, -1]
print(next_greater([1, 1, 1]))         # [-1, -1, -1]
```

> ★★★ **핵심**: 모노톤 스택은 **"인덱스를 넣고, 조건이 깨질 때 꺼내며 답을 확정한다"**가 전부다. 부등호만 바꾸면 **다음 작은 원소(`>`)**, **이전 큰 원소(뒤에서부터 순회)**로 그대로 응용된다.

응용으로 **히스토그램에서 가장 큰 직사각형** 유형이 있다. 각 막대에 대해 **왼쪽·오른쪽으로 자기보다 낮은 막대가 나오기 전까지의 범위**를 모노톤 스택으로 구한다.

```python
def largest_rectangle(heights):
    stack = []               # 높이가 증가하도록 유지되는 인덱스 스택
    best = 0
    # 끝에 0을 붙여 남은 스택을 강제로 비운다
    for i, h in enumerate(heights + [0]):
        while stack and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            # 스택이 비면 왼쪽 끝까지, 아니면 새 top 다음부터가 폭
            width = i if not stack else i - stack[-1] - 1
            best = max(best, height * width)
        stack.append(i)
    return best

print(largest_rectangle([2, 1, 5, 6, 2, 3]))   # 10
print(largest_rectangle([4, 4, 4]))            # 12
```

## 5. 괄호 짝 검사 (Balanced Parentheses) ★★

**여는 괄호는 스택에 넣고, 닫는 괄호가 오면 top과 짝이 맞는지 본다.** 짝이 안 맞거나 스택이 비어 있으면 실패, 다 돌고 스택이 남아 있어도 실패다.

```python
def is_balanced(s):
    pair = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif ch in pair:
            # 비어 있거나 top이 짝이 아니면 실패
            if not stack or stack.pop() != pair[ch]:
                return False
    return not stack        # 남아 있으면 실패

for t in ["(()[])", "([)]", "(((", "", "{[()]}"]:
    print(repr(t), is_balanced(t))
```

> **함정**: 마지막의 `return not stack`을 빼먹는 실수가 잦다. `"((("` 는 반복문을 무사히 통과하지만 **닫히지 않았으므로 실패**여야 한다.

## 6. 후위 표기법 계산 (Postfix / RPN) ★★

**피연산자는 스택에 쌓고, 연산자가 나오면 두 개를 꺼내 계산해 다시 넣는다.** 꺼내는 순서가 뒤집힌다는 점(**나중에 꺼낸 것이 왼쪽 피연산자**)이 핵심 함정이다.

```python
def eval_postfix(tokens):
    stack = []
    for t in tokens:
        if t in '+-*/':
            b = stack.pop()          # 오른쪽 피연산자가 먼저 나온다
            a = stack.pop()          # 왼쪽 피연산자
            if t == '+':
                stack.append(a + b)
            elif t == '-':
                stack.append(a - b)
            elif t == '*':
                stack.append(a * b)
            else:
                stack.append(a / b)  # 정수 나눗셈이면 int(a / b)
        else:
            stack.append(float(t))
    return stack.pop()

print(eval_postfix("3 4 + 2 *".split()))     # 14.0
print(eval_postfix("5 1 2 + 4 * + 3 -".split()))  # 14.0
```

## 7. 슬라이딩 윈도우 최대·최소를 덱으로 O(n)에 ★★

길이 `k` 윈도우를 한 칸씩 밀며 **각 윈도우의 최댓값**을 구할 때, 매번 `max()`를 쓰면 O(nk)다. **덱에 "앞으로 답이 될 수 있는 후보의 인덱스"만 감소 순서로 남기면 O(n)** 이 된다.

규칙은 두 가지다.
1. **범위를 벗어난 인덱스**(`i - k` 이하)는 **왼쪽에서 제거**한다.
2. 새 값보다 **작거나 같은 뒤쪽 후보는 영영 최댓값이 될 수 없으므로 오른쪽에서 제거**한다.

그러면 **덱의 맨 앞이 항상 현재 윈도우의 최댓값 인덱스**다.

```python
from collections import deque

def sliding_max(arr, k):
    dq = deque()             # 값이 감소하도록 유지되는 인덱스 덱
    res = []
    for i, x in enumerate(arr):
        # 1) 윈도우를 벗어난 인덱스 제거
        while dq and dq[0] <= i - k:
            dq.popleft()
        # 2) 새 값보다 작은 후보는 쓸모없다
        while dq and arr[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        if i >= k - 1:       # 윈도우가 완성된 뒤부터 기록
            res.append(arr[dq[0]])
    return res

print(sliding_max([1, 3, -1, -3, 5, 3, 6, 7], 3))   # [3, 3, 5, 5, 6, 7]
print(sliding_max([5, 4, 3, 2, 1], 2))              # [5, 4, 3, 2]
```

최솟값은 **부등호 방향만 바꾸면(`arr[dq[-1]] >= x`)** 그대로 된다.

```python
from collections import deque

def sliding_min(arr, k):
    dq, res = deque(), []
    for i, x in enumerate(arr):
        while dq and dq[0] <= i - k:
            dq.popleft()
        while dq and arr[dq[-1]] >= x:   # 부등호만 반대
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            res.append(arr[dq[0]])
    return res

print(sliding_min([1, 3, -1, -3, 5, 3, 6, 7], 3))   # [-1, -3, -3, -3, 3, 3]
```

## 8. 정리 — 언제 무엇을 쓰나 ★★

| 상황 | 선택 | 이유 |
|---|---|---|
| LIFO(되돌리기, 괄호, DFS) | `list` | `append`/`pop` 둘 다 O(1) |
| FIFO(BFS, 위상 정렬) | `deque` | `popleft` O(1) |
| 양끝 모두 사용(회전, 요세푸스) | `deque` | 양끝 O(1), `rotate` 지원 |
| 인덱스 접근이 잦음 | `list` | 덱의 `dq[i]`는 O(n) |
| 최근 k개만 유지 | `deque(maxlen=k)` | 넘치면 자동 제거 |
| 우선순위대로 꺼내기 | `heapq` | 덱·스택으로는 불가 |

> **함정**: `queue.Queue`는 **스레드 안전용**이라 락 비용이 붙어 느리다. 코딩테스트에서는 쓰지 말고 `collections.deque`를 쓴다.

---

### 한 줄 요약
파이썬에서 **스택은 `list`(`append`/`pop`), 큐는 반드시 `collections.deque`(`popleft`)** 로 만들며, `list.pop(0)`이 O(n)이라 큐로 쓰면 O(n²)가 되어 시간 초과의 단골 원인이 된다. **모노톤 스택**은 인덱스를 쌓아두었다가 조건이 깨질 때 꺼내며 답을 확정해 "다음 큰 원소"·"히스토그램 최대 직사각형"을 O(n)에 푸는 핵심 패턴이다. 덱은 양끝 O(1)이라는 성질 덕에 **슬라이딩 윈도우 최대·최소도 후보 인덱스를 단조 순서로 관리해 O(n)** 에 구할 수 있다. 대신 덱의 중간 인덱싱은 O(n)이므로, 랜덤 접근이 필요하면 `list`로 돌아가야 한다.
