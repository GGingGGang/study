# 이분 탐색과 투 포인터 (Binary Search & Two Pointers)

> 알고리즘 · 자료구조 · 학습내용: 이분 탐색 원리와 경계 조건(`lo<hi` vs `lo<=hi`), 무한 루프 함정, `bisect_left`/`bisect_right` 차이와 개수 세기, 매개변수 탐색(파라메트릭 서치)으로 "최댓값의 최솟값" 풀기, 실수 이분 탐색, 투 포인터(정렬 배열의 합 찾기·부분합 최소 길이), 고정·가변 슬라이딩 윈도우, 두 기법의 구분 기준

## 1. 이분 탐색의 원리 ★★★

**정렬된 배열**에서 탐색 범위를 **매번 절반으로 줄인다.** n개를 다 보면 O(n)이지만, 절반씩 줄이면 **O(log n)** 이다. n이 10억이어도 약 30번이면 끝난다.

전제 조건이 하나 있다. **탐색 대상이 단조(monotonic)여야 한다.** 정렬된 배열이거나, "어떤 값 이상에서는 항상 참, 미만에서는 항상 거짓" 같은 성질이 있어야 한다.

```python
def binary_search(arr, target):
    """target의 인덱스, 없으면 -1"""
    lo, hi = 0, len(arr) - 1        # 닫힌 구간 [lo, hi]
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1            # 오른쪽 절반
        else:
            hi = mid - 1            # 왼쪽 절반
    return -1

arr = [1, 3, 5, 7, 9, 11]
print(binary_search(arr, 7))    # 3
print(binary_search(arr, 4))    # -1
print(binary_search(arr, 1), binary_search(arr, 11))   # 0 5
```

## 2. 경계 조건 — lo<hi vs lo<=hi ★★★

이분 탐색이 어려운 이유는 알고리즘이 아니라 **경계 처리**다. 두 형태를 **섞어 쓰지 말고 하나를 골라 외우는 것**이 안전하다.

| 형태 | 구간 | 초기값 | 갱신 | 용도 |
|---|---|---|---|---|
| `while lo <= hi` | 닫힌 `[lo, hi]` | `hi = n-1` | `lo=mid+1` / `hi=mid-1` | **값 존재 확인**, 매개변수 탐색 |
| `while lo < hi` | 반열린 `[lo, hi)` | `hi = n` | `lo=mid+1` / `hi=mid` | **경계 위치 찾기**(lower/upper bound) |

```python
def lower_bound(arr, x):
    """x 이상인 첫 인덱스 (없으면 len(arr))"""
    lo, hi = 0, len(arr)            # 반열린 구간 [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid                # mid도 후보이므로 -1 하지 않는다
    return lo

def upper_bound(arr, x):
    """x 초과인 첫 인덱스"""
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:           # <= 하나만 다르다
            lo = mid + 1
        else:
            hi = mid
    return lo

arr = [1, 2, 2, 2, 5]
print(lower_bound(arr, 2), upper_bound(arr, 2))   # 1 4
print(lower_bound(arr, 3), upper_bound(arr, 3))   # 4 4
print(lower_bound(arr, 0), upper_bound(arr, 9))   # 0 5
```

> ★★★ **핵심**: `lo < hi` 형태에서는 **`hi = mid`(-1 없음)**, `lo <= hi` 형태에서는 **`hi = mid - 1`**. 이 조합을 어기면 무한 루프거나 정답을 한 칸 놓친다.

> **함정**: `while lo < hi` 안에서 `hi = mid`를 쓰면서 `lo = mid`(+1 없이)를 쓰면 **무한 루프**다. `lo=3, hi=4`일 때 `mid = (3+4)//2 = 3`이라 `lo`가 영원히 3에 머문다. 반드시 **한쪽은 `mid + 1`** 로 범위를 줄여야 한다.

## 3. bisect 모듈 ★★★

파이썬은 이분 탐색을 표준 라이브러리로 제공한다. **직접 구현할 필요가 없다.**

| 함수 | 의미 |
|---|---|
| `bisect_left(a, x)` | **x 이상**인 첫 위치 (= lower_bound). 같은 값이 있으면 그 **앞** |
| `bisect_right(a, x)` | **x 초과**인 첫 위치 (= upper_bound). 같은 값이 있으면 그 **뒤** |
| `insort_left/right(a, x)` | 정렬을 유지하며 삽입 (**삽입 자체는 O(n)**) |

```python
from bisect import bisect_left, bisect_right, insort

a = [1, 2, 2, 2, 5, 8]
print(bisect_left(a, 2), bisect_right(a, 2))     # 1 4
print(bisect_right(a, 2) - bisect_left(a, 2))    # 3 <- 2의 개수
print(bisect_left(a, 3), bisect_right(a, 3))     # 4 4 (없으면 둘이 같다)

# 값의 존재 여부
def contains(a, x):
    i = bisect_left(a, x)
    return i < len(a) and a[i] == x

print(contains(a, 5), contains(a, 6))            # True False

# 구간 [lo, hi] 안의 원소 개수
def count_range(a, lo, hi):
    return bisect_right(a, hi) - bisect_left(a, lo)

print(count_range(a, 2, 5))                      # 4  (2,2,2,5)

# 정렬 유지 삽입
insort(a, 4)
print(a)                                          # [1, 2, 2, 2, 4, 5, 8]
```

파이썬 3.10+에서는 `key` 인자도 쓸 수 있어, 튜플 리스트에서 특정 필드로 탐색할 수 있다(`bisect_left(rows, 20, key=lambda r: r[1])`).

> **함정**: `insort`는 **탐색만 O(log n)이고 삽입은 O(n)** 이다. 반복 삽입이 많으면 O(n²)가 되니, 그럴 땐 **모아서 정렬**하거나 힙·트리 계열 자료구조를 쓴다.

## 4. 매개변수 탐색 (Parametric Search) ★★★

**"최댓값의 최솟값", "최솟값의 최댓값", "가능한 최대 크기"** 같은 최적화 문제를, **"이 값이 가능한가?"라는 예/아니오 결정 문제**로 바꿔 이분 탐색하는 기법이다.

성립 조건은 **단조성**이다. 예를 들어 **"길이 L로 자를 수 있다"** 가 참이면 **L보다 짧은 모든 길이도 참**이어야 한다. 이 성질이 있으면 참/거짓의 **경계**를 이분 탐색으로 찾을 수 있다.

**답 자체를 이분 탐색한다**는 발상이 핵심이다. 배열이 아니라 **정답 후보의 범위**를 반씩 줄인다. 아래 두 예제의 **`parametric_max`(가능한 최댓값) / `parametric_min`(가능한 최솟값)이 그대로 외워 쓰는 템플릿**이고, 문제마다 바뀌는 것은 **판정 함수 `ok`와 탐색 범위**뿐이다.

**유형 1 — "K개 이상 만들 수 있는 최대 길이"**. 길이 L로 잘랐을 때 조각 수는 L이 커질수록 줄어드니 단조다.

```python
def parametric_max(lo, hi, ok):
    """ok(x)가 참인 x의 최댓값 (작은 값에서 참, 커지면 거짓)"""
    best = lo - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return best

def max_cut_length(lengths, k):
    def ok(L):
        if L == 0:
            return True
        return sum(x // L for x in lengths) >= k   # L 길이로 k개 이상 나오나
    return parametric_max(1, max(lengths), ok)

print(max_cut_length([802, 743, 457, 539], 11))    # 200
print(max_cut_length([10, 10], 4))                 # 5
```

**유형 2 — "그룹 합의 최댓값을 최소화"**. 대표적인 "최댓값의 최솟값" 문제다. 허용 용량이 클수록 필요한 그룹 수가 줄어드니 단조다.

```python
def parametric_min(lo, hi, ok):
    """ok(x)가 참인 x의 최솟값 (큰 값에서 참, 작아지면 거짓)"""
    best = hi + 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            best = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return best

def min_max_group_sum(arr, m):
    """배열을 연속된 m개 구간으로 나눌 때, 구간 합 최댓값의 최솟값"""
    def ok(cap):
        groups, cur = 1, 0
        for x in arr:
            if cur + x > cap:      # 넘치면 새 그룹 시작
                groups += 1
                cur = 0
            cur += x
        return groups <= m
    # 하한은 원소 최댓값(한 원소는 반드시 담겨야), 상한은 전체 합
    return parametric_min(max(arr), sum(arr), ok)

print(min_max_group_sum([1, 2, 3, 4, 5], 2))       # 9
print(min_max_group_sum([7, 2, 5, 10, 8], 2))      # 18
print(min_max_group_sum([1, 1, 1, 1], 4))          # 1
```

> ★★★ **핵심**: 매개변수 탐색은 **"최적값을 직접 구하려 하지 말고, 후보 값을 찍고 검증하라"**가 전부다. 문제에서 **"최대의 최소" / "최소의 최대"** 라는 표현이 보이면 거의 확정이다. 검증 함수 `ok`는 대개 **그리디 O(n)** 이므로 전체는 **O(n log(범위))** 다.

> **함정**: 탐색 범위의 하한·상한을 잘못 잡으면 답이 범위 밖으로 나간다. **하한은 "확실히 가능한 최소", 상한은 "확실히 가능한 최대"** 로 넉넉히 잡는다. 위 예에서 하한을 `1`로 잡으면 원소 하나조차 못 담는 경우가 생겨 무한히 그룹이 늘어난다.

## 5. 실수 이분 탐색 ★★

실수는 `lo == hi`가 되는 순간이 오지 않을 수 있다. **`while hi - lo > eps`는 부동소수점 오차로 안 끝날 위험**이 있으므로, **반복 횟수를 고정**하는 방식이 안전하다. **100번이면 구간이 2⁻¹⁰⁰배로 줄어** 어떤 정밀도든 충분하다.

```python
def sqrt_binary(x):
    lo, hi = 0.0, max(1.0, x)
    for _ in range(100):        # 횟수 고정 -> 무한 루프 없음
        mid = (lo + hi) / 2
        if mid * mid < x:
            lo = mid
        else:
            hi = mid
    return hi

print(f"{sqrt_binary(2):.10f}")     # 1.4142135624
print(f"{sqrt_binary(9):.10f}")     # 3.0000000000
print(round(sqrt_binary(0.25), 10)) # 0.5
```

> **함정**: 실수 이분 탐색에서 `lo = mid + 1` 같은 정수식 갱신을 쓰면 안 된다. **실수는 `lo = mid`, `hi = mid`** 로 갱신한다(구간이 반씩 줄어드는 것이 보장되므로 무한 루프가 아니다).

## 6. 투 포인터 (Two Pointers) ★★★

**두 개의 인덱스를 서로 다른 규칙으로 움직여 O(n)** 에 푸는 기법이다. 이중 반복문 O(n²)를 대체한다.

**유형 A — 정렬된 배열에서 합이 target인 쌍.** 양끝에서 좁혀 온다. 합이 작으면 왼쪽을 올리고, 크면 오른쪽을 내린다.

```python
def two_sum_sorted(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo < hi:
        s = arr[lo] + arr[hi]
        if s == target:
            return (arr[lo], arr[hi])
        elif s < target:
            lo += 1        # 더 큰 값이 필요
        else:
            hi -= 1        # 더 작은 값이 필요
    return None

a = [1, 3, 4, 6, 8, 10]
print(two_sum_sorted(a, 14))   # (4, 10)
print(two_sum_sorted(a, 100))  # None
```

**유형 B — 합이 S 이상인 최소 길이 구간.** 오른쪽 포인터로 늘리고, 조건을 만족하면 왼쪽 포인터로 줄인다. **양수 배열**에서만 성립한다(합이 단조적으로 변해야 한다).

```python
def min_len_subarray(arr, S):
    """합이 S 이상인 가장 짧은 연속 구간의 길이 (없으면 0)"""
    lo, cur, best = 0, 0, len(arr) + 1
    for hi, x in enumerate(arr):
        cur += x
        while cur >= S:                  # 조건 만족 -> 왼쪽을 당겨 최소화
            best = min(best, hi - lo + 1)
            cur -= arr[lo]
            lo += 1
    return 0 if best > len(arr) else best

print(min_len_subarray([2, 3, 1, 2, 4, 3], 7))    # 2  ([4,3])
print(min_len_subarray([1, 1, 1], 10))            # 0
```

> **함정**: 투 포인터로 부분합을 다룰 땐 **음수가 있으면 안 된다.** 음수가 섞이면 오른쪽을 늘려도 합이 줄 수 있어 단조성이 깨진다. 그럴 땐 **누적합 + 해시**나 다른 기법으로 간다.

## 7. 슬라이딩 윈도우 (Sliding Window) ★★

투 포인터의 특수한 형태로, **구간(윈도우)이 항상 연속**이라는 점이 특징이다.

**고정 길이**: 윈도우 크기가 k로 고정. **하나 넣고 하나 빼면** 매번 다시 합을 구할 필요가 없다.

```python
def max_sum_fixed(arr, k):
    cur = sum(arr[:k])
    best = cur
    for i in range(k, len(arr)):
        cur += arr[i] - arr[i - k]      # 들어온 값 더하고 나간 값 뺀다 O(1)
        best = max(best, cur)
    return best

print(max_sum_fixed([1, 4, 2, 10, 2, 3, 1, 0, 20], 4))   # 24
print(max_sum_fixed([5, 5, 5], 2))                       # 10
```

**가변 길이**: 조건이 깨지면 왼쪽을 당겨 조건을 회복한다. "중복 없는 가장 긴 부분 문자열"이 대표 예다.

```python
def longest_unique(s):
    last = {}                 # 문자 -> 마지막 등장 인덱스
    lo, best = 0, 0
    for hi, ch in enumerate(s):
        if ch in last and last[ch] >= lo:
            lo = last[ch] + 1     # 중복이 생기면 왼쪽 경계를 그 다음으로
        last[ch] = hi
        best = max(best, hi - lo + 1)
    return best

print(longest_unique("abcabcbb"))    # 3
print(longest_unique("bbbbb"))       # 1
print(longest_unique("pwwkew"))      # 3
print(longest_unique(""))            # 0
```

**"서로 다른 원소가 K개 이하인 최장 구간"** 도 같은 골격이다. `Counter`로 종류 수를 세면서 `len(cnt) > k`인 동안 왼쪽을 당기면 된다.

> **함정**: 카운터를 줄일 때 **개수가 0이 된 키를 `del`로 지우지 않으면** `len(cnt)`가 실제 종류 수보다 커져 오답이 난다.

## 8. 언제 무엇을 쓰나 ★★

| 신호 | 기법 |
|---|---|
| 정렬된 배열에서 **특정 값/위치** 찾기 | 이분 탐색, `bisect` |
| **"최대의 최소" / "최소의 최대"** | 매개변수 탐색 |
| "이 값이 가능한가?"를 O(n)에 판정 가능 | 매개변수 탐색 |
| 정렬된 배열에서 **두 원소의 합** | 투 포인터(양끝) |
| **연속 구간**의 합·개수·길이 | 슬라이딩 윈도우(같은 방향 투 포인터) |
| 윈도우 크기가 **고정** | 고정 슬라이딩 윈도우 |
| 조건을 만족하는 **가장 짧은/긴 구간** | 가변 슬라이딩 윈도우 |
| 값 범위가 크지만 **단조성** 존재 | 이분 탐색(범위를 탐색) |

구분 기준은 간단하다. **이분 탐색은 "답의 후보 공간"을 반씩 줄이고, 투 포인터는 "배열 위의 두 인덱스"를 한 방향으로 한 번씩만 움직인다.** 투 포인터는 각 포인터가 최대 n번 이동하므로 **전체 O(n)** 이다.

---

### 한 줄 요약
이분 탐색의 실전 난이도는 알고리즘이 아니라 **경계 조건**에 있으므로, `lo<=hi`(닫힌 구간, `hi=mid-1`)와 `lo<hi`(반열린 구간, `hi=mid`) 중 **하나를 골라 일관되게** 쓰고, 위치 탐색은 아예 `bisect_left`/`bisect_right`에 맡기는 게 안전하다. **매개변수 탐색**은 "최대의 최소" 유형을 **"이 값이 가능한가"라는 결정 문제**로 바꿔 O(n log(범위))에 푸는 핵심 무기이며, 단조성과 탐색 범위의 하한·상한 설정이 관건이다. 실수 이분 탐색은 `eps` 비교 대신 **반복 횟수를 100회로 고정**하면 무한 루프를 피할 수 있다. 투 포인터와 슬라이딩 윈도우는 두 인덱스가 되돌아가지 않아 **O(n)** 이지만, 부분합 문제에서는 **음수가 없어야** 단조성이 성립한다는 전제를 반드시 확인해야 한다.
