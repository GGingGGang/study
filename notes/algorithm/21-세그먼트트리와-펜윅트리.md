# 세그먼트 트리와 펜윅 트리 (Segment Tree & Fenwick Tree)

> 알고리즘 · 심화 · 학습내용: 누적 합의 한계와 구간 질의·점 갱신을 모두 O(log n)에 처리하는 이유, 세그먼트 트리 배열 크기 4N의 근거와 구간 합·최솟값 구현(빌드/질의/갱신), 재귀 구현 vs 반복(iterative) 구현, Lazy Propagation으로 구간 갱신까지 O(log n)에 처리하기, 펜윅 트리(BIT)의 구조와 `i & -i`의 의미, 세그먼트 트리 vs 펜윅 비교표, 역순 쌍 개수 세기 같은 응용, 파이썬에서 재귀가 느린 문제와 회피법

---

## 1. 왜 필요한가 — 누적 합의 한계 ★★★

배열에서 "구간 [l, r]의 합"을 여러 번 물어보는 문제는 **누적 합(prefix sum)** 으로 O(1)에 답한다.

```python
arr = [3, 1, 4, 1, 5, 9, 2, 6]
pre = [0] * (len(arr) + 1)
for i, v in enumerate(arr):
    pre[i + 1] = pre[i] + v

print(pre[5 + 1] - pre[2])   # [2,5] 구간 합 = 4+1+5+9 = 19, 질의는 O(1)
```

문제는 **갱신**이다. `arr[3] = 100`으로 바꾸면 `pre[4]`부터 끝까지 다시 계산해야 하므로 **갱신이 O(n)** 이다. N과 Q가 10만이면 100억 연산으로 터진다.

| 방식 | 구간 질의 | 점 갱신 | 언제 쓰나 |
|---|---|---|---|
| 누적 합 | O(1) | **O(n)** | 갱신이 아예 없을 때 |
| **세그먼트 트리 / 펜윅** | **O(log n)** | **O(log n)** | 질의와 갱신이 섞여 나올 때 |

> ★★★ **핵심**: 세그먼트 트리는 "구간 질의와 갱신이 **둘 다** 자주 일어나는" 상황을 위한 자료구조다. 갱신이 없으면 누적 합이 더 빠르고 짧다. 갱신이 있는 순간 누적 합은 무너진다.

## 2. 세그먼트 트리 구조 — 왜 배열 크기가 4N인가 ★★★

배열 구간을 **반씩 쪼개 이진 트리**로 만든다. 루트는 전체 구간 [0, n-1], 자식은 왼쪽/오른쪽 절반, 리프는 원소 하나다. 루트를 1번으로 두면 **노드 `k`의 자식은 `2k`, `2k+1`** 이고, 리프가 n개인 트리의 높이는 `ceil(log2 n)`이다.

**정확히 필요한 크기는 `2 × 2^ceil(log2 n)`** 이다(n=9면 32). n이 2의 거듭제곱보다 1 클 때 이 값이 거의 4n까지 부풀기 때문에, **계산이 귀찮으면 그냥 `4 * n`으로 잡는 게 관례**다.

> **함정**: `2 * n`이나 `2 * n + 1`로 잡으면 n이 2의 거듭제곱이 아닐 때 `IndexError`가 난다. 재귀 구현에서는 반드시 **4N**을 쓴다. (2N으로 충분한 건 아래 4번의 **반복 구현**뿐이다.)

## 3. 세그먼트 트리 구현 — 빌드 / 질의 / 갱신 ★★★

**병합 연산(`merge`)과 항등원(`ident`)만 갈아끼우면** 구간 합·최솟값·최댓값·GCD가 전부 같은 코드로 굴러간다.

```python
class SegTree:
    def __init__(self, arr, merge=lambda a, b: a + b, ident=0):
        self.n = len(arr)
        self.merge = merge          # 두 자식을 합치는 연산
        self.ident = ident          # 구간을 벗어났을 때 돌려줄 "아무 영향 없는 값"
        self.tree = [ident] * (4 * self.n)     # 재귀 구현은 4N 필수
        self._build(arr, 1, 0, self.n - 1)

    def _build(self, arr, node, s, e):
        if s == e:                             # 리프: 원소 하나
            self.tree[node] = arr[s]
            return self.tree[node]
        m = (s + e) // 2
        self.tree[node] = self.merge(self._build(arr, node * 2, s, m),
                                     self._build(arr, node * 2 + 1, m + 1, e))
        return self.tree[node]

    def query(self, l, r):                     # 0-based 폐구간 [l, r]
        return self._query(1, 0, self.n - 1, l, r)

    def _query(self, node, s, e, l, r):
        if r < s or e < l:                     # (1) 완전히 벗어남 → 항등원
            return self.ident
        if l <= s and e <= r:                  # (2) 완전히 포함됨 → 저장값 그대로
            return self.tree[node]
        m = (s + e) // 2                       # (3) 걸침 → 양쪽 내려가 합친다
        return self.merge(self._query(node * 2, s, m, l, r),
                          self._query(node * 2 + 1, m + 1, e, l, r))

    def update(self, idx, val):                # idx 위치를 val로 교체
        self._update(1, 0, self.n - 1, idx, val)

    def _update(self, node, s, e, idx, val):
        if s == e:
            self.tree[node] = val
            return
        m = (s + e) // 2
        if idx <= m:
            self._update(node * 2, s, m, idx, val)
        else:
            self._update(node * 2 + 1, m + 1, e, idx, val)
        self.tree[node] = self.merge(self.tree[node * 2], self.tree[node * 2 + 1])

a = [3, 1, 4, 1, 5, 9, 2, 6]

seg = SegTree(a)                                       # 구간 합
print(seg.query(2, 5))                                 # 19
seg.update(3, 100)                                     # arr[3] = 1 -> 100
print(seg.query(2, 5))                                 # 118

sm = SegTree(a, min, float('inf'))                     # 구간 최솟값
print(sm.query(2, 5))                                  # 1
sm.update(3, -5)
print(sm.query(2, 5))                                  # -5
```

`SegTree(a, math.gcd, 0)` 처럼 넘기면 구간 GCD 트리가 된다.

**질의 함수의 세 갈래(벗어남 / 완전 포함 / 걸침)가 세그먼트 트리의 전부다.** 이 골격만 외우면 나머지는 표 한 줄이다.

| 목적 | 구간 합 | 구간 최솟값 | 구간 최댓값 | 구간 GCD |
|---|---|---|---|---|
| 병합 연산 | `a + b` | `min(a, b)` | `max(a, b)` | `math.gcd(a, b)` |
| 항등원 | `0` | `float('inf')` | `float('-inf')` | `0` |

> **함정**: 최솟값 트리의 항등원을 `0`으로 두면 **음수가 섞였을 때 조용히 틀린다.** 연산마다 "합쳐도 아무 영향 없는 값"이 뭔지 반드시 따져야 한다. 참고로 **속도가 급하면 `self.merge` 같은 간접 호출을 걷어내고 `+`를 직접 박아 넣는다** — 파이썬에서는 람다 호출 비용이 무시할 수준이 아니다.

## 4. 재귀 vs 반복(iterative) 구현 ★★★

파이썬은 함수 호출이 비싸서 **재귀 세그먼트 트리가 유난히 느리다.** 점 갱신 + 구간 질의만 필요하면 **반복 구현**이 훨씬 낫고, 배열 크기도 `2N`이면 충분하다.

```python
class SegIter:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (2 * self.n)
        self.t[self.n:] = arr                  # 뒤쪽 절반이 리프
        for i in range(self.n - 1, 0, -1):     # 뒤에서 앞으로 부모 채우기
            self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]

    def update(self, i, val):
        i += self.n
        self.t[i] = val
        i //= 2
        while i:                               # 리프에서 루트까지 올라가며 갱신
            self.t[i] = self.t[i * 2] + self.t[i * 2 + 1]
            i //= 2

    def query(self, l, r):                     # 0-based 폐구간 [l, r]
        res = 0
        l += self.n
        r += self.n + 1                        # 내부적으로 반열린 구간으로 다룬다
        while l < r:
            if l & 1:                          # l이 오른쪽 자식이면 자기 자신을 먹고 옆으로
                res += self.t[l]; l += 1
            if r & 1:                          # r이 오른쪽 자식이면 하나 당겨 먹는다
                r -= 1; res += self.t[r]
            l //= 2; r //= 2
        return res

si = SegIter([3, 1, 4, 1, 5, 9, 2, 6])
print(si.query(2, 5))     # 19
si.update(3, 100)
print(si.query(2, 5))     # 118
```

재귀 구현은 길고 느리지만 Lazy·구간 이분탐색으로 **확장하기 쉽고**, 반복 구현은 짧고 **빠르지만** 구간 갱신을 붙이기 까다롭다.

> ★★★ **핵심**: **점 갱신만 필요하면 반복 구현 또는 펜윅**, **구간 갱신(Lazy)이 필요하면 재귀 구현**. 이 기준으로 고르면 대부분 맞는다.

## 5. Lazy Propagation — 구간 갱신 ★★★

"구간 [l, r]에 전부 v를 더해라"를 점 갱신으로 처리하면 매번 O(n log n)이라 의미가 없다. **Lazy Propagation은 "나중에 내려보낼 갱신"을 노드에 적어만 두고 미룬다.**

1. 갱신 구간이 **노드 구간을 통째로 덮으면** 자식까지 내려가지 않고 "얼마 더해야 함"만 `lazy`에 적어둔다.
2. 그 노드를 **다시 방문할 때(`push`)** 밀린 값을 자기 값에 반영하고 자식에게 물려준다.
3. 질의·갱신 모두 **내려가기 직전에 반드시 `push`** 를 부른다.

```python
class SegLazy(SegTree):                    # 3번의 구간 합 SegTree를 그대로 쓴다
    def __init__(self, arr):
        super().__init__(arr)              # merge=+, ident=0 으로 tree 빌드
        self.lazy = [0] * (4 * self.n)     # 아직 반영 안 된 "구간에 더할 값"

    def _push(self, node, s, e):
        if self.lazy[node] == 0:
            return
        # 구간 합이므로 (더할 값) x (구간 길이) 만큼 증가한다
        self.tree[node] += self.lazy[node] * (e - s + 1)
        if s != e:                          # 리프가 아니면 자식에게 물려준다
            self.lazy[node * 2] += self.lazy[node]
            self.lazy[node * 2 + 1] += self.lazy[node]
        self.lazy[node] = 0

    def update(self, l, r, add):            # [l, r]에 add를 더한다
        self._update(1, 0, self.n - 1, l, r, add)

    def _update(self, node, s, e, l, r, add):
        self._push(node, s, e)              # 내려오자마자 밀린 것부터 정리
        if r < s or e < l:
            return
        if l <= s and e <= r:               # 통째로 덮임 → 적어만 두고 즉시 반영
            self.lazy[node] += add
            self._push(node, s, e)
            return
        m = (s + e) // 2
        self._update(node * 2, s, m, l, r, add)
        self._update(node * 2 + 1, m + 1, e, l, r, add)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def query(self, l, r):
        return self._query(1, 0, self.n - 1, l, r)

    def _query(self, node, s, e, l, r):
        self._push(node, s, e)              # 질의에서도 push는 필수
        if r < s or e < l:
            return 0
        if l <= s and e <= r:
            return self.tree[node]
        m = (s + e) // 2
        return (self._query(node * 2, s, m, l, r)
                + self._query(node * 2 + 1, m + 1, e, l, r))

sl = SegLazy([1, 2, 3, 4, 5])
sl.update(1, 3, 10)         # [1,3]에 +10  ->  1 12 13 14 5
print(sl.query(0, 4), sl.query(1, 3))    # 45 39
```

> **함정**: **질의 함수에서 `push`를 빼먹는 것**이 Lazy의 1순위 버그다. 갱신에서만 push하면 밀린 값이 반영되지 않은 채로 답이 나간다. 그리고 **구간 합에서는 `lazy * 구간길이`**, **구간 최솟값에서는 `lazy` 그대로** 더한다 — 여기서 길이를 곱하는 걸 헷갈리면 조용히 틀린다.

## 6. 펜윅 트리(BIT) — 짧고 상수가 작다 ★★★

**펜윅 트리(Fenwick Tree, Binary Indexed Tree)** 는 **구간 합 계열 한정**으로 세그먼트 트리와 같은 O(log n)을 내면서 **코드가 10줄이고 상수가 훨씬 작다.** 파이썬 코딩테스트에서는 가능하면 이쪽이 유리하다.

핵심은 `i & -i` 하나다 — **i의 이진 표현에서 "가장 낮은 켜진 비트(LSB)"만 남긴다.**

```python
print([(i, bin(i), i & -i) for i in (3, 6, 12)])
# [(3, '0b11', 1), (6, '0b110', 2), (12, '0b1100', 4)]
```

`tree[i]`는 **`[i - (i & -i) + 1, i]` 구간의 합**을 담는다. 즉 i가 책임지는 구간 길이가 곧 `i & -i`다. 그래서 **`query(i)`** 는 `i -= i & -i`로 왼쪽으로 건너뛰며 조각을 모으고, **`update(i, delta)`** 는 `i += i & -i`로 나를 포함하는 상위 구간을 타고 올라가며 더한다.

```python
class BIT:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)      # 1-based (0번은 안 쓴다)

    def update(self, i, delta):        # i번 원소에 delta를 "더한다"
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i                # 나를 덮는 다음 구간으로

    def query(self, i):                # [1, i] 구간 합
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & -i                # 이 조각 만큼 왼쪽으로 점프
        return s

    def range_query(self, l, r):       # [l, r] 구간 합
        return self.query(r) - self.query(l - 1)

arr = [3, 1, 4, 1, 5, 9, 2, 6]
bit = BIT(len(arr))
for i, v in enumerate(arr):
    bit.update(i + 1, v)               # 1-based로 넣는다
print(bit.range_query(3, 6))           # 4+1+5+9 = 19
bit.update(4, 99)                      # arr[3]에 99를 "더한다" (교체가 아님)
print(bit.range_query(3, 6))           # 118
```

> **함정**: 펜윅은 **1-based 필수**다. `i = 0`이면 `i & -i == 0`이라 `while` 루프가 영원히 안 끝나거나 즉시 끝난다. 그리고 `update`는 **교체가 아니라 증분(delta)** 이다. 값을 v로 "교체"하려면 `update(i, v - 현재값)`처럼 차이를 넣고 현재값을 따로 배열로 관리해야 한다.

## 7. 세그먼트 트리 vs 펜윅 비교표 ★★★

| 항목 | 세그먼트 트리 | 펜윅 트리(BIT) |
|---|---|---|
| 코드 길이 / 메모리 | 길다(40줄+) / 4N | **짧다(10줄) / N+1** |
| 상수(실제 속도) | 느림 | **빠름** |
| 구간 합 | O(log n) | O(log n) |
| **구간 최소/최대** | **가능** | 사실상 불가(역원이 없음) |
| GCD·행렬곱 등 임의 결합연산 | **가능** | 불가 |
| 구간 갱신 | Lazy로 가능 | BIT 2개 트릭으로 제한적 가능 |
| 인덱스 기준 | 0-based 가능 | **1-based 필수** |

> ★★★ **핵심**: **"합/개수만 세면 펜윅, 최소·최대·GCD처럼 뺄셈이 안 되는 연산이면 세그먼트 트리."** 펜윅이 되는 이유는 구간 합에 **역원(뺄셈)** 이 있어서 `[1,r] - [1,l-1]`이 성립하기 때문이고, 최솟값은 뺄 수가 없어서 안 된다.

## 8. 대표 응용 — 역순 쌍(inversion) 개수 세기 ★★★

`i < j` 인데 `arr[i] > arr[j]`인 쌍의 개수를 세는 문제. 브루트포스는 O(N²)이지만 **펜윅으로 O(N log N)** 에 푼다. 아이디어는 **뒤에서부터 훑으며 "지금까지 본 값 중 나보다 작은 게 몇 개인가"** 를 세는 것이고, 값 범위가 크면 **좌표 압축**으로 1..M 랭크로 바꾼다.

```python
def count_inversions(arr):
    # 1) 좌표 압축: 값 -> 1부터 시작하는 랭크
    srt = sorted(set(arr))
    rank = {v: i + 1 for i, v in enumerate(srt)}

    bit = BIT(len(srt))
    inv = 0
    for x in reversed(arr):            # 뒤에서 앞으로
        r = rank[x]
        inv += bit.query(r - 1)        # 나보다 작은 값이 이미 몇 개 나왔나
        bit.update(r, 1)               # 나를 등록
    return inv

print(count_inversions([3, 1, 4, 1, 5, 9, 2, 6]))   # 8
print(count_inversions([5, 4, 3, 2, 1]))            # 10 (완전 역정렬 = nC2)
```

같은 골격으로 "특정 값 이하의 개수", "k번째 수 찾기" 등이 전부 나온다. **개수를 세는 문제는 값을 인덱스로 바꿔 BIT에 꽂는 것**이 정석 패턴이다.

## 9. 파이썬 성능 주의 ★★★

플래티넘 구간에서 세그먼트 트리는 **알고리즘이 맞아도 파이썬이라 시간 초과**가 나기 쉽다.

| 문제 | 대응 |
|---|---|
| 재귀 함수 호출이 느리다 | **반복 구현이나 펜윅으로 교체** |
| `input()` 사용 | `input = sys.stdin.readline` 필수. 질의 10만 줄이면 이것만으로 몇 배 차이 |
| `print()` 반복 호출 | 결과를 리스트에 모아 `sys.stdout.write('\n'.join(...))` |
| 클래스·람다 호출 비용 | 극한 상황에선 **전역 리스트 + 함수**로 펴고 연산을 직접 박아 넣기 |
| PyPy3 제출 가능 여부 | 가능하면 PyPy3 (재귀·메모리 많이 쓰는 경우는 예외) |

입력이 아주 크면 `it = iter(sys.stdin.buffer.read().split())` 로 한 번에 읽고 `int(next(it))`로 꺼내 쓰는 게 가장 빠르다.

> **함정**: 세그먼트 트리를 클래스로 예쁘게 짜면 읽기는 좋지만, 파이썬에서는 **메서드 호출 오버헤드 + 재귀**가 겹쳐 2~3배 느려진다. 시간이 빡빡한 문제에서는 **트리를 전역 리스트로 두고 재귀 대신 반복으로 푸는** 형태로 바꾸는 게 마지막 카드다.

### 한 줄 요약
누적 합은 질의 O(1)이지만 **갱신이 O(n)** 이라, 질의와 갱신이 섞이면 **세그먼트 트리(배열 4N, 벗어남/완전포함/걸침 3갈래)** 로 둘 다 O(log n)에 처리한다. 병합 연산과 항등원만 바꾸면 합·최솟값·GCD로 확장되고, **구간 갱신은 Lazy Propagation**(질의에서도 `push` 필수, 구간 합은 `lazy × 구간길이`)으로 해결한다. **합·개수 세기만 필요하면 `i & -i` 하나로 굴러가는 펜윅 트리(BIT)** 가 코드도 10줄, 메모리도 N+1, 상수도 작아 파이썬에서는 사실상 1순위이며, 좌표 압축과 묶으면 **역순 쌍 개수**처럼 세는 문제를 O(N log N)에 푼다. 다만 최소·최대처럼 **역원이 없는 연산은 펜윅으로 안 되므로** 세그먼트 트리를 쓰고, 파이썬에서는 **재귀보다 반복 구현·`sys.stdin.buffer.read()`·출력 모아 쓰기**로 상수를 깎아야 살아남는다.
