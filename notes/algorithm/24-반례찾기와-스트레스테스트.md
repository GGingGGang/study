# 반례 찾기와 스트레스 테스트 (Stress Testing)

> 알고리즘 · 실전 · 학습내용: "틀렸습니다"를 만났을 때의 표준 절차, 스트레스 테스트 원리(랜덤 생성기 + 브루트포스 정답 + 내 풀이 대조), gen.py / brute.py / sol.py 3파일 구성과 bash·python 비교 루프 전체 코드, 랜덤 생성기 작성 요령(작은 N부터·시드 고정), 찾은 반례를 최소화하기, 브루트포스를 못 짜는 경우의 불변식 자가 검증, 경계값 체크리스트, 랜덤 테스트로 못 잡는 버그 유형

---

## 1. "틀렸습니다"를 만났을 때 ★★★

예제는 통과하는데 채점에서 틀렸다면, 코드를 다시 읽는 건 대체로 시간 낭비다. **눈으로 못 찾았으니까 틀린 것**이기 때문이다.

| 순서 | 할 일 | 비용 |
|---|---|---|
| 1 | **경계값 체크리스트**(8번)를 손으로 훑는다 | 1분 |
| 2 | 문제 조건을 다시 읽는다 (범위·부호·중복 허용 여부) | 2분 |
| 3 | **스트레스 테스트**로 반례를 기계에게 찾게 한다 | 5~10분 |
| 4 | 반례를 **최소화**해 원인을 눈으로 확인한다 | 2분 |

> ★★★ **핵심**: 스트레스 테스트는 **"내 풀이가 틀렸다는 증거(반례 입력)를 기계가 만들어 주는 것"** 이다. 사람이 못 떠올린 케이스를 컴퓨터는 초당 수백 개 만들어 본다. 플래티넘 구간에서 이걸 못 하면 한 문제에 며칠이 날아간다.

## 2. 스트레스 테스트 원리 ★★★

```
       gen.py            sol.py  ──→ 내 답
   (랜덤 입력 생성) ──┬──→                  ──→ diff ──→ 다르면 반례!
                     └──→ brute.py ──→ 정답
```

| 파일 | 역할 | 조건 |
|---|---|---|
| `gen.py` | **랜덤 입력 생성** | 시드를 인자로 받아 **재현 가능**해야 한다 |
| `brute.py` | **느리지만 확실히 맞는 풀이** | 완전탐색·O(N²)·O(2^N) 무엇이든 |
| `sol.py` | **내가 제출하려는 풀이** | 빠르지만 틀렸을지 모르는 것 |

**이 셋을 작은 입력으로 수천 번 돌려 답이 갈리는 순간을 잡는다.** 입력이 작아야 (a) 브루트포스가 돌고 (b) 반례를 눈으로 읽을 수 있다.

## 3. 3파일 구성 — 전체 코드 ★★★

예시 문제: **"정수 배열에서 연속 부분 수열의 합 중 최댓값"**(부분 수열은 비어 있을 수 없다).

### gen.py — 랜덤 입력 생성기

```python
import random, sys

# 사용법: python3 gen.py <시드>
# 시드를 인자로 받아야 반례를 그대로 재현할 수 있다.
seed = int(sys.argv[1])
random.seed(seed)

n = random.randint(1, 8)                       # 작게! 브루트포스가 돌아야 한다
arr = [random.randint(-10, 10) for _ in range(n)]   # 음수를 반드시 섞는다

print(n)
print(*arr)
```

### brute.py — 느리지만 확실히 맞는 풀이

```python
import sys
input = sys.stdin.readline

# 모든 구간을 다 본다 O(N^2). 느려도 되고, 무조건 맞기만 하면 된다.
n = int(input())
arr = list(map(int, input().split()))

best = arr[0]
for i in range(n):
    s = 0
    for j in range(i, n):
        s += arr[j]
        best = max(best, s)
print(best)
```

### sol.py — 내 풀이 (버그가 숨어 있다)

```python
import sys
input = sys.stdin.readline

n = int(input())
arr = list(map(int, input().split()))

best = 0        # <-- 버그: 0으로 시작하면 모두 음수일 때 답이 0이 되어버린다
cur = 0
for x in arr:
    cur = max(x, cur + x)
    best = max(best, cur)
print(best)
```

> **함정**: `brute.py`는 **최대한 멍청하게** 짜야 한다. 여기에 최적화를 넣거나 `sol.py`의 아이디어를 재활용하면 **같은 버그를 공유해 둘 다 틀린 답을 내고**, 스트레스 테스트가 "전부 일치"라고 거짓말한다.

## 4. 비교 루프 — bash 버전 ★★★

```bash
#!/bin/bash
# stress.sh — 반례가 나올 때까지 랜덤 입력으로 sol.py 와 brute.py 를 대조한다.
for ((i=1; i<=10000; i++)); do
    python3 gen.py "$i" > in.txt
    python3 sol.py   < in.txt > out_sol.txt
    python3 brute.py < in.txt > out_brute.txt

    if ! diff -q -Z out_sol.txt out_brute.txt > /dev/null; then
        echo "반례 발견! (시드 $i)"
        echo "--- 입력 ---";     cat in.txt
        echo "--- 내 출력 ---";  cat out_sol.txt
        echo "--- 정답 ---";     cat out_brute.txt
        exit 1
    fi
    [ $((i % 100)) -eq 0 ] && echo "$i 개 통과..."
done
echo "10000개 전부 일치 (반례 못 찾음)"
```

실제로 돌리면 **두 번째 시도에서 바로 잡힌다.**

```bash
$ chmod +x stress.sh
$ ./stress.sh
반례 발견! (시드 2)
--- 입력 ---
1
-8
--- 내 출력 ---
0
--- 정답 ---
-8
```

`best = 0`으로 시작한 탓에 **모두 음수인 배열에서 0을 내놓는** 버그가 그대로 드러났다. `best = arr[0]`으로 고치고 다시 돌리면 `10000개 전부 일치`가 나온다.

## 5. 비교 루프 — python 버전 ★★★

파이썬 버전이 더 편할 때가 많다. **런타임 에러도 반례로 잡아주고**, 출력 가공이 자유롭다.

```python
import subprocess, sys

def run(script, data):
    p = subprocess.run([sys.executable, script], input=data,
                       capture_output=True, text=True)
    if p.returncode != 0:                      # 런타임 에러도 훌륭한 반례다
        return f"<RUNTIME ERROR>\n{p.stderr.strip()}"
    return p.stdout.strip()

for seed in range(1, 10001):
    data = subprocess.run([sys.executable, 'gen.py', str(seed)],
                          capture_output=True, text=True).stdout
    mine = run('sol.py', data)
    ans = run('brute.py', data)
    if mine != ans:
        print(f"반례 발견! (시드 {seed})")
        print("--- 입력 ---");    print(data, end='')
        print("--- 내 출력 ---"); print(mine)
        print("--- 정답 ---");    print(ans)
        sys.exit(1)
    if seed % 200 == 0:
        print(f"{seed}개 통과...", file=sys.stderr)
else:
    print("전부 일치 (반례 못 찾음)")
```

`stress.py`도 bash 버전과 똑같이 **시드 2에서 입력 `1 / -8`, 내 출력 `0`, 정답 `-8`** 을 잡아낸다.

> **함정**: 시드를 고정하지 않고 `random.seed()`(인자 없음)로 돌리면 **반례를 찾은 뒤 다시 재현할 수 없다.** 출력에 시드를 반드시 찍고, 입력도 `in.txt`로 남긴다.

## 6. 랜덤 생성기 작성법과 반례 최소화 ★★★

### 생성기 원칙

| 원칙 | 이유 |
|---|---|
| **N을 아주 작게**(1~8) 시작 | 브루트포스가 돌고, 반례를 눈으로 읽을 수 있다 |
| **값 범위도 좁게**(-10~10) | 좁아야 중복·같은 값·상쇄가 자주 생겨 버그를 자극한다 |
| **시드를 인자로** | 재현 가능성. 이게 없으면 반례를 놓친다 |
| 안 잡히면 **범위를 조금씩 넓힌다** | 작은 값에서 안 나오면 N=50, 값 -10^9~10^9 로 |
| 그래프면 **트리·완전그래프·사이클을 따로** | 순수 랜덤 그래프는 특수 구조를 거의 안 만든다 |

### 반례 최소화 (shrink)

스트레스 테스트가 N=50짜리 반례를 던져줬다면 그대로 읽기 어렵다. **원소를 하나씩 빼 보며 여전히 틀리면 채택**하는 그리디 축소로 몇 초 만에 최소 반례를 얻는다.

```python
import subprocess, sys

def out(script, data):
    p = subprocess.run([sys.executable, script], input=data,
                       capture_output=True, text=True)
    return f"<RE>{p.stderr.strip()}" if p.returncode else p.stdout.strip()

def fails(arr):
    if not arr:                                  # 빈 입력은 애초에 유효하지 않다
        return False
    data = f"{len(arr)}\n{' '.join(map(str, arr))}\n"
    return out('sol.py', data) != out('brute.py', data)

arr = [-4, -9, -2, -7, -1, -5, -3, -8]           # 크게 잡힌 반례
assert fails(arr), '시작 입력부터 틀려야 최소화가 의미 있다'

changed = True
while changed:
    changed = False
    for i in range(len(arr)):
        cand = arr[:i] + arr[i + 1:]
        if fails(cand):                          # 빼도 여전히 틀리면 채택
            arr = cand
            changed = True
            break
print("최소 반례:", arr)
```

```
$ python3 shrink.py
최소 반례: [-8]
```

원소 8개짜리 반례가 **`[-8]` 하나로 줄었다.** 여기까지 오면 "아, 전부 음수면 0을 내는구나"가 코드를 안 봐도 보인다.

## 7. 브루트포스를 못 짜는 경우 — 불변식 자가 검증 ★★

정답 풀이가 아예 안 떠오르거나, 답이 여러 개라 단순 비교가 안 되는 문제도 있다. 이럴 때는 **"답이 반드시 만족해야 할 성질"만 검사**한다. 검증이 푸는 것보다 훨씬 쉬운 경우가 많다.

| 문제 유형 | 검사할 불변식 |
|---|---|
| 위상 정렬 | 모든 정점이 정확히 한 번 등장 + 모든 간선이 순서를 지킴 |
| 최단 경로 | 모든 간선에 대해 `dist[v] <= dist[u] + w` |
| 최소 신장 트리 | 간선 N-1개 + 사이클 없음 + 모든 정점 연결 |
| 구간 스케줄링 | 고른 구간들이 서로 안 겹침 |
| 순열·조합 출력 | 개수가 맞고 중복이 없음 |

```python
import random
from collections import deque

def topo_sort(n, edges):
    """위상 정렬 — 버그 있음: 큐 초기화 범위가 range(1, n) 이라 정점 n을 빠뜨린다"""
    indeg = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]
    for u, v in edges:
        g[u].append(v)
        indeg[v] += 1
    q = deque(v for v in range(1, n) if indeg[v] == 0)   # <-- range(1, n+1) 이어야 한다
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return order

def check(n, edges, order):
    """정답 풀이 없이도 답이 갖춰야 할 성질만으로 검증한다."""
    if sorted(order) != list(range(1, n + 1)):
        return "모든 정점이 정확히 한 번씩 나오지 않음"
    pos = {v: i for i, v in enumerate(order)}
    for u, v in edges:
        if pos[u] >= pos[v]:
            return f"간선 {u}->{v} 가 순서를 어김"
    return None

random.seed(3)
for t in range(3000):
    n = random.randint(1, 6)
    edges = [(u, v) for u in range(1, n + 1) for v in range(u + 1, n + 1)
             if random.random() < 0.35]          # u<v 로만 만들어 DAG 보장
    order = topo_sort(n, edges)
    err = check(n, edges, order)
    if err:
        print(f"자가 검증 실패! n={n} edges={edges}")
        print(f"  출력={order}  사유={err}")
        break
else:
    print("3000회 자가 검증 통과")
```

```
$ python3 selfcheck.py
자가 검증 실패! n=2 edges=[]
  출력=[1]  사유=모든 정점이 정확히 한 번씩 나오지 않음
```

## 8. 경계값 체크리스트 ★★★

스트레스 테스트를 돌리기 전에 **1분이면 끝나는 이 목록부터** 훑는다. 절반은 여기서 잡힌다.

| 케이스 | 확인할 것 |
|---|---|
| **N = 1** | 반복문이 한 번도 안 돌거나, `arr[i-1]` 인덱스가 음수가 되지 않는가 |
| **N = 0 / 빈 입력** | 허용된다면 `max()`가 `ValueError`를 내지 않는가 |
| **최댓값 입력** | N과 값이 최대일 때의 시간·메모리 |
| **음수** | `best = 0` 초기화, `abs`, 나눗셈 방향(`//`는 음수에서 내림) |
| **0** | 0으로 나누기, 0을 곱해 답이 0이 되는 경우 |
| **중복 값** | `set`으로 날려도 되는가, 등호(`<` vs `<=`) 처리 |
| **모두 같은 값** | 이분 탐색·투 포인터가 무한 루프에 빠지지 않는가 |
| **정렬된 입력 / 역정렬 입력** | 퀵정렬류 최악, 스택 깊이, 그리디 가정 |
| **답이 음수/0일 수 있는가** | 초기값을 `0`이 아니라 `-inf`나 `arr[0]`으로 |
| **출력 형식** | 소수점 자리수, 공백/개행, 대소문자(`YES` vs `Yes`) |

```python
# 위 목록을 그대로 tests/ 케이스로 찍어내는 습관
cases = {
    'n1':   "1\n0\n",                 # N=1
    'neg':  "3\n-5 -1 -3\n",          # 전부 음수
    'same': "4\n7 7 7 7\n",           # 모두 같은 값
    'sort': "5\n1 2 3 4 5\n",         # 정렬된 입력
    'rev':  "5\n5 4 3 2 1\n",         # 역정렬 입력
}
for name, data in cases.items():
    with open(f'tests/{name}.in', 'w') as f:
        f.write(data)
print(f"{len(cases)}개 경계 케이스 생성 완료")
```

> ★★★ **핵심**: **`N=1`, `전부 음수`, `모두 같은 값`** — 이 셋이 코딩테스트 오답의 압도적 다수다. 제출 전에 이 세 개만이라도 손으로 넣어 보면 "틀렸습니다"의 절반이 사라진다.

## 9. 랜덤 테스트로 못 잡는 버그 ★★

스트레스 테스트는 만능이 아니다. **구조적으로 못 잡는 유형**을 알아야 헛수고를 안 한다.

| 못 잡는 유형 | 왜 못 잡나 | 대응 |
|---|---|---|
| **시간 초과** | 작은 N만 돌리므로 성능이 안 드러난다 | 별도로 최대 입력을 만들어 `time` 측정 |
| **메모리 초과** | 위와 같은 이유 | 최대 입력으로 RSS 확인 |
| 큰 값에서만 나는 버그 | 값 범위를 좁게 잡아서 | 범위를 넓힌 생성기를 따로 돌린다 |
| **특수 구조**(별 모양 트리, 완전 그래프, 일직선) | 순수 랜덤은 거의 안 만든다 | 구조별 생성기를 따로 쓴다 |
| 브루트포스와 **공유한 오해** | 문제를 잘못 읽었으면 둘 다 같이 틀린다 | 문제 조건을 다시 읽는다 |
| **재귀 깊이 초과** | 작은 N에서는 안 터진다 | 최대 깊이 입력을 따로 만든다 |

> **함정**: "10000개 전부 일치"가 나왔다고 정답이 보장되지는 않는다. **생성기가 만들 수 있는 범위 안에서만** 맞다는 뜻이다. 안 잡히면 **생성기를 의심하라** — N 범위, 값 범위, 그래프 모양을 바꿔 보는 게 코드를 다시 읽는 것보다 훨씬 생산적이다.

### 한 줄 요약
"틀렸습니다"에는 코드를 다시 읽지 말고 **경계값 체크리스트(N=1·전부 음수·모두 같은 값) → 스트레스 테스트 → 반례 최소화** 순서로 대응한다. 스트레스 테스트는 **`gen.py`(시드를 인자로 받는 작은 랜덤 입력) + `brute.py`(느리지만 확실한 완전탐색) + `sol.py`(내 풀이)** 를 수천 번 돌려 `diff`로 갈리는 순간을 잡는 것이며, bash `for` 루프든 `subprocess`를 쓰는 파이썬이든 상관없다(파이썬 쪽이 **런타임 에러까지 반례로 잡아준다**). 브루트포스는 **의도적으로 멍청하게** 짜야 같은 오해를 공유하지 않고, 반례를 찾으면 **원소를 하나씩 빼며 그리디하게 최소화**해 눈으로 읽을 수 있게 줄인다. 정답 풀이를 못 짜는 문제는 **"답이 만족해야 할 불변식"만 검사하는 자가 검증**으로 대체할 수 있다. 다만 스트레스 테스트는 작은 입력만 돌리므로 **시간·메모리 초과, 특수 구조, 문제 오독은 절대 못 잡는다** — 안 잡힐 때는 코드가 아니라 **생성기를 의심하는 것**이 정답이다.
