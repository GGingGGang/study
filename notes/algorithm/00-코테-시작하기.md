## 1. 코딩테스트란 무엇인가 ★★★

코딩테스트는 **"정해진 시간·메모리 안에서 정확한 답을 내는 프로그램을 짜는 능력"** 을 보는 시험이다. 실무 코드처럼 읽기 좋게 설계할 필요가 없고, 반대로 **입력을 읽고 → 알고리즘을 돌리고 → 출력하는** 단 하나의 파이프라인만 정확하면 된다.

| 실무 코드 | 코테 코드 |
|---|---|
| 유지보수·확장성이 중요 | **한 번 쓰고 버림**, 짧고 빠르면 됨 |
| 예외 처리·검증 필수 | 입력은 **문제 조건대로 반드시 들어온다**고 가정 |
| 성능은 병목만 최적화 | **처음부터 최악 입력 기준**으로 복잡도를 맞춤 |
| 테스트 코드 작성 | 예제 입출력 + 반례를 손으로 만듦 |

채점은 사람이 아니라 **채점기(judge)** 가 한다. 채점기는 여러분의 프로그램을 실행해 **표준 입력(stdin)** 으로 데이터를 밀어 넣고, **표준 출력(stdout)** 을 정답 파일과 문자 단위로 비교한다. 그래서 **"디버깅용 print"가 하나라도 남아 있으면 무조건 틀린다.**

```python
import sys
input = sys.stdin.readline          # 빠른 입력으로 교체 (거의 모든 문제의 기본형)

def solve():
    n = int(input())                # 첫 줄: 원소 개수
    arr = list(map(int, input().split()))  # 둘째 줄: 공백으로 구분된 N개의 정수
    print(sum(arr))                 # 결과는 stdout으로만 출력

solve()
```

> ★★★ **핵심**: 채점기는 **stdout 전체**를 정답과 비교한다. `print("여기까지 옴")` 같은 로그가 남으면 로직이 완벽해도 "틀렸습니다"가 뜬다. 디버그 출력은 `print(..., file=sys.stderr)`로 빼거나 제출 전에 지운다.

## 2. 채점 결과 읽는 법 ★★★

채점 결과는 **에러 메시지가 아니라 진단서**다. 결과별로 의심해야 할 원인이 정해져 있다.

| 결과 | 뜻 | 가장 흔한 원인 |
|---|---|---|
| **맞았습니다** | 모든 테스트 케이스 통과 | — |
| **틀렸습니다 (WA)** | 출력이 정답과 다름 | 로직 오류, **경계값**(N=1, 0, 음수), 출력 형식(공백·줄바꿈), 자료형 착각 |
| **시간 초과 (TLE)** | 제한 시간 안에 못 끝냄 | 복잡도 과다, **느린 입출력**(`input()`, 반복 `print`), 불필요한 재계산 |
| **메모리 초과 (MLE)** | 제한 메모리 초과 | 너무 큰 배열, 리스트 복사 남발, **깊은 재귀**, 방문 처리 없는 탐색 |
| **런타임 에러 (RE)** | 실행 중 예외로 죽음 | 인덱스 초과, 0으로 나눔, **재귀 깊이 초과**, 빈 리스트 pop, 입력 부족 |
| **출력 초과** | 출력이 정답보다 지나치게 김 | 무한 루프 안의 print, 디버그 출력이 남음 |
| **컴파일 에러** | 문법 오류 | 파이썬은 문법 오류·들여쓰기 오류 |

파이썬의 런타임 에러는 종류를 세분해서 보여주는 저지가 많다. 대응은 이렇게 한다.

| 파이썬 예외 | 의미 | 대응 |
|---|---|---|
| `IndexError` | 리스트 범위 밖 접근 | 경계 검사, 배열 크기를 `N+1`로 여유 있게 |
| `ValueError` | `int('')` 등 파싱 실패 | 입력 줄 수·형식 재확인, `rstrip()` 처리 |
| `RecursionError` | 재귀 깊이 초과 | `sys.setrecursionlimit` 상향 또는 **반복문으로 변환** |
| `ZeroDivisionError` | 0으로 나눔 | 분모 0 케이스 분기 |
| `MemoryError` | 메모리 부족 | 자료구조 축소, 제너레이터 사용 |
| `EOFError` | 읽을 입력이 없음 | 입력 줄 수 계산 오류, EOF 처리 |

```python
import sys

sys.setrecursionlimit(10**6)        # 기본값은 1000 → 깊은 DFS면 반드시 올린다

def depth(n):
    if n == 0:                      # 종료 조건이 없으면 RecursionError
        return 0
    return 1 + depth(n - 1)

print(depth(50000))                 # 50000
print(sys.getrecursionlimit())      # 1000000
```

> **함정**: `sys.setrecursionlimit`을 너무 크게(예: `10**9`) 잡으면 재귀 프레임이 실제 스택을 넘어서 **RecursionError 대신 프로세스가 통째로 죽는다**(저지에서는 런타임 에러나 메모리 초과로 표시). `10**6` 정도가 실무적 상한이다.

## 3. 파이썬으로 코테를 본다는 것 ★★★

파이썬은 **"짧게 짜서 빨리 제출하고, 대신 상수 시간이 느린"** 언어다. 이 트레이드오프를 알고 들어가야 한다.

### 3.1 장점

- **구현 속도가 압도적이다.** 정렬 한 줄, 딕셔너리 한 줄, 조합·순열이 표준 라이브러리에 다 있다.
- **정수 오버플로가 없다.** `int`가 임의 정밀도라서 `10**100`도 그냥 계산된다. C++에서 `long long` 넘침으로 틀리는 사고가 원천 봉쇄된다.
- **표준 라이브러리가 강하다.** `heapq`, `bisect`, `collections`, `itertools`, `functools.lru_cache`만으로 상당수 알고리즘 문제의 뼈대가 나온다.
- **코드가 짧아 디버깅 지점이 적다.** 실전에서 시간 압박이 있을 때 이 차이가 크다.

### 3.2 단점

- **느리다.** 같은 알고리즘이라도 C++ 대비 대략 **10~50배** 느리다고 보는 게 안전하다. 복잡도가 아슬아슬하면 파이썬만 시간 초과가 난다.
- **메모리를 많이 쓴다.** 정수 하나가 객체라서 `int` 100만 개 리스트가 **약 35MB**(포인터 8MB + 객체 약 27MB)를 먹는다.
- **재귀가 비싸다.** 함수 호출 오버헤드가 커서 깊은 DFS는 반복문(스택) 변환이 필요할 때가 있다.

```python
import sys

# 파이썬 정수는 자릿수 제한이 없다 (오버플로 없음)
print(2 ** 200)                     # 1606938044258990275541962092341162602522202993782792835301376
print(len(str(2 ** 200)))           # 61

# 대신 객체라서 메모리를 먹는다
print(sys.getsizeof(1))             # 28  (작은 정수 하나가 28바이트)
print(sys.getsizeof([0] * 1000000)) # 8000056  (포인터만 약 8MB)
```

> ★★★ **핵심**: 파이썬 선택의 결론은 **"알고리즘을 한 단계 더 좋은 걸로 고르고, 입출력·상수 최적화를 습관화한다"** 이다. 언어 탓을 하기 전에 `sys.stdin.readline`부터 쓴다.

## 4. Python3 vs PyPy3 ★★★

같은 코드를 두 가지 실행기로 제출할 수 있는 저지가 많다.

| 항목 | Python3 (CPython) | PyPy3 |
|---|---|---|
| 실행 방식 | 바이트코드 인터프리터 | **JIT 컴파일**(실행 중 기계어로 변환) |
| 반복문·산술 속도 | 느림 (기준) | **보통 3~10배 빠름** |
| 메모리 사용량 | 적음 | **더 많이 씀**(JIT 코드·객체 오버헤드) |
| 짧은 코드 | 시작 오버헤드 적음 | 워밍업 때문에 **오히려 느릴 수 있음** |
| 깊은 재귀 | 상대적으로 안전 | **프레임이 무거워 메모리 초과 위험** |
| 큰 정수 연산 | 최적화가 잘 되어 있음 | 종종 CPython이 더 나음 |

### 4.1 선택 기준

- **기본은 PyPy3.** 반복문이 많은 완전탐색·DP·그래프 탐색은 거의 항상 PyPy3가 유리하다.
- **깊은 재귀(DFS 깊이 수만 이상)** 이면 재귀를 **반복문으로 바꾼 뒤** PyPy3를 쓰거나, 그게 어려우면 Python3로 제출한다.
- **메모리 제한이 빡빡한 문제**(예: 128MB 이하)에서 PyPy3가 메모리 초과를 내면 Python3로 바꿔본다.
- **아주 큰 정수 연산이 핵심**(거듭제곱·팩토리얼 등)이면 Python3도 같이 시도해 본다.
- 시간 초과가 났을 때 **"실행기만 바꿔서 통과"를 노리는 건 임시방편**이다. 근본은 복잡도다.

> **함정**: PyPy3에서 시간 초과가 났는데 Python3에서는 통과하는 경우도 실제로 있다. 원인은 대개 **큰 정수 연산**이나 **문자열 처리**다. 두 실행기 모두 한 번씩 눌러보는 건 공짜다.

## 5. 티어 체계와 플래티넘 5 로드맵 ★★

티어는 보통 **브론즈 → 실버 → 골드 → 플래티넘 → 다이아몬드 → 루비** 순이고, 각 티어는 **V(5)가 가장 낮고 I(1)이 가장 높다**. 즉 골드 I 바로 위가 **플래티넘 V**다.

| 구간 | 요구 능력 | 대표 주제 |
|---|---|---|
| 브론즈 | 입출력·조건문·반복문 | 사칙연산, 문자열 처리, 단순 시뮬레이션 |
| 실버 | 자료구조·기본 알고리즘 | 정렬, 스택·큐·덱, 완전탐색, BFS/DFS, 이분탐색, 기본 그리디 |
| 골드 | 알고리즘 조합·최적화 | DP(배낭·LIS·구간), 다익스트라, 유니온 파인드, MST, 위상정렬, 투 포인터, 누적합 |
| **플래티넘 V** | **정형 알고리즘 + 관찰** | 세그먼트 트리, 트리 DP, 비트마스크 DP, 최단경로 응용, 강한 연결 요소, 고급 그리디 |

### 5.1 단계별 로드맵 (플래티넘 5까지)

1. **기초 다지기 (2~3주)** — 빠른 입출력, 시간복잡도 감각, 리스트·문자열·딕셔너리·셋, 정렬 `key`.
2. **자료구조 (2~3주)** — 스택, 큐, `deque`, 힙(`heapq`), `bisect`, `Counter`/`defaultdict`.
3. **완전탐색·백트래킹 (2주)** — 재귀 설계, 순열·조합, 가지치기, 비트마스크 표현.
4. **그래프 (3~4주)** — BFS·DFS, 최단거리 BFS, 다익스트라, 유니온 파인드, MST, 위상정렬.
5. **DP (4주 이상, 가장 오래 걸림)** — 1차원 → 2차원 → 배낭 → LIS → 구간 → 비트마스크 → 트리 DP.
6. **고급 (4주)** — 세그먼트 트리·펜윅 트리, 분할정복, 파라메트릭 서치, SCC.

> ★★ **핵심**: 대부분의 사람이 **DP에서 멈춘다.** 플래티넘 5의 벽은 자료구조가 아니라 **"점화식을 스스로 세우는 훈련량"** 이다. 골드 구간에서 DP 문제만 50문제 이상 몰아서 푸는 구간을 반드시 만든다.

## 6. 하루 학습 루틴 제안 ★★

취업 준비 중이라면 **매일 짧게, 대신 빠지지 않고**가 정답이다. 주 5~6일, 하루 2~3시간 기준 예시다.

| 시간 | 활동 | 목적 |
|---|---|---|
| 20분 | 어제 푼 문제 **다시 보기**(코드 안 보고 접근만 떠올리기) | 장기 기억화 |
| 40분 | **쉬운 문제 1개**(현재 티어보다 한 단계 아래) | 손 풀기·자신감 |
| 60분 | **목표 티어 문제 1개**(현재 티어 또는 한 단계 위) | 실력 상승 구간 |
| 20분 | **오답·해설 정리**(핵심 아이디어 3줄로 기록) | 패턴 축적 |

- **주 1회는 "복습 데이" 로 쓴다.** 그 주에 틀렸던 문제를 백지에서 다시 푼다. 새 문제를 푸는 것보다 실력이 빨리 오른다.
- **한 주제를 몰아서 판다.** 오늘 BFS, 내일 DP 식으로 흩뿌리면 패턴이 안 붙는다. **한 주제 10~15문제 연속**이 훨씬 효과적이다.
- **손으로 먼저 설계한다.** 종이에 입력 예시를 그려보고 자료구조·복잡도를 정한 뒤 코드를 친다. 이게 실전에서 시간을 가장 많이 아낀다.

## 7. 못 풀 때, 언제 답을 볼 것인가 (30~60분 룰) ★★★

**"오래 붙잡고 있는 것"과 "성장하는 것"은 다르다.** 기준을 미리 정해두지 않으면 하루를 한 문제에 태우고 자책만 남는다.

| 상황 | 권장 행동 |
|---|---|
| 0~30분: 접근법 자체가 안 떠오름 | **계속 고민한다.** 이 구간이 실력이 자라는 구간 |
| 30분 경과, 아이디어 0개 | **문제 유형(태그)만 확인한다.** "DP구나"만 알고 다시 30분 |
| 60분 경과, 여전히 막힘 | **해설의 아이디어 한 줄만** 읽고 코드는 직접 짠다 |
| 아이디어는 맞는데 구현이 틀림 | **반례를 만든다.** 무식한 완전탐색 코드와 결과를 대조 |
| 해설 코드를 다 봤다 | 즉시 닫고 **백지에서 다시 짠다.** 그리고 **3일 뒤 한 번 더** |

- **핵심은 "답을 보는 것"이 아니라 "답을 본 뒤 무엇을 하는가"** 다. 해설 코드를 그대로 복붙하고 넘어가면 아무것도 남지 않는다.
- 틀린 문제는 **한 줄 메모**를 남긴다. 예: "정렬 기준이 두 개일 때 `key=lambda x: (x[0], -x[1])`" 처럼 **다음에 재사용 가능한 형태**로.

### 7.1 무식한 코드로 반례 찾기

```python
import random

def solve_fast(arr):                # 내가 최적화해서 짠 풀이 (여기서는 최댓값 구하기)
    best = arr[0]
    for x in arr:
        if x > best:
            best = x
    return best

def solve_brute(arr):               # 확실히 맞지만 느린 풀이
    return sorted(arr)[-1]

random.seed(42)                     # 재현 가능하게 시드 고정
for _ in range(1000):               # 랜덤 입력으로 두 결과를 비교
    arr = [random.randint(-10, 10) for _ in range(random.randint(1, 8))]
    if solve_fast(arr) != solve_brute(arr):
        print('반례 발견:', arr)
        break
else:
    print('1000회 테스트 통과')      # 1000회 테스트 통과
```

> ★★★ **핵심**: 이 **랜덤 스트레스 테스트**는 "틀렸습니다"가 뜨는데 반례를 못 찾을 때 가장 확실한 무기다. 느려도 확실한 완전탐색 코드를 하나 더 짜서 결과를 대조한다.

---

## 8. 제출 전 체크리스트 ★★

- [ ] **디버그 `print`를 전부 지웠는가**
- [ ] 입력을 `sys.stdin.readline`으로 받고 있는가 (또는 한 번에 읽는가)
- [ ] 출력이 많다면 **모아서 한 번에** 출력하는가
- [ ] N이 최댓값일 때 **복잡도가 제한 시간 안에** 들어오는가
- [ ] **경계값**(N=1, 원소 1개, 값이 0·음수·최댓값)을 넣어봤는가
- [ ] 재귀를 쓴다면 `sys.setrecursionlimit`을 올렸는가
- [ ] 출력 형식(공백·개행·소수점 자릿수)이 문제 요구와 정확히 같은가
- [ ] 실수 연산 대신 **정수 연산으로 바꿀 수 있는지** 확인했는가

### 한 줄 요약
코딩테스트는 **stdin을 읽어 stdout으로 정확히 출력하는 단일 파이프라인**을 제한 시간·메모리 안에 완성하는 시험이고, 채점 결과(**시간 초과는 복잡도, 런타임 에러는 인덱스·재귀, 출력 초과는 남은 디버그 print**)는 그 자체가 진단서다. 파이썬은 **구현이 빠르고 오버플로가 없는 대신 C++보다 10~50배 느리므로**, 기본은 PyPy3로 제출하되 **깊은 재귀나 빡빡한 메모리 제한에서는 Python3**를 시도한다. 플래티넘 5까지는 **기초 → 자료구조 → 완전탐색 → 그래프 → DP → 고급** 순서로 한 주제씩 몰아 풀고, **30분에 유형만·60분에 아이디어만** 보는 규칙과 **백지 재구현·랜덤 스트레스 테스트**를 습관으로 만드는 것이 가장 빠른 길이다.
