# 입출력과 시간 관리 (Fast I/O in Python)

> 알고리즘 · 기초 · 학습내용: `input()`이 느린 진짜 이유와 `sys.stdin.readline`으로의 교체, `readline`의 개행 포함 함정과 `rstrip`, `sys.stdin.read().split()`으로 한 번에 읽기, 반복 `print`가 느린 이유와 `'\n'.join()`·`sys.stdout.write`로 모아 출력하기, `map(int, ...)` 패턴, 2차원 입력, EOF까지 읽기, `print(*arr)` 언패킹과 `sep`/`end`, 소수점 출력 서식, 문제 유형별 입력 파싱 패턴 모음

---

## 1. 왜 입출력부터 배우는가 ★★★

파이썬 코테에서 **시간 초과의 절반 이상은 알고리즘이 아니라 입출력 때문**이다. 입력이 10만 줄인 문제에서 `input()`을 쓰면 그것만으로 수 초가 날아간다. **알고리즘을 배우기 전에 입출력 템플릿을 손에 붙이는 게 순서다.**

```python
import sys
input = sys.stdin.readline          # 이 한 줄이 사실상 모든 문제의 시작

n = int(input())                    # 개수 N
arr = list(map(int, input().split()))
print(sum(arr))
```

> ★★★ **핵심**: `input = sys.stdin.readline` 한 줄을 습관으로 만든다. 다만 **`readline`은 개행 문자를 포함**하므로 문자열을 다룰 땐 `.rstrip()`이 필요하다(3절).

## 2. `input()`은 왜 느린가 ★★★

내장 `input()`은 편의 기능이 붙어 있어 호출마다 다음 일을 한다.

| 단계 | `input()` | `sys.stdin.readline()` |
|---|---|---|
| 프롬프트 처리 | 인자를 stdout에 쓰고 **flush** | 없음 |
| 줄 읽기 | 한 줄 읽기 | 한 줄 읽기 |
| 개행 처리 | **끝의 `\n`을 잘라서** 반환 | **`\n`을 포함**해 반환 |
| 인터랙티브 훅 | 터미널이면 readline 라이브러리 경유 | 없음 |
| 결과 | 편하지만 **호출당 오버헤드가 큼** | **거의 순수한 버퍼 읽기** |

즉 `input()`은 "사람과 대화하는 함수"고 `sys.stdin.readline()`은 "파일에서 한 줄 떼는 함수"다. 채점기는 파일로 입력을 밀어 넣으므로 후자가 맞다.

```python
import sys, time, io

N = 200000
data = ''.join(f'{i}\n' for i in range(N))           # 20만 줄짜리 가짜 입력

def bench(reader):                                   # reader 로 N줄을 읽어 합산
    t0 = time.perf_counter()
    total = sum(int(reader()) for _ in range(N))
    return total, time.perf_counter() - t0

sys.stdin = io.StringIO(data)
s1, t1 = bench(input)                                # 내장 input()
sys.stdin = io.StringIO(data)
s2, t2 = bench(sys.stdin.readline)                   # sys.stdin.readline

print(s1 == s2)                                      # True   결과는 동일
print(f'input()   : {t1:.3f}s')                      # 느림
print(f'readline(): {t2:.3f}s')                      # 대체로 수 배 빠름
```

> **함정**: `input = sys.stdin.readline`으로 **덮어쓴 뒤에는 `input()`에 프롬프트 문자열을 넣으면 안 된다.** `input('N: ')`처럼 쓰면 `readline`은 인자를 "버퍼 크기"로 해석해 엉뚱하게 동작한다. 코테에서는 프롬프트 자체가 필요 없다.

## 3. `readline()`의 개행 함정과 `rstrip()` ★★★

`readline()`은 줄 끝의 `\n`을 **그대로 붙여서** 준다. 숫자로 변환할 땐 `int()`가 공백·개행을 알아서 무시해서 문제가 없지만, **문자열로 쓰면 눈에 안 보이는 버그가 된다.**

```python
import sys, io

sys.stdin = io.StringIO('abc\n5\n')
input = sys.stdin.readline

s = input()                         # 'abc\n'  ← 개행이 붙어 있다!
print(repr(s))                      # 'abc\n'
print(len(s))                       # 4  (기대한 3이 아님)
print(s == 'abc')                   # False ← 비교가 깨진다

s = 'abc\n'.rstrip()                # 오른쪽 공백·개행 제거
print(repr(s), len(s), s == 'abc')  # 'abc' 3 True

n = int('5\n')                      # 숫자 변환은 개행을 알아서 무시
print(n + 1)                        # 6
```

| 입력 종류 | 권장 코드 |
|---|---|
| 정수 한 개 | `n = int(input())` |
| 정수 여러 개 (한 줄) | `a, b = map(int, input().split())` |
| **문자열 한 개** | `s = input().rstrip()` ★ |
| 문자열 여러 개 (한 줄) | `words = input().split()` (`split()`이 개행도 제거) |
| 문자 하나씩 리스트로 | `row = list(input().rstrip())` |

> ★★★ **핵심**: **`split()`은 개행까지 알아서 없애준다.** `rstrip()`이 반드시 필요한 건 **`split()` 없이 줄 전체를 문자열로 쓸 때**뿐이다. 격자(grid) 문제에서 `list(input())`으로 받으면 마지막 칸에 `'\n'`이 들어가 인덱스가 밀린다.

## 4. 한 번에 다 읽기 — `sys.stdin.read()` ★★★

입력 줄 수가 매우 많거나(수십만 줄), 줄 구분이 중요하지 않은 문제라면 **한 번의 시스템 호출로 전부 읽는 게 가장 빠르다.**

```python
import sys, io

sys.stdin = io.StringIO('3\n1 2 3\n4 5 6\n7 8 9\n')

data = sys.stdin.read().split()     # 전체를 읽고 공백·개행 기준으로 토큰화
idx = 0
n = int(data[idx]); idx += 1        # 첫 토큰이 N
total = 0
for _ in range(n):
    a, b, c = map(int, data[idx:idx + 3])
    idx += 3
    total += a + b + c
print(total)                        # 45
```

전부 정수인 입력이라면 **처음부터 정수 리스트로 만들어 두고 인덱스로 꺼내 쓰는** 패턴이 편하다.

```python
import sys, io

sys.stdin = io.StringIO('2\n10 20\n30 40\n')

it = iter(list(map(int, sys.stdin.read().split())))   # 이터레이터로 순차 소비
n = next(it)
for _ in range(n):
    a, b = next(it), next(it)
    print(a + b)                    # 30 / 70
```

| 방식 | 언제 쓰나 | 주의점 |
|---|---|---|
| `input = sys.stdin.readline` | **대부분의 문제** (기본형) | 문자열은 `rstrip()` |
| `sys.stdin.read().split()` | 입력이 **수십만 토큰 이상** | 메모리에 전부 올라감 |
| `sys.stdin` 순회(`for line in sys.stdin`) | **EOF까지** 줄 단위 처리 | 줄마다 `\n` 포함 |

## 5. 출력 — 반복 `print`가 느린 이유 ★★★

`print()`는 호출마다 **문자열 포맷팅 + 버퍼 쓰기 + 개행 처리**를 한다. 10만 번 호출하면 10만 번의 함수 호출 오버헤드가 그대로 쌓인다. **출력할 줄이 많으면 문자열 하나로 합쳐 한 번에 내보낸다.**

```python
import sys, time, io

n = 200000
buf = io.StringIO()
sys.stdout = buf                                     # 출력을 가로채서 시간만 측정
t0 = time.perf_counter()
for i in range(n):
    print(i)                                         # 느린 방식: 반복 print
slow = time.perf_counter() - t0

t0 = time.perf_counter()
sys.stdout.write('\n'.join(map(str, range(n))) + '\n')   # 빠른 방식: 모아서 한 번
fast = time.perf_counter() - t0

sys.stdout = sys.__stdout__                          # 원래 stdout 복구
print(f'print x {n}   : {slow:.3f}s')
print(f'join + write  : {fast:.3f}s')                # 보통 몇 배 빠르다
```

실전 템플릿은 이렇다.

```python
import sys

answers = []                        # 결과를 리스트에 모으고
for i in range(5):
    answers.append(i * i)
sys.stdout.write('\n'.join(map(str, answers)) + '\n')   # 마지막에 한 번만 출력
# 0 / 1 / 4 / 9 / 16 이 줄마다 하나씩 출력된다
```

| 출력 방식 | 속도 | 비고 |
|---|---|---|
| `for ...: print(x)` | 느림 | 줄 수가 1000 이하면 무방 |
| `print('\n'.join(map(str, ans)))` | 빠름 | **가장 자주 쓰는 형태** |
| `sys.stdout.write(...)` | 가장 빠름 | **개행을 직접 붙여야 함** |
| `print(*ans, sep='\n')` | 빠름 | 인자 언패킹, 리스트가 크면 메모리 주의 |

> **함정**: `sys.stdout.write`는 **개행을 자동으로 붙이지 않는다.** 마지막 `+ '\n'`을 빼먹으면 정답과 한 글자가 달라 "틀렸습니다"가 뜰 수 있다. 또한 `write`는 **문자열만** 받는다. `sys.stdout.write(3)`은 `TypeError`다.

## 6. 출력 서식 다루기 ★★

```python
arr = [3, 1, 4, 1, 5]
x = 1 / 3

print(*arr)                         # 3 1 4 1 5      (언패킹, 기본 구분자 공백)
print(*arr, sep=', ')               # 3, 1, 4, 1, 5  (구분자 지정)
print(*arr, sep='\n')               # 한 줄에 하나씩
print('a', 'b', end='')             # 개행 없이 이어 붙이기
print()                             # (개행만)
print(f'{x:.6f}', f'{x:.10f}')      # 0.333333 0.3333333333   소수점 자릿수 고정
print(f'{12:05d}', f'{3.0:g}')      # 00012 3   0 채우기 / 불필요한 0 제거
print(f'{255:b} {255:o} {255:x}')   # 11111111 377 ff
```

| 요구사항 | 코드 |
|---|---|
| 소수점 N자리 | `f'{x:.6f}'` |
| 정수를 자릿수 맞춰 | `f'{n:05d}'` 또는 `str(n).zfill(5)` |
| 리스트를 공백 구분 한 줄로 | `print(*arr)` 또는 `' '.join(map(str, arr))` |
| 리스트를 줄마다 하나씩 | `print('\n'.join(map(str, arr)))` |
| 2차원 배열 출력 | `print('\n'.join(' '.join(map(str, r)) for r in grid))` |

> **함정**: 실수 출력에서 `print(x)`를 그대로 쓰면 `0.30000000000000004`나 `1e-07` 같은 표기가 나올 수 있다. **문제가 자릿수를 지정했다면 반드시 `f'{x:.6f}'` 형태로 고정**한다.

## 7. 자주 쓰는 입력 파싱 패턴 모음 ★★★

### 7.1 첫 줄 N, 다음 N줄에 정수 하나씩

```python
import sys, io
sys.stdin = io.StringIO('3\n10\n20\n30\n')
input = sys.stdin.readline

n = int(input())
arr = [int(input()) for _ in range(n)]      # 리스트 컴프리헨션으로 N줄 읽기
print(arr, sum(arr))                        # [10, 20, 30] 60
```

### 7.2 첫 줄 N M, 다음 N줄에 M개씩 (2차원 배열)

```python
import sys, io
sys.stdin = io.StringIO('2 3\n1 2 3\n4 5 6\n')
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(n)]
print(grid)                                 # [[1, 2, 3], [4, 5, 6]]
print(grid[1][2])                           # 6  (행 1, 열 2)
```

### 7.3 문자 격자 (붙어 있는 숫자·문자)

```python
import sys, io
sys.stdin = io.StringIO('2\n101\n010\n')
input = sys.stdin.readline

n = int(input())
board = [list(map(int, input().rstrip())) for _ in range(n)]   # rstrip 필수!
print(board)                                # [[1, 0, 1], [0, 1, 0]]

sys.stdin = io.StringIO('2\n#.#\n.#.\n')
input = sys.stdin.readline
n = int(input())
maze = [input().rstrip() for _ in range(n)]                    # 문자열 그대로 두면 인덱싱 가능
print(maze, maze[0][1])                     # ['#.#', '.#.'] .
```

### 7.4 테스트 케이스 T개 반복

```python
import sys, io
sys.stdin = io.StringIO('3\n1 2\n3 4\n5 6\n')
input = sys.stdin.readline

t = int(input())
out = []
for tc in range(1, t + 1):
    a, b = map(int, input().split())
    out.append(f'Case #{tc}: {a + b}')      # 케이스 번호를 요구하는 형식도 흔하다
print('\n'.join(out))
# Case #1: 3
# Case #2: 7
# Case #3: 11
```

### 7.5 EOF까지 (줄 수를 안 알려주는 경우)

```python
import sys, io

sys.stdin = io.StringIO('1 2\n3 4\n5 6\n')
total = 0
for line in sys.stdin:                      # EOF까지 자동 순회
    if not line.strip():                    # 빈 줄 방어
        continue
    a, b = map(int, line.split())
    total += a + b
print(total)                                # 21
```

`while True` + `readline` 형태도 자주 쓴다. **`readline()`은 EOF에서 빈 문자열 `''`을 반환**한다는 점이 핵심이다.

```python
import sys, io
sys.stdin = io.StringIO('7\n8\n')
input = sys.stdin.readline

res = []
while True:
    line = input()
    if not line:                            # EOF면 '' → 종료
        break
    res.append(int(line))
print(res)                                  # [7, 8]
```

> **함정**: 줄바꿈 위치가 들쭉날쭉해 한 줄에 몇 개가 올지 모르면 **줄 단위로 읽지 말고 `sys.stdin.read().split()`으로 토큰 단위로** 읽는다. 줄 구분을 무시하므로 형식이 흔들려도 안전하다.

## 8. 시간 관리 — 코드가 아니라 시험 운영 ★★

실전 시험(보통 2~4문제, 90~180분)에서는 **알고리즘만큼 순서 전략이 점수를 가른다.**

| 단계 | 시간 배분 | 할 일 |
|---|---|---|
| 0~10분 | 전체 문제 **훑기** | 난이도 체감으로 **푸는 순서 결정** |
| 문제당 초반 5분 | 제약 조건 확인 | **N의 최대값 → 허용 복잡도 역산** |
| 설계 10~15분 | 종이/주석으로 흐름 | 자료구조 결정, 예제 손으로 추적 |
| 구현 | 한 번에 | 함수 단위로 쪼개고 중간 출력으로 확인 |
| 검증 | 5분 | **경계값**(N=1, 최댓값), 형식 확인 |

- **막히면 미련 없이 다음 문제로 넘어간다.** 한 문제에 40분 이상 붙잡히면 전체 점수가 무너진다.
- **부분 점수가 있는 시험이면 완전탐색이라도 제출**한다. 0점보다 낫다.
- 제출 직전 **디버그 출력 제거**와 **입출력 템플릿 적용**을 마지막 루틴으로 고정한다.

---

### 한 줄 요약
파이썬 코테에서 시간 초과의 가장 흔한 원인은 알고리즘이 아니라 입출력이므로, **`input = sys.stdin.readline`을 기본 템플릿으로 깔고 문자열은 `rstrip()`**, 토큰이 수십만 개면 **`sys.stdin.read().split()`으로 한 번에** 읽는다. 출력은 **반복 `print` 대신 `'\n'.join(map(str, ans))`으로 모아 한 번에** 내보내고, `sys.stdout.write`를 쓸 땐 **마지막 개행을 직접 붙이는 것**을 잊지 않는다. 소수점은 `f'{x:.6f}'`로 자릿수를 고정하고, 격자 입력은 **`list(input().rstrip())`** 으로 개행이 섞이지 않게 받는 것이 정석이다.
