# 그래프 표현과 순회 (Graph Representation & Traversal)

> 알고리즘 · 그래프 · 학습내용: 그래프 용어(정점·간선·방향/무방향·가중치·차수), 인접 리스트 vs 인접 행렬 비교, 파이썬 1-indexed 인접 리스트 관례, DFS 재귀와 재귀 깊이 한계, 스택 기반 반복 DFS, deque BFS, DFS/BFS 선택 기준, 연결 요소 세기, 격자 그래프와 dx·dy 방향 배열, 방문 처리 시점 함정

---

## 1. 용어부터 정확히 ★

| 용어 | 의미 |
|------|------|
| 정점 (vertex, node) | 그래프의 점. 보통 `N`개, `1..N`으로 번호를 매긴다 |
| 간선 (edge) | 정점을 잇는 선. 보통 `M`개 |
| 무방향 (undirected) | `a-b`가 양방향. 인접 리스트에 **양쪽 다 넣는다** |
| 방향 (directed) | `a→b`만 성립. 한쪽만 넣는다 |
| 가중치 (weighted) | 간선에 비용이 붙음. `(정점, 비용)` 튜플로 저장 |
| 차수 (degree) | 한 정점에 붙은 간선 수. 방향 그래프는 진입차수/진출차수로 나뉜다 |
| 희소 (sparse) | `M`이 `N`에 가까움. 실전 문제 대부분 |
| 밀집 (dense) | `M`이 `N²`에 가까움 |

**입력 크기부터 본다.** `N ≤ 500`이면 인접 행렬이나 `O(N³)`도 통과하고, `N ≤ 100,000`이면 인접 리스트에 `O(N+M)` 계열만 살아남는다. 문제의 제약이 곧 알고리즘 선택이다.

## 2. 인접 리스트 vs 인접 행렬 ★★★

| 항목 | 인접 리스트 | 인접 행렬 |
|------|-------------|-----------|
| 자료구조 | `[[] for _ in range(n+1)]` | `[[0]*(n+1) for _ in range(n+1)]` |
| 메모리 | `O(N + M)` | `O(N²)` |
| **간선 존재 확인** | `O(deg(v))` — 리스트를 훑어야 함 | **`O(1)`** — `adj[a][b]` |
| **한 정점의 이웃 순회** | **`O(deg(v))`** — 있는 것만 | `O(N)` — 없는 칸도 다 봄 |
| 전체 순회(DFS/BFS) | `O(N + M)` | `O(N²)` |
| 유리한 상황 | 희소 그래프 (실전 대부분) | 밀집 · `N` 작음 · 플로이드워셜 |

> ★★★ **핵심**: 코딩테스트 그래프 문제의 **95%는 인접 리스트**다. `N = 100,000`이면 인접 행렬은 100억 칸이라 메모리에서 즉사한다. 인접 행렬은 `N ≤ 500` 정도의 플로이드-워셜이나 "두 정점이 이어졌나"를 극단적으로 자주 묻는 문제에서만 쓴다.

```python
n, m = 5, 4
graph = [[] for _ in range(n + 1)]          # 1번 정점부터 쓰려고 n+1개를 만든다
edges = [(1, 2), (1, 3), (2, 4), (3, 5)]
for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)                       # 무방향이면 양쪽 다 넣는다
for v in range(1, n + 1):
    graph[v].sort()                          # 방문 순서를 고정해야 할 때만
# graph == [[], [2, 3], [1, 4], [1, 5], [2], [3]]
```

**`[[]] * (n+1)`은 절대 쓰면 안 된다.** 같은 리스트 객체 하나를 n+1번 참조하는 것이라 한 곳에 `append`하면 전부 바뀐다. 반드시 `[[] for _ in range(n+1)]` 컴프리헨션을 쓴다.

**1-indexed가 관례다.** 문제 입력이 대개 1번부터 주어지므로 `n+1` 크기로 잡고 0번 칸을 버리는 게 `-1` 변환을 매번 하는 것보다 훨씬 실수가 적다.

```python
adj = [[0] * (n + 1) for _ in range(n + 1)]  # 인접 행렬
for a, b in edges:
    adj[a][b] = adj[b][a] = 1

wgraph = [[] for _ in range(n + 1)]          # 가중치 그래프
for a, b, w in [(1, 2, 7), (1, 3, 3)]:
    wgraph[a].append((b, w))
    wgraph[b].append((a, w))
```

## 3. DFS 재귀와 재귀 깊이 한계 ★★★

```python
import sys
sys.setrecursionlimit(10 ** 6)      # 기본값 1000은 그래프 문제에서 100% 터진다

visited = [False] * (n + 1)
order = []

def dfs(v):
    visited[v] = True               # 들어오자마자 방문 표시
    order.append(v)
    for nxt in graph[v]:
        if not visited[nxt]:
            dfs(nxt)

dfs(1)                              # order == [1, 2, 4, 3, 5]
```

> **함정**: `sys.setrecursionlimit(10**6)`을 걸어도 안전하지 않다. 이건 **파이썬 인터프리터의 카운터 상한**만 올릴 뿐, **실제 C 스택 크기는 그대로**다. 정점이 일렬로 늘어선 그래프(사슬 모양)에서 깊이 10만을 넘어가면 파이썬이 `RecursionError` 대신 **세그폴트로 죽는다.** 채점 결과는 런타임 에러로 찍히고 원인을 찾기 어렵다.

> ★★★ **핵심**: **`N`이 10만 이상이면 재귀 DFS를 쓰지 말고 처음부터 반복 DFS로 짠다.** 재귀는 `N ≤ 10,000` 정도이거나 깊이가 얕다고 보장될 때만 쓴다. 습관을 반복 DFS 쪽으로 들여놓는 게 플래티넘 구간에서 훨씬 안전하다.

## 4. 스택 기반 반복 DFS ★★★

```python
def dfs_iter(start):
    visited = [False] * (n + 1)
    stack = [start]
    res = []
    while stack:
        v = stack.pop()
        if visited[v]:              # 스택엔 중복이 들어갈 수 있으므로 꺼낼 때 거른다
            continue
        visited[v] = True
        res.append(v)
        for nxt in reversed(graph[v]):   # 뒤집어 넣어야 재귀와 순서가 같아진다
            if not visited[nxt]:
                stack.append(nxt)
    return res

dfs_iter(1)                         # [1, 2, 4, 3, 5] — 재귀 결과와 동일
```

BFS와 달리 **반복 DFS는 방문 표시를 "꺼낼 때" 해야 한다.** 스택은 나중에 넣은 걸 먼저 꺼내므로, 넣을 때 표시해버리면 깊이 우선 순서가 깨진다. 대신 같은 정점이 스택에 여러 번 들어갈 수 있어 `if visited[v]: continue` 방어가 필수다.

`reversed()`는 재귀와 방문 순서를 맞추기 위한 것일 뿐, 순서가 상관없는 문제(연결 요소 세기 등)에서는 빼도 된다.

## 5. BFS (deque) ★★★

```python
from collections import deque

def bfs(start):
    dist = [-1] * (n + 1)           # -1이 곧 미방문 표시 겸 거리
    dist[start] = 0
    q = deque([start])
    while q:
        v = q.popleft()             # O(1). list.pop(0)은 O(N)이라 쓰면 안 된다
        for nxt in graph[v]:
            if dist[nxt] == -1:
                dist[nxt] = dist[v] + 1
                q.append(nxt)
    return dist

bfs(1)                              # [-1, 0, 1, 1, 2, 2]
```

> **함정**: `q = []` + `q.pop(0)`은 매번 원소 전체를 앞으로 당기므로 `O(N)`이다. `N = 100,000`이면 전체가 `O(N²)`이 되어 시간 초과가 난다. **BFS 큐는 무조건 `collections.deque`.**

`visited` 배열과 `dist` 배열을 따로 두지 말고, **`dist`를 `-1`로 초기화해 방문 표시까지 겸하게** 하면 코드가 짧아지고 버그도 준다.

## 6. DFS vs BFS 선택 기준 ★★★

| 상황 | 선택 | 이유 |
|------|------|------|
| **가중치 없는 그래프의 최단 거리** | **BFS** | 가까운 정점부터 층별로 퍼지므로 처음 도달한 순간이 최단 |
| 최소 이동 횟수 / 최소 변환 횟수 | BFS | 위와 같은 문제 |
| 연결 요소 개수·크기 | 둘 다 | 전부 훑기만 하면 됨 |
| 경로 존재 여부 | 둘 다 | |
| 모든 경로 열거 / 백트래킹 | DFS | 되돌아오며 상태를 복구하기 좋음 |
| 사이클 판별 (방향 그래프) | DFS | 방문 중/완료 상태 구분이 자연스러움 |
| 위상 정렬, SCC | DFS | 후위 순서(finish time)가 필요 |
| 재귀 깊이가 위험할 때 | BFS | 큐는 힙 메모리라 스택과 무관 |

> ★★★ **핵심**: **"최소 몇 번에?"라고 묻는 순간 BFS다.** DFS로 최단 거리를 구하려 들면 모든 경로를 다 봐야 해서 지수 시간이 된다. 반대로 **가중치가 있으면 BFS도 안 되고 다익스트라**로 넘어가야 한다.

## 7. 연결 요소 개수 세기 ★★

```python
from collections import deque

n2 = 6
g2 = [[] for _ in range(n2 + 1)]
for a, b in [(1, 2), (2, 5), (3, 4)]:
    g2[a].append(b)
    g2[b].append(a)

vis = [False] * (n2 + 1)
cnt = 0
for s in range(1, n2 + 1):          # 모든 정점을 시작점 후보로 한 번씩 훑는다
    if vis[s]:
        continue
    cnt += 1                        # 아직 안 봤다면 새로운 덩어리
    vis[s] = True
    q = deque([s])
    while q:
        v = q.popleft()
        for nxt in g2[v]:
            if not vis[nxt]:
                vis[nxt] = True
                q.append(nxt)
# cnt == 3  ({1,2,5}, {3,4}, {6})
```

핵심은 **바깥 `for` 루프**다. 그래프가 여러 덩어리로 쪼개져 있으면 한 점에서 시작한 탐색은 그 덩어리만 본다. **"탐색을 새로 시작한 횟수 = 연결 요소 개수"**이고, 이 패턴이 그대로 섬 개수 세기, 그룹 나누기, 유니온 파인드 대체로 쓰인다.

## 8. 격자(2차원) 그래프와 방향 배열 ★★★

지도, 미로, 섬 문제는 **격자 자체가 그래프**다. 간선을 만들지 않고 상하좌우 인접을 그때그때 계산한다.

```python
from collections import deque

board = [
    "11110",
    "11010",
    "11000",
    "00001",
]
N, M = len(board), len(board[0])
dx = (-1, 1, 0, 0)                  # 상 하 좌 우 (dx와 dy를 짝지어 읽는다)
dy = (0, 0, -1, 1)

def grid_bfs(sx, sy, vis):
    q = deque([(sx, sy)])
    vis[sx][sy] = True
    size = 0
    while q:
        x, y = q.popleft()
        size += 1
        for d in range(4):
            nx, ny = x + dx[d], y + dy[d]
            if not (0 <= nx < N and 0 <= ny < M):   # 1) 범위 밖 먼저 컷
                continue
            if vis[nx][ny] or board[nx][ny] == '0': # 2) 방문·벽 컷
                continue
            vis[nx][ny] = True                      # 3) 넣기 직전에 표시
            q.append((nx, ny))
    return size

vis = [[False] * M for _ in range(N)]
sizes = []
for i in range(N):
    for j in range(M):
        if board[i][j] == '1' and not vis[i][j]:
            sizes.append(grid_bfs(i, j, vis))
# sizes == [9, 1]  (덩어리 2개, 크기 9와 1)
```

> **함정**: **범위 검사를 방문/벽 검사보다 먼저** 해야 한다. 순서를 바꾸면 `board[-1][3]`처럼 파이썬 음수 인덱스가 반대편 칸을 조용히 읽어 정답이 미묘하게 틀린다. `IndexError`가 안 나서 더 무섭다.

대각선까지 포함하는 8방향은 방향 배열만 늘리면 된다.

```python
dx8 = (-1, -1, -1, 0, 0, 1, 1, 1)
dy8 = (-1, 0, 1, -1, 1, -1, 0, 1)
```

## 9. 방문 처리 시점 — BFS 최대 함정 ★★★

BFS에서 방문 표시를 **큐에 넣을 때** 할지 **큐에서 꺼낼 때** 할지가 정답과 시간 초과를 가른다.

```python
from collections import deque

cyc = [[], [2, 3], [1, 4], [1, 5], [2, 5], [3, 4]]   # 사이클이 있는 그래프

def bfs_push_mark(start):            # 정석: 큐에 "넣을 때" 방문 표시
    visited = [False] * len(cyc)
    visited[start] = True
    q = deque([start])
    pushed = 1
    while q:
        v = q.popleft()
        for nxt in cyc[v]:
            if not visited[nxt]:
                visited[nxt] = True  # 넣는 순간 표시 → 두 번 들어갈 수 없다
                q.append(nxt)
                pushed += 1
    return pushed

def bfs_pop_mark(start):             # 함정: 큐에서 "꺼낼 때" 방문 표시
    visited = [False] * len(cyc)
    q = deque([start])
    pushed = 1
    while q:
        v = q.popleft()
        if visited[v]:               # 이 방어 코드가 없으면 무한 루프
            continue
        visited[v] = True
        for nxt in cyc[v]:
            if not visited[nxt]:     # 아직 안 꺼낸 정점이라 계속 통과된다
                q.append(nxt)
                pushed += 1
    return pushed

# 정점 5개 / 넣을 때 표시: 5회 삽입 / 꺼낼 때 표시: 6회 삽입
```

> ★★★ **핵심**: **BFS는 큐에 넣는 순간 방문 표시한다.** 꺼낼 때 표시하면 같은 정점이 큐에 여러 번 쌓여 최악의 경우 큐 크기가 `O(M)`까지 부풀고, `if visited[v]: continue` 방어마저 빠지면 **무한 루프**에 빠진다. 반대로 **반복 DFS(스택)는 꺼낼 때 표시**한다 — 방향이 정반대라는 걸 몸에 익혀야 한다.

BFS에서 넣을 때 표시해도 되는 이유는, 가중치가 없으면 **어떤 정점에 처음 도달한 경로가 곧 최단 경로**이므로 나중에 더 짧은 경로가 나타날 일이 없기 때문이다. 가중치가 생기는 순간 이 전제가 깨지고, 그래서 다익스트라는 "꺼낼 때 확정"하는 구조를 쓴다.

## 10. 입력 속도 ★★

```python
import sys
input = sys.stdin.readline           # 간선 10만 줄 이상이면 필수

n, m = map(int, input().split())
graph = [[] for _ in range(n + 1)]
for _ in range(m):
    a, b = map(int, input().split())
    graph[a].append(b)
    graph[b].append(a)
```

**내장 `input()`은 매번 프롬프트 처리와 개행 정리를 해서 느리다.** 줄 수가 많으면 `sys.stdin.readline`으로 바꾸는 것만으로 시간 초과가 풀리는 경우가 흔하다. 단, `readline`은 개행 문자를 남기므로 문자열을 그대로 쓸 땐 `.rstrip()`이 필요하다. 출력도 많으면 `sys.stdout.write` 또는 `print('\n'.join(...))`로 한 번에 내보낸다.

---

### 한 줄 요약
그래프 문제는 **`[[] for _ in range(n+1)]` 인접 리스트로 시작해서**, **최단 거리면 `deque` BFS·완전 탐색이면 DFS**를 고른다. **`N`이 10만을 넘으면 재귀 DFS는 세그폴트 위험이므로 스택 기반 반복 DFS**로 짜고, **BFS는 큐에 넣을 때·반복 DFS는 꺼낼 때 방문 표시**한다는 정반대 규칙과 **격자에서 범위 검사를 가장 먼저** 한다는 순서를 손에 익히면 그래프 기본기는 끝난다.
