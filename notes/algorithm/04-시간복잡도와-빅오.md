# 시간복잡도와 빅오 (Time Complexity and Big-O)

> 알고리즘 · 기초 · 학습내용: 빅오 표기의 의미와 규칙, 대표 복잡도 O(1)~O(2^N)~O(N!)의 증가 속도, 입력 크기 N으로 허용 복잡도를 역산하는 표, "1초에 1억 연산" 기준과 파이썬의 상수 배 보정, 중첩 루프·재귀의 복잡도 계산 연습, 공간복잡도와 메모리 제한 계산, 자료구조별 연산 복잡도 종합표

---

## 1. 빅오 표기란 ★★★

빅오는 **입력 크기 N이 커질 때 연산 횟수가 어떤 비율로 늘어나는가**를 나타낸다. 정확한 연산 횟수가 아니라 **증가 추세**만 본다.

| 규칙 | 예 | 결론 |
|---|---|---|
| **상수는 버린다** | `3N + 5` | O(N) |
| **가장 큰 항만 남긴다** | `N² + 1000N` | O(N²) |
| **밑이 다른 로그는 같다** | `log₂N`, `log₁₀N` | O(log N) |
| 순차 실행은 **더한다** | O(N) 후 O(N log N) | O(N log N) |
| 중첩은 **곱한다** | O(N) 안에 O(log N) | O(N log N) |

**"N이 충분히 클 때 최악의 경우"** 를 기준으로 잡는다. 코테에서 중요한 건 딱 하나다 — **문제에 적힌 N의 최댓값을 넣었을 때 제한 시간 안에 끝나는가.**

> ★★★ **핵심**: 문제를 읽으면 **가장 먼저 제약 조건(N의 범위)을 본다.** N의 최댓값이 알고리즘을 결정한다. 코드를 짜기 전에 "이 N이면 O(N²)까지 되겠다"를 판단하는 게 코테 실력의 절반이다.

## 2. 대표 복잡도와 증가 속도 ★★★

| 복잡도 | 이름 | 대표 예시 | N=10 | N=1,000 | N=1,000,000 |
|---|---|---|---|---|---|
| O(1) | 상수 | 배열 인덱싱, 딕셔너리 조회, 수식 | 1 | 1 | 1 |
| O(log N) | 로그 | 이분 탐색, 힙 삽입/삭제 | 3 | 10 | 20 |
| O(N) | 선형 | 전체 순회, 합계, 최댓값 | 10 | 10³ | 10⁶ |
| O(N log N) | 선형로그 | **정렬**, 분할정복, 힙 정렬 | 33 | 10⁴ | 2×10⁷ |
| O(N²) | 이차 | 이중 루프, 인접 행렬 순회 | 100 | 10⁶ | 10¹² ✗ |
| O(N³) | 삼차 | 삼중 루프, 플로이드-워셜 | 1,000 | 10⁹ ✗ | ✗ |
| O(2^N) | 지수 | 부분집합 전체 탐색, 비트마스크 | 1,024 | ✗ | ✗ |
| O(N!) | 팩토리얼 | 순열 전체 탐색, 외판원 완전탐색 | 3,628,800 | ✗ | ✗ |

```python
import math

print(math.log2(1000))              # 9.965784284662087   → 약 10
print(math.log2(10 ** 6))           # 19.931568569324174  → 약 20
print(1000 * math.log2(1000))       # 9965.78...  N log N (N=1000)
print(2 ** 20, math.factorial(10))  # 1048576 3628800
print(f'{10 ** 6 * math.log2(10 ** 6):.3e}')   # 1.993e+07
```

**O(log N)이 얼마나 강한지 감을 잡는 게 중요하다.** N이 100만이어도 log₂N은 20이다. 즉 **이분 탐색은 100만 개에서 20번만 보면 끝난다.**

## 3. N으로 허용 복잡도 역산하기 ★★★

**이 표 하나가 이 문서의 핵심이다.** 문제의 N 최댓값을 보고 어떤 알고리즘까지 가능한지 즉시 판단한다.

| N의 최댓값 | 허용 복잡도 | 대표 접근법 |
|---|---|---|
| N ≤ 10 | **O(N!)** | 모든 순열 완전탐색, 백트래킹 |
| N ≤ 20 | **O(2^N)** | 부분집합 완전탐색, 비트마스크 DP |
| N ≤ 100 | O(N⁴) | 4중 루프도 가능 |
| N ≤ 500 | **O(N³)** | 플로이드-워셜, 3중 루프 DP |
| N ≤ 5,000 | **O(N²)** | 2중 루프 DP, LIS 기본형 |
| N ≤ 100,000 (10⁵) | **O(N log N)** | 정렬, 이분 탐색, 힙, 세그먼트 트리 |
| N ≤ 1,000,000 (10⁶) | O(N log N) ~ O(N) | 정렬은 아슬아슬, 선형 스캔은 안전 |
| N ≤ 10,000,000 (10⁷) | **O(N)** | 단순 순회·누적합만 |
| N ≥ 100,000,000 (10⁸) | **O(log N), O(1)** | 수식 유도, 이분 탐색, 거듭제곱 |

역방향으로도 외워둔다.

| 알고리즘 | 복잡도 | 실용 상한 N |
|---|---|---|
| 순열 전체 탐색 | O(N!) | 10 정도 |
| 부분집합 전체 탐색 | O(2^N) | 20~22 |
| 비트마스크 DP | O(2^N · N) | 18~20 |
| 플로이드-워셜 | O(V³) | V ≤ 400~500 |
| 다익스트라(힙) | O(E log V) | E ≤ 수십만 |
| 정렬 | O(N log N) | N ≤ 수십만~100만 |
| 에라토스테네스의 체 | O(N log log N) | N ≤ 10⁶~10⁷ |

> ★★★ **핵심**: **N ≤ 20이면 2^N을 의심하고, N ≤ 500이면 3중 루프를 의심하고, N이 10만이면 정렬이나 이분 탐색을 의심한다.** 문제 설정자는 N의 범위로 "이 알고리즘을 쓰라"는 힌트를 준 것이다.

## 4. "1초에 1억 연산"과 파이썬 보정 ★★★

경험칙으로 **C/C++은 1초에 약 1억(10⁸) 회의 단순 연산**을 처리한다고 본다. **파이썬은 여기서 10~50배를 나눠야 한다.**

| 언어 | 1초당 단순 연산 (경험칙) |
|---|---|
| C / C++ | 약 10⁸ |
| Java | 약 5×10⁷ |
| **Python (CPython)** | **약 10⁶ ~ 2×10⁷** |
| **PyPy3** | 약 10⁷ ~ 5×10⁷ |

```python
import time

t0 = time.perf_counter()
total = 0
for i in range(10 ** 7):            # 1천만 번의 단순 덧셈
    total += i
elapsed = time.perf_counter() - t0
print(total)                        # 49999995000000
print(f'순수 for 루프 10^7회: {elapsed:.2f}s')

t0 = time.perf_counter()
total2 = sum(range(10 ** 7))        # 같은 일을 내장 함수로 (C 레벨 실행)
elapsed2 = time.perf_counter() - t0
print(total == total2)              # True
print(f'sum(range) 10^7:    {elapsed2:.2f}s')   # 몇 배 빠르다
```

> ★★★ **핵심**: 파이썬에서 **같은 복잡도라도 "파이썬 레벨 루프"보다 "C 레벨 내장 함수"가 훨씬 빠르다.** `sum`, `max`, `min`, `sorted`, `''.join`, `map`, 리스트 컴프리헨션은 전부 C로 구현되어 있다. **직접 for를 도는 대신 내장 함수로 밀어 넣는 것**이 파이썬 상수 최적화의 1순위다.

| 파이썬에서 느린 것 | 대안 |
|---|---|
| `for` 안에서 `input()` | `sys.stdin.readline` / `read().split()` |
| 반복 `print` | `'\n'.join(...)` 한 번에 |
| `s += 문자열` 누적 | 리스트에 모아 `''.join()` |
| `list.pop(0)` | `collections.deque` |
| `x in list` | `set` / `dict` |
| 파이썬 for 누적 합 | `sum()`, `itertools.accumulate` |
| 깊은 재귀 | 반복문 + 명시적 스택 |
| 전역 변수 참조가 많은 루프 | 지역 변수에 담아 사용 |

## 5. 복잡도 계산 연습 ★★

### 5.1 중첩 루프

```python
n = 5

cnt = 0
for i in range(n):
    for j in range(n):
        cnt += 1
print(cnt)                          # 25   → O(N^2)

cnt = 0
for i in range(n):
    for j in range(i + 1, n):       # 삼각형 모양: N(N-1)/2 회
        cnt += 1
print(cnt, n * (n - 1) // 2)        # 10 10  → 상수를 버리면 여전히 O(N^2)

cnt = 0
i = 1
while i < 1000:                     # 매번 2배 → log2(1000) 회
    cnt += 1
    i *= 2
print(cnt)                          # 10   → O(log N)

cnt = 0
for i in range(n):
    j = 1
    while j < 1000:                 # O(N) 안에 O(log N)
        cnt += 1
        j *= 2
print(cnt)                          # 50   → O(N log N)
```

> **함정**: `for j in range(i + 1, n)` 처럼 삼각형 모양이어도 **O(N²)** 다. 상수 1/2는 버린다. "절반만 도니까 괜찮겠지"는 틀린 판단이며, N=10⁵면 여전히 5×10⁹로 터진다.

### 5.2 재귀

재귀의 복잡도는 **(호출 횟수) × (호출 1회당 비용)** 이다.

```python
import sys
sys.setrecursionlimit(10 ** 6)

calls = 0

def fib_naive(n):                   # 가지가 2개씩 벌어짐 → O(2^N)
    global calls
    calls += 1
    if n <= 1:
        return n
    return fib_naive(n - 1) + fib_naive(n - 2)

print(fib_naive(20), calls)         # 6765 21891   호출이 폭발한다

from functools import lru_cache

@lru_cache(maxsize=None)            # 메모이제이션 → 각 n을 한 번만 계산
def fib_memo(n):
    if n <= 1:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

print(fib_memo(100))                # 354224848179261915075   → O(N)

def binary_search_depth(lo, hi):    # 매번 절반 → O(log N)
    if lo >= hi:
        return 0
    mid = (lo + hi) // 2
    return 1 + binary_search_depth(lo, mid)

print(binary_search_depth(0, 1024)) # 11
```

| 재귀 형태 | 복잡도 |
|---|---|
| `f(n-1)` 한 번 호출 | O(N) |
| `f(n-1)` **두 번** 호출 | **O(2^N)** |
| `f(n/2)` 한 번 호출 | O(log N) |
| `f(n/2)` 두 번 + O(N) 병합 | **O(N log N)** (병합 정렬) |
| 메모이제이션한 DP | **(상태 개수) × (상태당 비용)** |

> ★★★ **핵심**: **DP의 복잡도는 "상태의 개수 × 전이 비용"** 이다. 상태가 `dp[i][j]`이고 각 상태에서 k번 반복하면 O(N·M·K)다. 이 공식만 있으면 DP 문제에서 시간 초과 여부를 코드 짜기 전에 판단할 수 있다.

## 6. 공간복잡도와 메모리 제한 ★★

메모리 제한은 보통 **128MB ~ 512MB**다. 파이썬은 객체 오버헤드가 커서 **C++ 기준으로 계산하면 안 된다.**

```python
import sys

print(sys.getsizeof(1))                     # 28       작은 정수 객체 하나
print(sys.getsizeof(10 ** 100))             # 72       자릿수가 크면 더 큼
print(sys.getsizeof([0] * 10 ** 6))         # 8000056  포인터 배열만 약 8MB

arr = [i for i in range(10 ** 6)]           # 서로 다른 정수 100만 개
ptr_mb = sys.getsizeof(arr) / 1024 / 1024
obj_mb = sum(sys.getsizeof(x) for x in arr) / 1024 / 1024
print(f'포인터: {ptr_mb:.1f}MB, 정수 객체: {obj_mb:.1f}MB, 합계: {ptr_mb + obj_mb:.1f}MB')
# 포인터: 7.6MB, 정수 객체: 26.7MB, 합계: 34.3MB
```

| 자료구조 | 원소 100만 개 기준 대략 메모리 |
|---|---|
| `[0] * 10**6` (같은 객체 참조) | 약 **8MB** |
| `list(range(10**6))` (서로 다른 정수) | 약 **35MB** |
| 2차원 `[[0]*1000 for _ in range(1000)]` | 약 **8MB + 리스트 오버헤드** |
| `set` / `dict` (원소 100만) | 약 **50~80MB** ★ |
| `array.array('i', ...)` (정수 100만) | 약 **4MB** |

```python
import sys, array

a = array.array('i', range(10 ** 6))        # C 배열처럼 4바이트 정수로 저장
print(a.itemsize)                           # 4
print(f'{sys.getsizeof(a) / 1024 / 1024:.1f}MB')   # 약 4MB
print(a[999999])                            # 999999
```

| 상황 | 대응 |
|---|---|
| 2차원 방문 배열이 너무 큼 | `bytearray`나 비트마스크로 압축 |
| 정수 배열이 메모리를 먹음 | `array.array('i', ...)` 사용 |
| 큰 리스트를 한 번만 순회 | 리스트 대신 **제너레이터** |
| 재귀가 메모리를 먹음 | 반복문 + 명시적 스택으로 변환 |

> **함정**: `dict`와 `set`은 해시 테이블이라 **원소당 메모리가 리스트의 5~10배**다. 인덱스가 0~N 범위의 정수라면 **`set` 대신 `[False] * (N+1)` 리스트**를 쓰는 게 메모리·속도 모두 유리하다.

## 7. 자료구조별 연산 복잡도 종합표 ★★★

| 연산 | `list` | `deque` | `dict` | `set` | `heapq`(list) |
|---|---|---|---|---|---|
| 끝에 추가 | O(1)* | O(1) | — | — | `heappush` O(log N) |
| 끝에서 제거 | O(1) | O(1) | — | — | — |
| **앞에 추가/제거** | **O(N)** | **O(1)** | — | — | — |
| 인덱스 접근 `a[i]` | O(1) | **O(N)** | — | — | O(1) (내부 리스트) |
| 키/값 조회 | O(N) | O(N) | **O(1)** 평균 | **O(1)** 평균 | — |
| 삽입 (키) | O(N) (insert) | — | **O(1)** 평균 | **O(1)** 평균 | O(log N) |
| 삭제 (값) | O(N) | O(N) | **O(1)** 평균 | **O(1)** 평균 | `heappop` O(log N) |
| **최솟값 조회** | O(N) | O(N) | O(N) | O(N) | **O(1)** (`h[0]`) |
| 정렬 | O(N log N) | — | — | — | `heapify` **O(N)** |
| 순회 | O(N) | O(N) | O(N) | O(N) | O(N) |

\* `append`는 분할상환(amortized) O(1)

```python
from collections import deque
import heapq

dq = deque([1, 2, 3])
dq.appendleft(0)                    # 앞 삽입 O(1)
dq.append(4)                        # 뒤 삽입 O(1)
print(dq, dq.popleft(), dq.pop())   # deque([0, 1, 2, 3, 4]) 0 4

h = [5, 1, 4, 2]
heapq.heapify(h)                    # O(N) 으로 힙 구성
print(h[0])                         # 1   최솟값 조회 O(1)
heapq.heappush(h, 0)                # O(log N)
print(heapq.heappop(h))             # 0   최솟값 제거 O(log N)

d = {'a': 1}
s = {1, 2, 3}
print('a' in d, 2 in s)             # True True   둘 다 평균 O(1)
```

### 7.1 선택 가이드

| 필요한 것 | 자료구조 |
|---|---|
| 순서 있는 목록, 인덱스 접근 | `list` |
| **양끝 삽입·삭제 (BFS 큐, 슬라이딩 윈도우)** | **`deque`** |
| 빠른 포함 검사·중복 제거 | `set` |
| 키-값 매핑, 카운팅 | `dict`, `Counter`, `defaultdict` |
| **항상 최솟값·최댓값을 꺼내야 함** | **`heapq`** |
| 정렬 상태를 유지하며 삽입·탐색 | `bisect` + `list` |

### 한 줄 요약
빅오는 정확한 연산 횟수가 아니라 **N이 커질 때의 증가 추세**이며, 코테에서의 쓸모는 오직 하나 — **문제에 적힌 N의 최댓값으로 쓸 알고리즘을 역산하는 것**이다(**N≤20이면 O(2^N), N≤500이면 O(N³), N≤5000이면 O(N²), N≤10⁵이면 O(N log N), N≤10⁷이면 O(N)**). C++이 1초에 약 1억 연산이라면 **파이썬은 그 10~50분의 1**이므로 보수적으로 잡아야 하고, 같은 복잡도라도 **파이썬 for 루프보다 `sum`·`sorted`·`join` 같은 C 레벨 내장 함수가 훨씬 빠르다.** 메모리도 마찬가지여서 **정수 100만 개 리스트가 약 35MB, `set`/`dict`는 그 두 배**이므로, 인덱스가 정수 범위라면 `set` 대신 리스트 방문 배열을 쓰는 게 정석이다.
