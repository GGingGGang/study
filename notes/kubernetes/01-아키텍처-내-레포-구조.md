# 내 레포 구조 — oci-always-free-k8s 플랫폼 (Repository Architecture & Governance)

> 쿠버네티스 · 아키텍처 기준/내 레포 · 학습내용: `oci-always-free-k8s` 플랫폼의 실제 구조(네트워크·OKE·메시·게이트웨이·TLS·DNS·네임스페이스·RBAC), 이 플랫폼 위 MSA 앱 설계·배포 규약, 그리고 저장소 거버넌스 규범(MUST/SHOULD)

---

이 문서는 일반 아키텍처를 `oci-always-free-k8s` 저장소가 **구체적으로 어떻게 구현하는가**를 정확히 기술한다. 모든 수치·이름은 실제 코드 기준이고, 규칙은 **MUST/SHOULD**로 명문화한다. (이 문서는 다른 노트 파일을 참조하지 않고 자체 완결한다.)

## 1. 전체 그림 (상위 구조)

```
                         [ 인터넷 클라이언트 ]
                                  │ 80/443
                          [ Internet Gateway ]
                                  │
        ┌──────────────── VCN 10.0.0.0/16 ────────────────────┐
        │                                                       │
        │   subnet-public 10.0.1.0/28 (public)                  │
        │     └─ OCI NLB (flexible, L4 passthrough, src 보존)    │
        │             │ NodePort 30000-32767                    │
        │   subnet-workers 10.0.102.0/24 (private)              │
        │     └─ Node Pool: VM.Standard.A1.Flex ×2              │
        │          (Istio envoy Gateway 파드 → ztunnel → 앱)     │
        │             │                                          │
        │   subnet-oke-api 10.0.0.0/28 (public)  ← OKE API       │
        │   subnet-db 10.0.201.0/28 (private)    ← HeatWave MySQL │
        │                                                        │
        │   NAT GW(워커 아웃바운드) · Service GW(OCI 내부)         │
        └────────────────────────────────────────────────────────┘
```

- **클러스터**: OKE `BASIC_CLUSTER`, CNI **Flannel Overlay**, 런타임 **containerd**, Kubernetes `v1.34.2`.
- **메시**: **Istio Ambient**(istiod + ztunnel, 사이드카 없음).
- **노출**: **Gateway API**(`gatewayClassName: istio`) → Istio가 envoy 게이트웨이와 **OCI NLB**를 자동 프로비저닝.
- **TLS**: **cert-manager + Let's Encrypt(DNS-01)**, **DNS**: **external-dns + Cloudflare**. apex 도메인 `ggang.cloud`.

## 2. 네트워크 구조 (Terraform `networking` 모듈)

### (1) VCN·서브넷

| 서브넷 | CIDR | 유형 | 용도 |
|--------|------|------|------|
| `subnet-oke-api` | `10.0.0.0/28` | public | OKE API 엔드포인트 |
| `subnet-public` | `10.0.1.0/28` | public | NLB(로드밸런서) |
| `subnet-workers` | `10.0.102.0/24` | private | 워커 노드 풀 |
| `subnet-db` | `10.0.201.0/28` | private | HeatWave MySQL |

- VCN CIDR: `10.0.0.0/16`. 클러스터 내부 **Pod CIDR `10.244.0.0/16`**, **Service CIDR `10.96.0.0/16`**(Flannel 오버레이).

### (2) 게이트웨이·라우팅
- **Internet Gateway**: public 서브넷의 `0.0.0.0/0` 아웃바운드/인바운드.
- **NAT Gateway**: 워커(private)의 아웃바운드(이미지 풀·업데이트)용. 외부에서 워커로 직접 진입 불가.
- **Service Gateway**: 워커·DB가 OCI 내부 서비스(오브젝트 스토리지·모니터링 등)에 **인터넷을 거치지 않고** 접근. **db 서브넷은 인터넷 경로가 없다**(Service GW만).

> ★ **설계 의도**: 워커·DB를 **private**로 두고, 진입은 오직 **public 서브넷의 NLB**를 통해서만. DB는 인터넷에서 완전히 격리된다.

## 3. 보안 계층 — Security List + NSG (이중 방어)

OCI는 **Security List**(서브넷 단위)와 **NSG**(리소스 단위)를 함께 쓴다.

- **인터넷 인그레스**: NLB 서브넷에 **TCP 80, 443만** `0.0.0.0/0` 허용.
- **LB→워커**: NodePort `30000-32767`, 헬스체크 `10256`.
- **API 통신**: 워커↔OKE API `6443`(kube-api), `12250`(컨트롤플레인↔kubelet).
- **DB**: 워커→MySQL `3306`만(다른 곳에서 접근 불가).
- **NSG `nsg-public-access`**: source = `var.allowed_cidr`(관리자 IP). OKE API 엔드포인트와 NLB에 부착되어, Security List가 넓게 열려 있어도 **두 번째 관문**으로 관리 접근을 좁힌다.

- **MUST**: 새 외부 노출 포트를 열 때 Security List와 NSG **양쪽**을 함께 검토한다.
- **SHOULD**: 관리/민감 엔드포인트는 `allowed_cidr`(NSG)로 출발지를 제한한다.

## 4. OKE 클러스터·노드 (Terraform `oke` 모듈)

- **클러스터 타입**: `BASIC_CLUSTER`. **CNI**: `FLANNEL_OVERLAY`. **K8s**: `v1.34.2`(변수 기본값).
- **API 엔드포인트**: public IP + `nsg-public-access` 부착.
- **노드 풀**: `VM.Standard.A1.Flex`(ARM Ampere), **2 OCPU / 12 GB × 2 노드 = 4 OCPU / 24 GB**, 이미지 Oracle Linux 8 ARM64, 노드 라벨 `pool=arm-workers`.
- **노드 부트스트랩**(`node_pool_init.sh`): 루트 FS 확장(`oci-growfs`) 후 OKE 메타데이터의 init 스크립트를 받아 실행.

- **MUST**: 노드/클러스터 변경은 Terraform으로만(콘솔 수동 변경 금지).
- **SHOULD**: 워크로드 합계 자원이 노드 풀 용량(4 OCPU / 24 GB)을 넘지 않도록 requests를 설계한다.

## 5. 데이터베이스 (Terraform `database` 모듈)
- **HeatWave MySQL**, 스토리지 **50 GB**, **db 서브넷(private)**, 관리자 비밀번호는 `var.db_admin_password`(tfvars, git 미포함).
- 출력: `heatwave_ip`, `heatwave_port`(앱 접속 문자열 구성용).
- **MUST**: DB는 워커 서브넷에서만 `3306`으로 접근. 앱은 **자기 스키마/계정**으로 접근하고 자격증명은 시크릿으로 주입한다.

## 6. 노출 경로 — Gateway API + Istio + NLB

### (1) 트래픽 흐름
```
인터넷 → Internet GW → OCI NLB(subnet-public, flexible, L4 passthrough, preserve-source)
   → NodePort(30000-32767) → Istio envoy Gateway 파드(istio-system)
   → TLS Terminate(443) → HTTPRoute 매칭 → app 서비스(:포트)
내부 서비스 간: ztunnel이 자동 mTLS
```

### (2) Gateway 리소스 (`public-gateway`, namespace `istio-system`, `gatewayClassName: istio`)
- 리스너 3개: **http(80)** / **https-apex(`ggang.cloud`)** / **https-wildcard(`*.ggang.cloud`)**.
- HTTPS는 `mode: Terminate`, 인증서 시크릿 `public-wildcard-tls` 참조.
- **apex와 wildcard 리스너를 분리**하는 이유: 와일드카드 인증서는 apex(`ggang.cloud`)에 매칭되지 않으므로 둘 다 명시 필요(같은 시크릿 참조).
- **http→https 308 리다이렉트**는 별도 HTTPRoute(`sectionName: http`)로 80 리스너에만 적용.
- Gateway에 NLB 어노테이션(`load-balancer-type: nlb`, `flexible`, `preserve-source: true`)을 달면 **OCI Cloud Controller가 NLB를 자동 생성**한다.

```yaml
# (요약) public-gateway 리스너 구조
listeners:
  - {name: http,           port: 80,  protocol: HTTP}
  - {name: https-apex,     port: 443, protocol: HTTPS, hostname: "ggang.cloud",   tls: {mode: Terminate, certificateRefs: [public-wildcard-tls]}}
  - {name: https-wildcard, port: 443, protocol: HTTPS, hostname: "*.ggang.cloud", tls: {mode: Terminate, certificateRefs: [public-wildcard-tls]}}
```

- **MUST**: 새 서비스 노출은 **HTTPRoute**로 `public-gateway`에 붙인다(직접 LoadBalancer Service 남발 금지 — NLB는 게이트웨이가 공유).
- **MUST**: 외부 호스트는 `*.ggang.cloud` 하위로, HTTP 접근은 308로 HTTPS 리다이렉트.
- **SHOULD**: Gateway API CRD는 Istio와 **분리 설치**(표준 CRD `v1.5.0`, server-side apply)해 버전 수명주기를 분리한다.

## 7. 서비스 메시 — Istio Ambient

- Helm 차트 `~1.29.0`, **profile `ambient`**: istiod(컨트롤플레인, replica 1) + **istio-cni(chained)** + **ztunnel**(노드별 L4 mTLS 프록시). **사이드카 주입 없음**.
- DNS capture 활성(`ISTIO_META_DNS_CAPTURE=true`).
- **L7 정책이 필요할 때만** waypoint 프록시를 네임스페이스/서비스 단위로 추가(기본은 ztunnel의 L4만).
- 사이드카 방식보다 RAM이 적게 든다(파드당 프록시 없음, 노드당 ztunnel 공유) — Ambient를 채택하는 일반 근거.

- **MUST**: `app` 네임스페이스 워크로드 간 통신은 **ztunnel mTLS**로 암호화한다(평문 통신 금지).
- **SHOULD**: 세밀한 L7 인가/라우팅이 필요한 서비스에만 **waypoint**를 둔다(불필요한 waypoint 남발 금지).

## 8. TLS — cert-manager + Let's Encrypt (DNS-01)

- Helm `~1.18.0`, `enableGatewayAPI: true`.
- **ClusterIssuer 2개**: `letsencrypt-staging`(테스트), `letsencrypt-prod`(운영). 둘 다 ACME **DNS-01(Cloudflare)** 솔버.
- **Certificate `public-wildcard`**(namespace `istio-system`): CN `ggang.cloud`, SAN `*.ggang.cloud`, **ECDSA P-256**, 유효 90일, **만료 15일 전(75%) 자동 갱신**, 시크릿 `public-wildcard-tls`.
- DNS-01 재귀 네임서버 `1.1.1.1:53, 8.8.8.8:53` 고정(CoreDNS 캐시 우회).

- **MUST**: 운영 인증서는 `letsencrypt-prod`로 발급한다. 시험·디버깅은 `letsencrypt-staging`(레이트리밋 회피).
- **SHOULD**: 와일드카드가 필요하므로 **DNS-01**을 쓴다(HTTP-01은 와일드카드 불가).

## 9. DNS — external-dns + Cloudflare

- Helm `~1.16.0`, provider **cloudflare**, 소스 **`gateway-httproute` + `gateway-grpcroute`**(Ingress/Service 소스는 미사용).
- **policy `sync`**: HTTPRoute를 지우면 DNS 레코드도 삭제.
- **registry `txt`**, `txtOwnerId: oci-oke`: TXT 레코드로 **소유권**을 표시해 다른 컨트롤러/클러스터의 레코드를 건드리지 않음.
- `domainFilter: ggang.cloud`, proxied=false(DNS-only).

- **MUST**: 외부 호스트명은 **HTTPRoute의 hostname**으로 선언한다(external-dns가 자동으로 Cloudflare에 A 레코드 생성). 콘솔에서 수동 DNS 추가 금지.

## 10. 네임스페이스·Pod 보안 (PSA)

| 네임스페이스 | PSA | 용도 |
|--------------|-----|------|
| `app` | **restricted** | 사용자 워크로드(MSA 앱). 비루트·읽기전용FS 강제 |
| `cicd` | baseline(enforce) / restricted(warn) | Jenkins·ArgoCD |
| `build` | **privileged** | 이미지 빌드(Kaniko, 루트 권한 필요) |
| `istio-system`,`cert-manager`,`external-dns` | (미적용) | 인프라 컴포넌트(ztunnel/cni 등 권한 필요) |
| `monitoring`,`vault` | (예정) | 관측성 / 시크릿 관리 |

- **MUST**: MSA 앱은 **`app` 네임스페이스(restricted)** 에 배포한다 → 컨테이너는 **비루트·읽기전용 루트FS·권한 최소화**를 만족해야 한다.
- **MUST**: 빌드(루트 권한)는 격리된 **`build`** 에서만. 앱/CI 네임스페이스에서 특권 파드 금지.

## 11. RBAC 규범

- **MUST**: `cluster-admin` **금지**(상시).
- **SHOULD**: **Role 우선**, ClusterRole은 클러스터 범위 리소스/다중 NS 부여에만.
- **SHOULD**: 시크릿 접근은 `resourceNames`로 **특정 시크릿만** 허용.
- **SHOULD**: API를 호출하지 않는 파드는 `automountServiceAccountToken: false`.
- **SHOULD**: RBAC 매니페스트는 해당 컴포넌트 폴더에 함께 둔다(중앙집중 X). aggregation 라벨 사용 자제.

## 12. 이 플랫폼 위 MSA 앱 설계·배포 규약 (요약 체크리스트)

새 마이크로서비스를 올릴 때 지켜야 할 규범:

1. **배포 위치**: `app` 네임스페이스(restricted PSA 충족: 비루트·읽기전용FS). (MUST)
2. **노출**: 외부 노출이 필요하면 `*.ggang.cloud` 호스트로 **HTTPRoute** 작성 → `public-gateway` 부착. http는 308 리다이렉트. (MUST)
3. **서비스 간 통신**: 클러스터 내부 통신은 ztunnel **mTLS** 전제. L7 인가/라우팅 필요 시 waypoint + AuthorizationPolicy. (MUST/SHOULD)
4. **회복탄력성**: 동기 호출에 타임아웃·재시도(멱등 한정)·서킷브레이커를 **메시 레벨**로 적용. (SHOULD)
5. **설정/시크릿**: 설정은 ConfigMap, 비밀은 Secret으로 주입. **Git에 평문 시크릿 금지**(향후 OpenBao 이관). (MUST)
6. **DB**: HeatWave MySQL에 **자기 계정/스키마**로 접근, 자격증명은 시크릿. (MUST)
7. **관측성**: liveness/readiness 프로브 + RED 지표 노출, 로그는 JSON stdout. (MUST)
8. **배포 방식**: 매니페스트는 Git, **ArgoCD가 동기화**(수동 kubectl apply로 운영 변경 금지). (MUST)
9. **이미지**: GHCR에 푸시, **불변 태그/다이제스트**로 참조(`latest` 금지). (MUST)
10. **자원**: requests/limits를 명시해 노드 용량(4 OCPU/24 GB) 안에서 스케줄되게. (SHOULD)

## 13. 저장소 거버넌스 (컨벤션)

- **README 5섹션**: 모든 컴포넌트 README는 **Prerequisites / Setup / Verification / Decisions / Notes** 구조. (MUST)
- **시크릿 취급**: 시크릿은 `kubectl create secret`로 **런타임 주입**, git에는 없음. gitignore에 `*.env`·`*.tfvars`·`*.pem`·`*.ppk`·`*.pub`·`*.tfstate*` 등. (MUST)
- **하드코딩 값**: apex 도메인 `ggang.cloud`, 관리자 이메일 `admin@ggang.cloud`는 코드에 하드코딩하고, 포크 시 **`init.sh <도메인>`** 으로 일괄 치환. (규약)
- **Helm 버전 핀**: `~X.Y.0`(틸드) — 패치는 자동, 마이너 업은 명시적 변경. (MUST)
- **설치 순서 의존성**: namespaces → gateway-api(CRD) → istio(base/istiod/cni/ztunnel) → external-dns → cert-manager → istio gateway(HTTPS). HTTPS 리스너는 Certificate가 `Ready`된 뒤 적용. (MUST)
- **배포 부트스트랩**: 인프라(`kubernetes/infra/`)는 수동 helm/kubectl로 콜드스타트, **ArgoCD는 앱만 배포(자기 자신 부트스트랩 X)**. (규약)

### 한 줄 요약
`oci-always-free-k8s`는 VCN(`10.0.0.0/16`) 위 **public NLB → Istio(Ambient) Gateway → HTTPRoute → `app` 워크로드**로 트래픽을 흘리고, **private 워커·격리된 DB**, **Security List+NSG 이중 방어**, **cert-manager(DNS-01)+external-dns(Cloudflare)** 로 TLS·DNS를 자동화하며, MSA 앱은 *restricted 네임스페이스·mTLS·HTTPRoute 노출·GitOps(ArgoCD)·불변 이미지·시크릿 분리* 라는 MUST/SHOULD 규범 아래 배포한다.
