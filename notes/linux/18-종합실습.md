# 18 — 종합 실습: 로컬 HTTP 서비스를 운영하고 복구하기

> 학습 목표: 실행 계정·파일 권한·리스닝·systemd·로그·백업을 하나의 서비스로 연결한다.

## 1. 결과물과 준비 조건

**개인 Ubuntu VM**에서만 수행한다. systemd가 PID 1이고 sudo, python3, curl이 있어야 한다. 이 실습은 Python 개발용 HTTP 서버를 **127.0.0.1:18081**에만 띄운다. 인증이나 TLS를 갖춘 공개 웹 서버를 만드는 과정이 아니다.

완료 기준은 서비스 running, curl 200과 본문 일치, journal 요청 기록, 백업 복원 일치, 장애 두 가지의 복구다. 각 단계가 성공했는지 확인하고 다음으로 진행한다. 이번 이름과 경로가 이미 있다면 덮어쓰지 말고 다른 이름으로 전체 예제를 맞춘다.

```bash
ps -p 1 -o comm=
command -v python3
command -v curl
systemctl cat linux-textbook-web.service
ls -ld /srv/linux-textbook-demo
ss -lnt '( sport = :18081 )'
```

systemctl과 ls에서 대상이 없다는 오류는 최초 확인에서는 예상된다. 포트는 비어 있어야 한다. 일반 Ubuntu에서 python3가 `/usr/bin/python3`인지 확인한다.

## 2. 데이터와 권한 준비

```bash
sudo install -d -m 755 /srv/linux-textbook-demo
printf 'linux textbook service\n' | sudo tee /srv/linux-textbook-demo/index.html >/dev/null
sudo chmod 644 /srv/linux-textbook-demo/index.html
ls -ld /srv/linux-textbook-demo
ls -l /srv/linux-textbook-demo/index.html
```

root가 소유하고 실행 계정에는 읽기·탐색만 허용한다. 파일을 제공하는 프로세스가 웹 데이터를 수정할 필요는 없다. 홈 디렉터리 대신 `/srv`를 사용해 서비스 데이터와 개인 홈을 구분한다.

## 3. 서비스 등록

```bash
sudo tee /etc/systemd/system/linux-textbook-web.service >/dev/null <<'EOF'
[Unit]
Description=Linux textbook local HTTP lab

[Service]
Type=simple
ExecStart=/usr/bin/python3 -m http.server 18081 --bind 127.0.0.1 --directory /srv/linux-textbook-demo
DynamicUser=yes
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes

[Install]
WantedBy=multi-user.target
EOF
sudo systemd-analyze verify /etc/systemd/system/linux-textbook-web.service
sudo systemctl daemon-reload
sudo systemctl enable --now linux-textbook-web.service
systemctl is-enabled linux-textbook-web.service
systemctl is-active linux-textbook-web.service
```

출력은 각각 enabled, active여야 한다. `DynamicUser`는 실행 동안 동적 UID를 배정하므로 고정 계정을 만들지 않는다. 이 서비스는 영구 쓰기 경로가 필요 없어서 해당 방식이 적합하다. enabled는 부팅 연결, active는 현재 상태다.

## 4. 기능과 로그 검증

```bash
ss -lnt '( sport = :18081 )'
curl --noproxy '*' --fail --max-time 3 -i http://127.0.0.1:18081/
sudo journalctl -u linux-textbook-web.service -n 20 --no-pager
```

`127.0.0.1:18081` 리스닝, 200, 본문 `linux textbook service`, 요청 로그를 확인한다. 단지 active인 것보다 실제 요청 성공이 더 강한 기능 검증이다. 반대로 한 번의 성공이 지속 가용성을 보장하지는 않는다.

## 5. 장애 훈련 A: 서비스가 멈췄다

```bash
sudo systemctl stop linux-textbook-web.service
curl --noproxy '*' --fail --max-time 3 http://127.0.0.1:18081/
systemctl status linux-textbook-web.service --no-pager
ss -lnt '( sport = :18081 )'
```

curl 실패, unit 비활성, 리스너 없음이 같은 원인을 가리키는지 확인한다. 이 경우 status의 종료 상태도 정상 중지를 반영할 수 있으며 “inactive”가 항상 프로그램 오류는 아니다.

```bash
sudo systemctl start linux-textbook-web.service
curl --noproxy '*' --fail --max-time 3 http://127.0.0.1:18081/
```

원래 요청이 다시 성공해야 복구다.

## 6. 장애 훈련 B: 서버는 응답하지만 파일이 없다

```bash
curl --noproxy '*' --fail --max-time 3 -i http://127.0.0.1:18081/missing.html
systemctl is-active linux-textbook-web.service
sudo journalctl -u linux-textbook-web.service -n 10 --no-pager
```

404와 curl의 0이 아닌 상태가 예상된다. 서비스는 active이고 요청 로그도 남는다. 이것을 포트 차단으로 해석하지 않는다. 이 경로가 실제로 필요한 파일인지 확인한 뒤 추가한다.

```bash
printf 'recovered page\n' | sudo tee /srv/linux-textbook-demo/missing.html >/dev/null
sudo chmod 644 /srv/linux-textbook-demo/missing.html
curl --noproxy '*' --fail --max-time 3 http://127.0.0.1:18081/missing.html
```

정적 파일 추가는 이 서버에서 재시작 없이 반영된다. 다른 프로그램의 설정 반영 방식까지 같다고 일반화하지 않는다.

## 7. 데이터 백업과 별도 복원

저장소를 내려받은 디렉터리에서 14장의 스크립트를 실행한다. 원본은 정적 파일이며 모두 읽을 수 있어 sudo는 필요 없다.

```bash
archive=$(bash notes/linux/labs/backup.sh /srv/linux-textbook-demo "$HOME/linux-lab/backups")
status=$?
printf 'backup status=%s\n' "$status"
```

0인지 확인한 다음 진행한다.

```bash
restore_dir=$(mktemp -d "$HOME/linux-lab/project-restore.XXXXXXXX")
tar -xzf "$archive" -C "$restore_dir"
diff -r /srv/linux-textbook-demo "$restore_dir"
```

차이가 없어야 한다. 이 백업은 데이터만 포함한다. unit 파일, 배포판 패키지, 실행 경로 등의 복구 정보는 별도 운영 기록에 남긴다.

## 8. 정리하기

이번 실습에서 만든 unit과 정확한 두 파일만 제거한다. 포트와 데이터가 다른 용도로 재사용되지 않았는지 먼저 확인한다. 백업과 복원 디렉터리는 학습 결과로 남겨도 된다.

```bash
sudo systemctl disable --now linux-textbook-web.service
sudo rm -- /etc/systemd/system/linux-textbook-web.service
sudo systemctl daemon-reload
sudo rm -- /srv/linux-textbook-demo/index.html /srv/linux-textbook-demo/missing.html
sudo rmdir /srv/linux-textbook-demo
ss -lnt '( sport = :18081 )'
```

## 제출할 보고서와 해설 기준

- 서비스 unit과 각 제한 옵션의 목적을 설명한다.
- 포트·HTTP·서비스 상태·로그 중 각 증거가 무엇을 증명하는지 적는다.
- 연결 실패와 404의 진단 차이를 명령 출력으로 제시한다.
- 백업 경로·복원 경로·diff 종료 상태를 기록한다.
- “파일을 변경할 수 없는 계정도 파일을 제공할 수 있는가?”에 답한다. 읽기와 경로 탐색 권한이 충분하면 가능하며 쓰기 권한은 별개다.
