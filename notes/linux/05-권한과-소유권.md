# 05 — 권한과 소유권: Permission denied를 설명하기

> 학습 목표: 파일과 디렉터리의 rwx 차이를 이해하고 chmod·umask·ACL을 해석한다.

## 1. 권한은 누구에게 적용되는가

`ls -l`의 `-rw-r-----`에서 첫 글자는 파일 유형이다. 뒤의 세 묶음은 소유자(user), 소유 그룹(group), 나머지(other)의 권한이다. 일반적인 접근 검사에서는 프로세스의 사용자와 소유자가 같으면 소유자 비트, 아니면 그룹 일치 여부, 그다음 other를 선택한다. 세 범주의 허용 권한을 단순 합산하지 않는다. ACL과 관리자 권한 등의 추가 규칙도 있다.

```bash
mkdir -p "$HOME/linux-lab/permissions"
cd "$HOME/linux-lab/permissions"
printf 'private\n' > memo.txt
chmod 640 memo.txt
ls -l memo.txt
id
stat -c '%A %a %U:%G %n' memo.txt
```

`r=4`, `w=2`, `x=1`을 더해 6은 읽기·쓰기, 4는 읽기만, 0은 없음이다. `640`은 소유자 rw, 그룹 r, other 없음이다. `chmod u+x script.sh` 같은 기호 방식은 선택한 비트만 바꾼다.

## 2. 파일과 디렉터리에서 rwx의 뜻

| 권한 | 일반 파일 | 디렉터리 |
|---|---|---|
| r | 내용 읽기 | 내부 이름 목록 읽기 |
| w | 내용 변경 | 항목 생성·삭제·이름 변경 |
| x | 프로그램으로 직접 실행 | 경로 탐색, 내부 항목 접근 |

디렉터리에 쓰기 작업을 하려면 일반적으로 w와 x가 함께 필요하다. 파일을 열려면 상위 경로의 모든 디렉터리에 탐색 권한이 필요하다. 따라서 파일 자체가 `644`여도 부모가 `700`이면 다른 사용자는 접근할 수 없다. 삭제는 파일 내용 수정이 아니라 부모 디렉터리의 항목 제거라서 파일에 쓰기 권한이 없어도 가능할 수 있다.

### 일반 사용자 실험

root가 아닌 사용자로 실행한다. root는 일부 권한 검사를 우회할 수 있어 결과가 달라진다.

```bash
cd "$HOME/linux-lab/permissions"
mkdir -p box
printf 'data\n' > box/item.txt
chmod 400 box/item.txt
chmod 700 box
rm -f -- box/item.txt
ls -la box
```

읽기 전용 파일도 부모에 w+x가 있으면 삭제된다. `rm -f`는 이번에 만든 정확한 파일 하나에만 사용한다. 이 결과가 모든 삭제를 보장하지는 않는다. sticky bit, 읽기 전용 마운트, immutable 속성, ACL·MAC 정책 등도 영향을 줄 수 있다.

## 3. umask는 기본 권한에서 비트를 제거한다

많은 프로그램은 새 일반 파일을 666, 디렉터리를 777을 기준으로 요청하고 umask가 비트를 제거한다. **산술 뺄셈이 아니라 비트 마스킹**이다. 프로그램이 더 제한적인 모드를 요청할 수도 있고 기본 ACL이 있으면 규칙이 달라질 수 있다.

```bash
cd "$HOME/linux-lab/permissions"
(
  umask 027
  touch mask-file
  mkdir mask-dir
  stat -c '%a %n' mask-file mask-dir
)
```

이름이 새로 생성되었다면 보통 파일은 640, 디렉터리는 750이다. 괄호의 서브셸에서 바꿔 바깥 셸의 umask를 보존했다. `touch`는 기존 파일의 권한을 umask에 맞춰 다시 설정하지 않는다. 일반 파일에 실행 비트를 기본 부여하지 않는 이유도 함께 기억한다.

## 4. 소유권, 특수 비트, ACL

`chown 사용자:그룹 파일`은 소유권을 바꾼다. 소유자 변경에는 보통 관리자 권한이 필요하다. `chgrp`는 일반 사용자도 자신이 속한 그룹 범위 등에서 사용할 수 있다. 권한 문제를 만나면 `id`, `ls -ld`, `namei -l /전체/경로`로 어느 경로에서 막히는지 먼저 본다.

| 기능 | 의미 | 예 |
|---|---|---|
| setgid 디렉터리 | 새 항목이 부모 그룹을 상속 | 공동 작업 디렉터리 `2770` |
| sticky 디렉터리 | 쓰기 가능한 디렉터리 안의 삭제·이름 변경을 소유자 등으로 제한 | 보통 `/tmp`의 `1777` |
| setuid 실행 파일 | 실행 시 파일 소유자의 유효 UID 사용 | 권한 상승이므로 엄격히 관리 |
| ACL | 특정 사용자·그룹에 세부 권한 부여 | `getfacl`, `setfacl` |

`ls -l`의 권한 뒤 `+`는 ACL 등 확장 접근 정보를 확인할 신호다. ACL의 `mask`는 이름 있는 사용자와 그룹 계열 항목의 유효 권한 상한에 영향을 주므로 표시된 개별 항목만 읽으면 오해할 수 있다.

`chmod -R 777`은 권한 문제의 표준 해법이 아니다. 비밀 파일을 공개하고 원치 않는 쓰기를 허용한다. 필요한 주체·대상·동작을 정한 뒤 최소 범위만 변경한다.

## 연습문제와 해설

1. `chmod 600 a.sh` 후 `./a.sh`는 실패하지만 `bash a.sh`가 되는 이유는?
   - 직접 실행에는 실행 비트가 필요하다. Bash에 파일을 인수로 주면 Bash가 읽어서 해석한다. 읽기 권한은 필요하다.
2. umask 022에서 새 디렉터리와 일반 파일은 보통 무엇인가?
   - 각각 755와 644다. 프로그램이 요청한 초기 모드와 기본 ACL에 따라 다를 수 있다.
3. 공유 폴더에 setgid를 주면 모든 파일이 그룹 쓰기 가능해지는가?
   - 아니다. 그룹 상속과 쓰기 허용은 별개다. umask, 요청 모드, 기본 ACL을 함께 설계한다.
