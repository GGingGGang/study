# 10 — 디스크와 파일시스템: 용량, inode, 마운트

> 학습 목표: 디스크·파티션·파일시스템·마운트를 구분하고 공간 부족을 진단한다.

## 1. 저장 장치에서 경로까지

블록 장치는 데이터를 블록 단위로 제공한다. 파티션은 장치를 나눈 영역이고 파일시스템은 파일·디렉터리·메타데이터를 관리하는 형식이다. ext4와 XFS 등이 있다. **마운트**는 파일시스템을 경로 트리에 연결하는 동작이다. LVM 같은 계층이 사이에 추가될 수도 있다.

```bash
lsblk -f
findmnt /
df -hT
df -i
```

`lsblk`는 장치 관계, `findmnt`는 실제 마운트, `df`는 파일시스템 단위의 사용량을 보여 준다. 컨테이너나 WSL에서는 호스트 장치와 보이는 결과가 다를 수 있다. 장치 이름을 추측해 포맷하지 않는다.

## 2. df와 du는 무엇을 세는가

```bash
du -h --max-depth=1 "$HOME/linux-lab"
df -h "$HOME/linux-lab"
```

`du`는 접근 가능한 경로 아래 파일의 할당 공간을 합산하고 `df`는 파일시스템의 전체 블록 사용 상태를 본다. 둘이 다른 대표적 이유는 다음과 같다.

- 삭제했지만 프로세스가 열고 있는 파일은 df에 남고 경로를 걷는 du에는 보이지 않을 수 있다.
- 권한 때문에 du가 일부 경로를 읽지 못할 수 있다.
- 하위 마운트, 예약 블록, 스냅샷·공유 블록 등 파일시스템 특성이 영향을 준다.
- 파일의 논리적 크기와 실제 할당 공간은 sparse file 등에서 다르다.

디스크 용량이 남아도 inode가 부족하면 새 파일을 만들 수 없다. 작은 파일이 아주 많은 경우 `df -i`를 확인한다. 실제 inode 제공 방식은 파일시스템마다 다르다.

### 일반 실습: sparse file

```bash
mkdir -p "$HOME/linux-lab/storage"
cd "$HOME/linux-lab/storage"
truncate -s 64M sparse.img
ls -lh sparse.img
du -h sparse.img
du -h --apparent-size sparse.img
```

파일시스템이 지원하면 논리적 크기는 64MiB지만 할당 공간은 훨씬 작다. 아직 데이터를 기록하지 않은 구간을 구멍으로 표현하기 때문이다. 논리적 크기만 보고 실제 복사 비용과 할당 공간을 단정하지 않는다.

## 3. 마운트하면 기존 파일은 어떻게 되는가

어떤 디렉터리에 다른 파일시스템을 마운트하면 원래 디렉터리 내용은 마운트 아래에 가려진다. 삭제된 것이 아니며 unmount 후 다시 보인다. 데이터가 이미 있는 경로에 마운트할 때 이 특성을 기억한다.

### VM 관리자 실습: 작은 tmpfs

개인 VM에서 `/mnt/linux-textbook-tmp`가 사용 중이 아닌지 확인한다. 비어 있지 않거나 이미 마운트되어 있으면 다른 경로를 선택한다.

```bash
findmnt --mountpoint /mnt/linux-textbook-tmp
sudo mkdir -p /mnt/linux-textbook-tmp
sudo ls -la /mnt/linux-textbook-tmp
sudo mount -t tmpfs -o size=16M,mode=1777 tmpfs /mnt/linux-textbook-tmp
findmnt --mountpoint /mnt/linux-textbook-tmp
printf 'temporary\n' > /mnt/linux-textbook-tmp/demo.txt
df -h /mnt/linux-textbook-tmp
```

tmpfs는 휘발성 파일시스템이며 메모리와 설정에 따라 swap을 사용할 수 있다. `size=16M`은 보통 최대 크기 한도이지 즉시 16MiB를 모두 예약하는 뜻은 아니다. 정리하면 내용이 사라진다.

```bash
cd "$HOME"
sudo umount /mnt/linux-textbook-tmp
sudo rmdir /mnt/linux-textbook-tmp
```

busy 오류가 나면 해당 경로의 현재 디렉터리·열린 파일을 확인한다. 강제 옵션으로 밀어붙이지 않는다.

## 4. 영구 마운트와 /etc/fstab

fstab은 파일시스템 식별자, 마운트 지점, 형식, 옵션, dump, fsck 순서 등을 기록한다. 장치명이 바뀔 수 있어 UUID가 유용하다. 하지만 잘못된 설정은 부팅을 지연시키거나 복구 모드로 보낼 수 있다. 이 책에서는 fstab을 변경하지 않고 `findmnt --fstab`으로 현재 설정만 관찰한다.

원격 공유(NFS 등)는 네트워크 의존성·인증·실패 시 동작을 함께 설계해야 한다. `/`의 디스크가 부족할 때 다른 파일시스템의 데이터를 지워도 `/` 용량은 늘지 않으므로 먼저 `df -h 대상경로`로 소속을 확인한다.

## 연습문제와 해설

1. 파일을 지웠는데 df가 줄지 않는다. 첫 가설은? → 열린 삭제 파일을 `lsof +L1` 등으로 확인한다. 증거 없이 관련 프로세스를 강제 종료하지 않는다.
2. “No space left on device”인데 df -h는 여유가 있다. 다음은? → inode 사용량, 사용자 quota, 실제 쓰는 파일시스템과 서비스별 한도 등을 확인한다.
3. tmpfs 데이터를 재부팅 뒤 백업으로 쓸 수 있는가? → 지속 저장을 보장하지 않으므로 불가능하다. 별도 영구 저장이 필요하다.
