# 리눅스 교과서 — 다시 시작하는 사람을 위한 학습 안내

> 목표: 명령어를 외우는 데서 그치지 않고, 파일·프로세스·권한·네트워크를 연결해서 서버의 동작을 설명하고 문제를 해결한다.

## 이 책을 읽는 방법

처음 접했거나 명령어가 가물가물하다면 01장부터 순서대로 읽는다. 이미 서버를 다뤄 봤다면 각 장의 연습문제를 먼저 풀고 설명이 막히는 부분을 복습한다. 한 장은 **개념 읽기 → 출력 예상 → 직접 실행 → 결과 설명 → 문제 풀이** 순서로 공부한다. 실행 결과를 복사하는 것보다 “왜 이 결과인가”를 한 문장으로 적는 것이 중요하다.

이 책의 기준 환경은 **Ubuntu Server 24.04 LTS, Bash, GNU 도구, systemd**다. 다른 Ubuntu 버전에서도 많은 명령이 같지만 출력과 패키지 버전은 다를 수 있다. RHEL 계열의 차이는 해당 장에 표시한다. macOS 터미널은 리눅스 환경이 아니므로 Linux VM이나 WSL 안에서 실습한다.

## 실습 환경 준비

운영 서버 대신 되돌릴 수 있는 VM을 권장한다. VM에 Ubuntu Server를 설치하고 일반 사용자와 sudo 권한을 준비한다. 메모리 2GB, 디스크 20GB 정도로 시작할 수 있다. 설치 직후 스냅샷을 남기면 계정·서비스·마운트 실습을 복구하기 쉽다.

| 환경 | 가능한 실습 | 제한 |
|---|---|---|
| Ubuntu VM | 책의 전체 과정 | 가상화 기능과 여유 디스크 필요 |
| WSL2 Ubuntu | 파일·Bash·프로세스·대부분의 네트워크 | systemd 활성화 여부, Windows와의 네트워크 차이 확인 |
| 일반 컨테이너 | 파일·텍스트·Bash 기초 | 보통 systemd·SSH·블록 장치 실습에 부적합 |
| 원격 VM | 전체 과정 | SSH·방화벽 변경 전 콘솔 접속 수단 확보 |

다음 명령은 환경을 관찰한다. 숫자와 버전은 예시와 달라도 정상이다.

```bash
cat /etc/os-release
uname -r
printf '%s\n' "$SHELL"
ps -p 1 -o comm=
id
```

`/etc/os-release`는 배포판, `uname -r`은 커널 버전이다. `$SHELL`은 등록된 로그인 셸이며 현재 실행 중인 셸과 항상 같지는 않다. PID 1이 `systemd`가 아니라면 09장의 시스템 서비스 실습은 VM으로 옮긴다.

실습 자료는 홈 디렉터리에 둔다. 각 장의 코드는 별도 안내가 없으면 일반 사용자로 실행하며 `$`나 `#` 프롬프트는 붙이지 않았다.

```bash
mkdir -p "$HOME/linux-lab"
cd "$HOME/linux-lab"
pwd
```

기초 명령은 기본 설치 도구로 실습한다. `curl`, `dig`, `lsof`, `iostat`, `python3` 등이 없으면 08장의 패키지 설치 방법을 참고한다. 설치에는 네트워크와 sudo 권한이 필요하다.

## 4주 학습 일정

하루 45~60분, 주 5일을 예로 든 일정이다. 일정이 밀리면 다음 장보다 실습을 먼저 마무리한다.

| 주 | 범위 | 주말까지 남길 결과물 |
|---|---|---|
| 1주 | 01~05 | 파일 조작 기록, 로그 집계, 권한 실험 설명 |
| 2주 | 06~10 | 계정·SSH 점검, 서비스 실습, 용량 분석 |
| 3주 | 11~15 | 접속 진단 기록, 자동화 스크립트, 복원 결과 |
| 4주 | 16~19 | 장애 해결 기록과 종합 실습 보고서 |

## 실습 범위 표시

- **일반 실습**: 홈 디렉터리 안에서 실행한다. `rm`, `>` 등은 이 안에서도 데이터를 지우거나 덮어쓸 수 있다.
- **VM 관리자 실습**: `sudo`, 계정 생성, 서비스·시스템 설정 변경이 들어간다. 해당 절에 준비와 되돌리는 절차를 함께 적었다.
- **관찰 명령**: `df`, `ip`, `ps` 등 상태를 읽는다. 출력에 사용자명·IP·경로가 들어갈 수 있으므로 외부 공유 전 확인한다.

디스크 포맷과 실제 파티션 변경은 이 책의 실행 실습에서 제외했다. 명령을 실행하기 전에는 **대상 경로와 실행 권한, 기존 데이터**를 확인한다. 특히 `sudo`는 오류를 해결하는 기본 수단이 아니다. 권한이 필요한 이유부터 확인한다.

## 시작 전 진단과 해설

1. `cd /var/log`와 `cd var/log`는 같은가? → 전자는 루트 기준 절대 경로, 후자는 현재 디렉터리 기준 상대 경로다.
2. 파일을 읽을 수 있으면 삭제할 수도 있는가? → 삭제는 주로 부모 디렉터리의 쓰기·탐색 권한과 관련된다. 05장에서 확인한다.
3. 서버에 ping이 되면 HTTP도 정상인가? → ICMP 응답과 TCP 연결·HTTP 응답은 별개다. 11장에서 계층을 나눠 검사한다.
