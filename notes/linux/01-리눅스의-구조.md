# 01 — 리눅스의 구조: 명령 한 줄 뒤에서 일어나는 일

> 학습 목표: 커널·배포판·셸·터미널을 구분하고, 파일 계층과 시스템 호출을 설명한다.

## 1. 리눅스라는 이름이 가리키는 것

좁은 의미의 Linux는 **커널**이다. 커널은 CPU 시간, 메모리, 장치, 파일시스템, 네트워크를 관리한다. 우리가 사용하는 Ubuntu 같은 **배포판**은 커널에 사용자 공간 도구, 패키지 관리자, 서비스 관리자와 기본 설정을 묶는다. 같은 커널 계열을 사용해도 패키지 이름과 설정 경로는 다를 수 있다.

**터미널**은 글자를 입력하고 출력을 보여 주는 창이다. **셸**은 입력을 해석하는 프로그램이다. Bash가 `ls`를 찾아 실행하면 `ls` 프로세스는 커널에 디렉터리 정보를 요청하고 결과를 표준 출력에 쓴다. 셸이 모든 명령의 기능을 직접 수행하는 것은 아니다.

```text
사람 → 터미널 → Bash → 프로그램(ls, curl, python3 ...)
                          ↓ 시스템 호출
                  커널 → 파일·장치·네트워크
```

`cd`, `export` 같은 기능은 셸 내부 명령이다. 자식 프로그램만 작업 디렉터리를 바꿔서는 부모 셸의 위치가 바뀌지 않기 때문에 `cd`가 셸 내부에 있어야 한다.

```bash
type cd
type ls
command -v bash
uname -s
cat /etc/os-release
```

`type cd`는 Bash에서 builtin이라고 표시한다. `ls`는 alias로 먼저 표시될 수도 있다. 배포판 버전과 커널 버전은 따로 관리되므로 두 버전 번호가 같을 필요가 없다.

## 2. 사용자 공간과 커널 공간

일반 프로그램은 장치나 다른 프로세스의 메모리를 마음대로 조작하지 못한다. 파일을 열 때는 `open`, 내용을 읽을 때는 `read` 같은 **시스템 호출**로 커널에 요청한다. 커널은 접근 권한과 상태를 확인한 뒤 결과나 오류를 반환한다. `Permission denied`는 요청이 접근 제어에서 거부되었다는 관찰이고, 곧바로 관리자 권한이 정답이라는 뜻은 아니다.

프로그램은 보통 라이브러리를 통해 시스템 호출을 사용한다. “Bash 명령”, “라이브러리 함수”, “시스템 호출”은 서로 다른 층이다. 뒤에서 사용할 `strace`는 이 요청을 관찰하는 도구이며, 단순히 셸의 실행 내역을 출력하는 `set -x`와 다르다.

## 3. 루트부터 이어지는 파일 계층

리눅스 경로의 시작은 `/`다. 디스크가 여러 개여도 특정 디렉터리에 **마운트**해서 하나의 트리에 연결한다. Windows 드라이브 문자와 같은 방식으로 접근하지 않는다.

| 경로 | 역할 | 관찰할 때 주의할 점 |
|---|---|---|
| `/home` | 일반 사용자의 홈 | root의 홈은 보통 `/root` |
| `/etc` | 시스템 설정 | 편집 전 원본·문법 검증 방법 확인 |
| `/var/log` | 파일로 저장하는 로그 | 서비스가 journal에만 기록할 수도 있음 |
| `/usr/bin` | 사용자 명령 | 배포판 패키지가 관리하는 영역 |
| `/usr/local` | 관리자가 별도로 설치한 도구 | 패키지 도구와 경로 충돌 주의 |
| `/tmp` | 임시 파일 | 재부팅·정리 정책으로 삭제될 수 있음 |
| `/run` | 실행 중 상태 | 보통 휘발성, 재부팅 후 재생성 |
| `/dev` | 장치 인터페이스 | 일반 파일처럼 보여도 장치에 연결됨 |
| `/proc` | 커널·프로세스 정보 | 가상 파일시스템, 내용이 실시간 변경 |
| `/sys` | 커널 장치·속성 인터페이스 | 일부 파일에 쓰면 시스템 상태 변경 |

현대 Ubuntu에서는 `/bin`, `/sbin`, `/lib`가 `/usr` 아래를 가리키는 링크인 경우가 흔하다. 오래된 경로 설명을 그대로 외우기보다 실제 링크를 확인한다.

```bash
ls -ld /bin /sbin /lib
ls /proc | head
cat /proc/version
ls -ld / /home /etc /var/log
```

`/proc`의 숫자 디렉터리는 프로세스 PID다. 프로세스가 종료되면 사라질 수 있다. 디스크 파일과 같은 수명이라고 가정하면 안 된다.

## 4. “모든 것이 파일”을 정확히 읽기

많은 자원을 파일 디스크립터로 다루는 공통 인터페이스가 있다는 뜻이다. 일반 파일, 파이프, 소켓, 장치는 읽기·쓰기 인터페이스를 공유할 수 있다. 그렇다고 모든 대상이 디스크에 저장된 일반 파일이거나 임의 위치 탐색을 지원하는 것은 아니다. 파이프는 바이트 흐름이며 보통 파일처럼 되감지 못한다.

**파일 디스크립터(FD)**는 프로세스가 열린 대상을 가리키는 번호다. 기본적으로 0은 표준 입력, 1은 표준 출력, 2는 표준 오류다. 프로그램이 무엇에 연결되어 있는지는 셸의 리다이렉션으로 바꿀 수 있다.

## 5. 도움말을 스스로 찾기

```bash
ls --help
man ls
man 5 passwd
```

`man`에서는 `/검색어`로 검색하고 `n`으로 다음 결과, `q`로 종료한다. 설치가 최소화된 환경에서는 man 페이지가 없을 수 있다. `passwd(1)`은 명령, `passwd(5)`는 파일 형식이다. 같은 이름이어도 설명하는 대상이 다르다.

## 실습: 내 환경 설명서 쓰기

배포판 이름과 버전, 커널 버전, 로그인 사용자, PID 1의 이름을 기록한다. `ps -p 1 -o pid,comm,args`로 확인하고 “이 환경에서 systemd 실습이 가능한가”를 판단한다. PID 1이 systemd라고 해서 권한과 서비스가 모두 준비된 것은 아니므로 VM 여부도 기록한다.

## 연습문제와 해설

1. Ubuntu를 업데이트했는데 `uname -r`이 그대로다. 반드시 실패인가?
   - 아니다. 사용자 공간 패키지만 갱신했거나, 새 커널이 설치되어도 아직 재부팅하지 않았을 수 있다. `uname`은 실행 중인 커널을 보여 준다.
2. `/proc`를 통째로 백업하면 실행 중인 프로세스를 복구할 수 있는가?
   - 아니다. 커널이 현재 상태를 노출하는 인터페이스이며 프로세스 실행 상태의 일반 백업 파일이 아니다.
3. 터미널을 바꾸면 셸도 바뀌는가?
   - 반드시 그렇지 않다. 터미널 앱이 실행하는 셸을 별도로 선택할 수 있다.
