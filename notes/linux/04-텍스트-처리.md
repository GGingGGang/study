# 04 — 텍스트 처리: 로그에서 답 찾기

> 학습 목표: grep·sort·uniq·sed·awk·find를 조합하고, 파일 이름을 안전하게 전달한다.

## 1. 재현 가능한 로그 만들기

이번 장은 실제 서버 로그 대신 구조가 정해진 TSV 파일을 쓴다. 다음은 탭 구분 필드를 만들며 헤더가 없다. 필드는 시각, 경로, HTTP 상태, 처리 시간(ms) 순이다.

```bash
mkdir -p "$HOME/linux-lab/text"
cd "$HOME/linux-lab/text"
printf '%s\t%s\t%s\t%s\n' \
  10:00 / 200 12 \
  10:01 /login 401 8 \
  10:02 /api 500 300 \
  10:03 /api 502 450 \
  10:04 / 200 10 > access.tsv
cat -n access.tsv
```

## 2. grep은 줄을 선택한다

```bash
grep -n '/api' access.tsv
grep -F '/login' access.tsv
grep -E '500|502' access.tsv
grep -v '/api' access.tsv
```

`-n`은 줄 번호, `-F`는 고정 문자열, `-E`는 확장 정규식, `-v`는 불일치 줄이다. 정규식에서 `.`은 임의 문자이고 `^`와 `$`는 줄의 시작·끝이다. `grep -F 'a.b'`는 점까지 그대로 찾는다. 사용자 입력처럼 정규식 해석이 필요 없는 데이터에는 `-F`가 알맞다.

`grep -E '500|502'`는 어느 필드에서든 해당 숫자가 나타나면 선택한다. 상태 필드를 정확히 검사하려면 뒤의 awk를 쓴다. “원하는 결과가 우연히 나왔다”와 “조건을 정확히 표현했다”를 구분한다.

## 3. 자르고 정렬하고 세기

```bash
cut -f 3 access.tsv | sort | uniq -c
sort -t "$(printf '\t')" -k4,4n access.tsv
wc -l access.tsv
```

상태 집계는 200이 2개, 401·500·502가 각각 1개다. `uniq`는 **연속된** 중복만 묶으므로 먼저 정렬한다. `sort -n`은 숫자로 비교한다. 기본 문자열 정렬에서는 `100`이 `20`보다 앞설 수 있다. 로케일에 따라 정렬 결과가 달라질 수 있어 재현 가능한 바이트 순서가 필요하면 해당 명령에 `LC_ALL=C`를 지정한다.

## 4. sed는 줄을 변환하고 awk는 필드를 계산한다

```bash
sed -n '2,4p' access.tsv
sed 's@/api@/backend@g' access.tsv
awk -F '\t' '$3 >= 500 {print $1, $2, $3}' access.tsv
awk -F '\t' '{sum += $4} END {if (NR) print sum / NR}' access.tsv
```

첫 sed는 2~4번째 줄을 출력한다. 두 번째는 `/api`를 `/backend`로 바꾸지만 원본 파일은 수정하지 않는다. `s` 명령의 구분자는 `/` 외에 `@`도 사용할 수 있다. awk는 한 줄을 레코드로 읽고 `$1`, `$2` 등으로 필드를 다룬다. 여기서 `$3`은 셸 변수가 아니라 awk 프로그램의 표현이므로 작은따옴표로 보호한다. 평균은 `156`ms다.

한 줄씩 분리되는 로그가 아닌 JSON은 `jq` 같은 구조화 파서를 사용한다. CSV도 필드 안의 쉼표와 따옴표가 허용되므로 단순 `cut -d,`만으로 일반적인 CSV를 정확히 처리할 수 없다.

## 5. find는 파일 자체를 찾는다

```bash
cd "$HOME/linux-lab/text"
mkdir -p samples
touch samples/a.log 'samples/two words.log' samples/keep.txt
find samples -type f -name '*.log' -print
find samples -type f -name '*.log' -exec wc -c -- {} +
```

`-name '*.log'`를 인용해야 현재 셸이 먼저 확장하지 않고 find가 패턴을 해석한다. `-exec ... {} +`는 파일 이름을 인수로 전달하므로 공백이 있어도 분리되지 않는다. GNU 도구끼리는 `-print0`과 `xargs -0`로 NUL 구분도 사용할 수 있다.

```bash
find samples -type f -name '*.log' -print0 | xargs -0 -r wc -c --
```

`-r`은 GNU xargs에서 입력이 없으면 실행하지 않는 옵션이다. 파일 삭제 자동화는 먼저 동일한 조건의 `-print` 결과를 확인한 뒤 설계한다. `find`의 `-mtime +7`은 달력상의 “7일 전”이 아니라 24시간 단위를 버림한 값이 7보다 큰 대상을 선택하므로 경계를 이해해야 한다.

## 실습과 해설

1. 상태가 400 이상인 줄의 개수를 구한다.

   ```bash
   awk -F '\t' '$3 >= 400 {count++} END {print count+0}' access.tsv
   ```

   결과는 `3`. 빈 입력에서도 0을 출력하게 `+0`을 사용했다.

2. `/api` 요청의 처리 시간 평균을 구한다.

   ```bash
   awk -F '\t' '$2 == "/api" {sum += $4; n++} END {if (n) print sum/n}' access.tsv
   ```

   결과는 `375`. 부분 문자열 검색 대신 필드의 일치를 사용한다.

3. 상태별 빈도를 많은 순서로 정렬한다.

   ```bash
   cut -f 3 access.tsv | sort | uniq -c | sort -nr
   ```

   200이 첫 번째다. 빈도가 같은 항목의 추가 순서가 필요하면 보조 정렬 기준도 명시한다.
