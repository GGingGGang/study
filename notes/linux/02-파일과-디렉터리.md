# 02 — 파일과 디렉터리: 경로, 복사, 링크, 편집

> 학습 목표: 절대·상대 경로를 구분하고, 파일을 안전하게 다루며 하드 링크와 심볼릭 링크의 차이를 설명한다.

## 1. 경로는 어디에서 시작하는가

`/etc/hosts`처럼 `/`로 시작하면 절대 경로다. `notes/a.txt`는 현재 작업 디렉터리 기준 상대 경로다. `.`은 현재, `..`은 부모 디렉터리다. `~`는 셸이 홈 경로로 확장한다. `"~/file"`에서는 틸드 확장이 일어나지 않으므로 스크립트에서는 `"$HOME/file"`이 명확하다.

```bash
mkdir -p "$HOME/linux-lab/files/notes"
cd "$HOME/linux-lab/files"
pwd
cd notes
pwd
cd ..
printf 'hello linux\n' > notes/hello.txt
ls -lah notes
```

`mkdir -p`는 중간 경로도 만든다. `ls -a`는 점으로 시작하는 이름을 표시한다. 점 파일은 이름 규칙일 뿐 특별한 암호화나 보안 기능이 아니다. `ls -l`은 소유권과 권한도 보여 주며 크기는 디렉터리 전체 사용량과 같지 않다.

## 2. 복사·이동·삭제

```bash
cd "$HOME/linux-lab/files"
cp -i notes/hello.txt notes/copy.txt
mv -i notes/copy.txt notes/renamed.txt
cat notes/renamed.txt
rm -i notes/renamed.txt
```

`-i`는 충돌 또는 삭제 전에 확인한다. 자동화에서는 확인 입력에 의존하기보다 파일 이름과 덮어쓰기 정책을 설계한다. `mv`는 같은 파일시스템 안에서는 보통 이름 연결을 바꾸지만 다른 파일시스템으로 이동하면 복사·삭제 과정이 필요할 수 있다. `rm`은 일반적으로 휴지통으로 옮기지 않는다.

디렉터리는 `cp -a source destination`으로 속성을 보존하며 복사할 수 있다. 대상 디렉터리의 존재 여부에 따라 결과 경로가 달라지므로 먼저 `ls`로 확인한다. 빈 디렉터리는 `rmdir`로 지우면 내용이 있을 때 실패하여 의도를 확인하기 쉽다.

## 3. 파일 이름을 정확히 전달하기

공백은 셸에서 인수를 나누므로 경로를 인용한다. `--`는 많은 GNU 명령에서 옵션의 끝을 뜻한다.

```bash
cd "$HOME/linux-lab/files"
printf 'space\n' > 'two words.txt'
cat -- 'two words.txt'
touch -- -example.txt
ls -l -- -example.txt
rm -i -- -example.txt
```

실제 파일 이름은 줄바꿈도 포함할 수 있다. 그래서 스크립트에서 `ls` 출력을 공백으로 나눠 파일 목록으로 쓰지 않는다. 04장에서 `find`의 안전한 전달 방식을 배운다.

## 4. inode와 두 종류의 링크

파일 이름은 디렉터리에 저장된 연결이며, inode는 파일의 메타데이터와 데이터 위치 정보를 관리한다. 일반적으로 이름 자체는 inode에 저장되지 않는다. **하드 링크**는 같은 inode에 이름을 하나 더 붙인다. **심볼릭 링크**는 다른 경로를 문자열로 가리키는 별도 파일이다.

```bash
cd "$HOME/linux-lab/files"
mkdir -p links
cd links
printf 'version 1\n' > original.txt
ln original.txt hard.txt
ln -s original.txt soft.txt
ls -li
printf 'version 2\n' >> hard.txt
cat soft.txt
rm -i original.txt
cat hard.txt
cat soft.txt
```

마지막 `cat soft.txt`는 대상 경로가 사라져 실패한다. `hard.txt`는 여전히 inode를 가리켜 두 줄을 읽는다. `ls -li`에서 원본과 하드 링크의 inode 번호가 같고 링크 수가 2였다가 1이 되는 것을 확인한다. 이 실습을 다시 하려면 새로운 하위 디렉터리를 사용한다.

| 항목 | 하드 링크 | 심볼릭 링크 |
|---|---|---|
| 참조 대상 | 같은 inode | 경로 문자열 |
| 파일시스템 경계 | 일반적으로 넘을 수 없음 | 넘을 수 있음 |
| 디렉터리 링크 | 일반 사용자에게 허용되지 않음 | 가능 |
| 원래 이름 삭제 | 다른 이름으로 내용 접근 가능 | 경로가 없어지면 끊어진 링크 |

상대 경로 심볼릭 링크의 대상은 **링크가 놓인 디렉터리 기준**으로 해석한다. 링크를 다른 디렉터리로 옮기면 의미가 달라질 수 있다.

## 5. 읽기와 편집

짧은 파일은 `cat`, 긴 파일은 `less`, 앞뒤만 볼 때는 `head`와 `tail`을 쓴다. `less`도 `/검색어`, `n`, `q`를 지원한다.

```bash
head -n 5 /etc/passwd
tail -n 5 /etc/passwd
file /etc/passwd
```

초보자는 `nano 파일명`으로 시작할 수 있다. 저장은 Ctrl+O와 Enter, 종료는 Ctrl+X다. Vim이 있는 환경에서는 `vim 파일명` → `i`로 입력 → Esc → `:wq`로 저장·종료한다. 변경을 버리려면 Esc 후 `:q!`를 쓴다. 편집기는 도구일 뿐이므로 처음부터 편집기 기능 전체를 외울 필요는 없다.

## 연습문제와 해설

1. `/home/me`에서 `cat ../other/a.txt`는 어디를 읽는가?
   - `/home/other/a.txt`. 상대 경로는 현재 위치를 기준으로 계산한다.
2. 1GB 파일의 하드 링크를 하나 만들면 데이터가 1GB 더 복제되는가?
   - 아니다. 같은 inode를 공유한다. 독립된 사본이 필요하면 복사해야 한다.
3. `rm` 후에도 디스크 공간이 줄지 않을 수 있는 이유는?
   - 다른 하드 링크가 있거나 프로세스가 파일을 열고 있을 수 있다. 마지막 링크와 열린 참조가 사라져야 데이터 공간이 회수된다.
