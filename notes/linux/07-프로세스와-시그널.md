# 07 — 프로세스와 시그널: 실행 중인 프로그램 다루기

> 학습 목표: PID·PPID·상태를 읽고, 작업 제어와 정상 종료를 구분한다.

## 1. 프로그램과 프로세스

프로그램은 실행할 코드이고 프로세스는 실행 중인 인스턴스다. 프로세스에는 PID, 부모 PID, 사용자, 작업 디렉터리, 환경변수, 열린 파일, 메모리 등이 있다. 같은 실행 파일로 여러 프로세스를 만들 수 있다. 스레드는 한 프로세스의 자원을 공유하며 실행 흐름을 나눈다.

```bash
ps -eo pid,ppid,user,stat,comm --sort=pid | head -n 15
ps -p $$ -o pid,ppid,stat,args
```

`$$`는 현재 Bash의 PID다. `ps`는 순간의 관찰이고 지속적으로 보려면 `top`을 사용한다. `top`은 `q`로 종료한다. CPU 사용률은 도구가 정의하는 집계 기간과 코어 수를 함께 해석한다.

| 상태 | 의미 | 해석 |
|---|---|---|
| R | 실행 중 또는 실행 대기 | CPU를 쓰거나 차례를 기다림 |
| S | 인터럽트 가능한 대기 | 입력·이벤트 대기는 정상일 수 있음 |
| D | 인터럽트 불가 대기 | 흔히 I/O 관련, 원인 자원 확인 |
| T | 정지 | 작업 제어·디버깅 등 |
| Z | 좀비 | 종료했지만 부모가 상태를 회수하지 않음 |

좀비는 계속 코드를 실행하는 프로세스가 아니다. 종료 상태를 기다리는 항목이므로 SIGKILL로 해결하지 못한다. 부모의 회수 동작을 조사한다. D 상태 프로세스도 시그널을 보냈다고 즉시 사라지지 않을 수 있다.

## 2. 포그라운드와 백그라운드

대화형 Bash에서 다음을 수행한다. 생성한 `sleep` 하나만 종료한다.

```bash
sleep 300 &
lab_pid=$!
jobs -l
ps -p "$lab_pid" -o pid,ppid,stat,args
kill -TERM "$lab_pid"
wait "$lab_pid"
printf 'wait status=%s\n' "$?"
```

`&`는 백그라운드 실행, `$!`는 마지막 백그라운드 작업 PID다. `wait`는 해당 자식의 종료를 기다리고 상태를 반환한다. Bash에서는 SIGTERM 종료 시 흔히 143이지만 도구별 표현 차이를 고려한다. 마지막 상태 출력 전 다른 명령을 넣지 않는다.

포그라운드 `sleep 300`에 Ctrl+Z를 누르면 정지한다. `jobs`로 확인하고 `bg`로 재개하거나 `fg`로 앞에 가져온다. Ctrl+C는 보통 터미널의 포그라운드 프로세스 그룹에 SIGINT를 보낸다. 작업 번호 `%1`과 PID는 다른 식별자다.

## 3. 시그널은 요청과 통지다

| 시그널 | 일반적 용도 | 처리 가능 여부 |
|---|---|---|
| SIGTERM | 정상 종료 요청 | 프로그램이 정리 동작 가능 |
| SIGINT | 사용자 중단 | 프로그램이 처리 가능 |
| SIGHUP | 터미널 종료 통지, 일부 서비스의 재읽기 | 의미는 프로그램마다 다름 |
| SIGKILL | 강제 종료 | 잡거나 무시할 수 없음 |
| SIGSTOP | 강제 정지 | 잡거나 무시할 수 없음 |

`kill`의 기본은 SIGTERM이다. SIGKILL부터 보내면 버퍼 기록, 임시 파일 정리, 연결 종료 기회가 사라진다. 먼저 대상을 확인하고 TERM을 보낸 뒤 종료 여부와 로그를 확인한다. systemd가 관리하는 프로세스는 `systemctl stop`으로 서비스 단위로 중지하는 것이 적절하다.

`pkill`은 조건에 맞는 여러 프로세스에 시그널을 보낼 수 있다. 넓은 이름 패턴보다 확인한 PID나 unit을 우선 사용한다. PID는 재사용될 수 있으므로 오래전에 기록한 숫자만 믿고 종료하지 않는다.

## 4. 터미널을 닫아도 서비스가 필요한가

`nohup 명령 &`는 HUP 처리와 입출력 연결을 도와줄 뿐 서비스의 재시작·권한·로그·부팅 자동 실행을 모두 관리하지 않는다. 지속 운영에는 09장의 systemd를 사용한다. SSH 세션을 유지하며 작업하려면 `tmux` 같은 터미널 다중화 도구도 선택할 수 있다.

열린 파일을 관찰할 때는 `lsof -p PID` 또는 권한이 허용된다면 `/proc/PID/fd`를 본다. 프로세스가 지워진 로그를 계속 열고 있으면 파일 이름은 없어도 디스크 사용량이 남는 현상을 이해할 수 있다.

## 연습문제와 해설

1. `sleep 300 &` 뒤 터미널이 즉시 돌아오는 이유는? → 셸이 백그라운드 작업의 종료를 기다리지 않고 다음 입력을 받기 때문이다.
2. SIGTERM과 SIGKILL을 구분하는 이유는? → 정상적인 정리 기회를 제공하는지 다르다. 종료되지 않는 원인도 관찰해야 한다.
3. 부모 프로세스가 종료되면 모든 자식도 반드시 즉시 종료되는가? → 아니다. 재부모화, 세션·시그널·서비스 관리 규칙에 따라 달라진다.
