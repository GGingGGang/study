# 08 — 패키지와 환경변수: 도구는 어디에서 오는가

> 학습 목표: 패키지 색인 갱신과 업그레이드를 구분하고 PATH와 셸 시작 파일을 이해한다.

## 1. 패키지 관리자의 역할

패키지 관리자는 파일과 버전, 의존 관계를 기록하고 설정된 저장소에서 설치한다. Ubuntu는 dpkg와 APT, RHEL 계열은 RPM과 DNF를 사용한다. 같은 기능도 패키지명은 다를 수 있다. 신뢰하는 저장소와 서명 검증을 유지하고 출처를 모르는 스크립트를 곧바로 관리자 셸에 넘기지 않는다.

```bash
apt-cache policy curl
apt show curl
dpkg -l curl
```

이 명령들은 설치 후보·설명·설치 상태를 확인한다. 설치되지 않은 패키지 조회가 실패할 수도 있다. APT 색인이 오래되었다면 현재 원격 저장소의 상태와 다를 수 있다.

### VM 관리자 실습: 이 책의 보조 도구 설치

```bash
sudo apt update
sudo apt install curl dnsutils lsof sysstat python3 man-db
```

`apt update`는 **패키지 목록**을 갱신한다. `apt upgrade`는 설치된 패키지 업그레이드다. 두 동작은 같지 않다. `full-upgrade`는 의존 관계 해결을 위해 제거가 포함될 수 있으므로 변경 내역을 읽는다. 이 책의 실습에 전체 업그레이드는 필수가 아니다. 자동화에서는 출력이 사람용인 `apt`보다 `apt-get` 등 스크립트용 인터페이스를 고려한다.

| 목적 | Ubuntu / Debian | RHEL 계열 |
|---|---|---|
| 설치 | `apt install 패키지` | `dnf install 패키지` |
| 검색 | `apt search 단어` | `dnf search 단어` |
| 설치 목록 | `dpkg -l` | `rpm -qa` |
| 파일 소유 패키지 | `dpkg -S /경로` | `rpm -qf /경로` |
| 제거 | `apt remove 패키지` | `dnf remove 패키지` |

`apt remove`와 `purge`도 다르다. purge는 패키지가 관리하는 설정 파일까지 제거하지만 사용자 홈의 모든 데이터를 정리한다는 뜻은 아니다. `autoremove`도 제거 목록을 검토한다.

## 2. 명령을 찾는 PATH

슬래시가 없는 외부 명령은 셸이 `$PATH`의 디렉터리를 순서대로 검색한다. 현재 디렉터리가 PATH에 없으면 `script.sh` 대신 `./script.sh`라고 실행해야 한다. alias, 함수, builtin도 있으므로 진단에는 `type -a`가 유용하다.

```bash
printf '%s\n' "$PATH"
type -a python3
command -v python3
```

PATH 앞에 쓰기 가능한 낯선 디렉터리를 추가하면 의도하지 않은 명령이 먼저 선택될 수 있다. 특히 `.`을 앞에 넣는 습관은 피한다. 패키지로 설치한 명령과 수동 설치 명령의 우선순위도 확인한다.

## 3. 셸 변수와 환경변수

일반 셸 변수는 현재 셸 내부에서 사용한다. `export`하면 이후 생성하는 자식 프로세스가 환경으로 전달받는다. 자식이 바꾼 환경이 부모 셸로 거슬러 올라오지는 않는다.

```bash
LAB_MESSAGE=hello
bash -c 'printf "before=<%s>\n" "${LAB_MESSAGE-unset}"'
export LAB_MESSAGE
bash -c 'printf "after=<%s>\n" "$LAB_MESSAGE"'
unset LAB_MESSAGE
```

첫 출력은 `unset`, 두 번째는 `hello`다. 명령 한 번에만 변수를 주려면 `LC_ALL=C sort file.txt`처럼 앞에 지정한다. 비밀 값을 명령행 인수나 공유하는 환경 덤프에 넣지 않는다. 프로세스 환경은 해당 시스템의 권한과 도구에 따라 관찰될 수 있다.

## 4. .bashrc와 로그인 셸

Bash는 실행 방식에 따라 서로 다른 시작 파일을 읽는다. 대화형 비로그인 셸은 보통 `~/.bashrc`, 로그인 셸은 `/etc/profile` 다음 사용자 프로필 파일 중 하나를 읽는다. Ubuntu의 기본 프로필은 `.bashrc`를 불러오는 구성이 흔하다. 비대화형 스크립트가 `.bashrc`를 자동으로 읽는다고 가정하지 않는다.

`source 파일` 또는 `. 파일`은 **현재 셸 안에서** 코드를 실행한다. `bash 파일`은 자식 셸에서 실행한다. 따라서 source한 파일의 `cd`, 변수 변경, `exit`가 현재 작업에 영향을 줄 수 있다. 믿을 수 없는 파일을 source하지 않는다.

## 실습: 개인 명령을 절대 경로로 실행하기

```bash
mkdir -p "$HOME/linux-lab/bin"
printf '#!/bin/bash\nprintf "hello from lab\\n"\n' > "$HOME/linux-lab/bin/lab-hello"
chmod u+x "$HOME/linux-lab/bin/lab-hello"
"$HOME/linux-lab/bin/lab-hello"
```

이 단계에서는 PATH를 영구 수정하지 않는다. 먼저 파일·권한·인터프리터가 정상인지 절대 경로로 확인한다. `#!/bin/bash`는 직접 실행할 때 사용할 인터프리터를 지정하는 shebang이다.

## 연습문제와 해설

1. `apt update` 후 curl 버전이 그대로인 이유는? → 목록만 갱신했기 때문이다. 설치·업그레이드 동작은 별도다.
2. 터미널에서는 되는데 cron에서 명령을 못 찾는 이유는? → PATH와 시작 파일, 작업 디렉터리가 다를 수 있다. 절대 경로와 필요한 환경을 명시한다.
3. `bash setup.sh`에서 export한 변수가 부모에 없는 이유는? → 자식 프로세스의 환경 변경이 부모에 전파되지 않기 때문이다.
