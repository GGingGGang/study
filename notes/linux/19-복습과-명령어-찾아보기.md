# 19 — 복습과 명령어 찾아보기

> 학습 목표: 상황에 맞는 관찰을 고르고, 명령 결과의 한계를 설명한다.

## 1. 설명할 수 있어야 하는 질문

해설을 가리고 말로 먼저 답한다. 명령 이름만 답하지 말고 어떤 결과가 나오면 가설이 맞는지도 설명한다.

| 질문 | 해설의 핵심 |
|---|---|
| 커널과 Ubuntu의 차이는? | 커널은 자원 관리의 핵심, 배포판은 사용자 공간·패키지·설정까지 포함 |
| 셸과 터미널의 차이는? | 셸은 명령 해석, 터미널은 입출력 인터페이스 |
| 하드 링크와 복사의 차이는? | 같은 inode 공유와 별도 데이터 사본 |
| 파일이 644인데 왜 읽지 못하는가? | 상위 디렉터리 x, 실행 사용자, ACL·MAC·마운트 등 확인 |
| 파일의 w 없이 왜 삭제 가능한가? | 부모 디렉터리 항목 변경 권한이 핵심 |
| export한 값이 부모에 왜 안 돌아오는가? | 환경은 자식 생성 시 상속, 역방향 전파 없음 |
| SIGTERM 다음에 무엇을 확인하는가? | 종료·정리 여부와 로그, 실패 원인 |
| enable과 active는 같은가? | 부팅 등 자동 연결과 현재 실행 상태는 별개 |
| df와 du가 왜 다른가? | 파일시스템 회계와 경로 순회, 열린 삭제 파일·마운트 등 |
| available과 free는 왜 다른가? | 캐시 회수 등 재사용 가능성을 반영 |
| HTTP 404와 연결 거부의 차이는? | 전자는 HTTP 응답 도달, 후자는 연결 단계 거부 |
| 컨테이너의 localhost는 누구인가? | 해당 network namespace, Pod 공유 여부 확인 |
| 백업 성공을 어떻게 검증하는가? | 복원 후 필요한 내용·권한·일관성·복구 시간 확인 |

## 2. 상황별 명령 색인

명령은 관련 장의 설명과 함께 사용한다. `경로`, `서비스명`, `PID`는 실제 대상으로 바꾸는 자리표시자다.

| 하려는 일 | 명령 | 장 |
|---|---|---|
| 배포판·커널 확인 | `cat /etc/os-release`, `uname -r` | 01 |
| 명령 유형 확인 | `type -a 명령`, `command -v 명령` | 01·08 |
| 현재 경로·숨김 파일 | `pwd`, `ls -lah` | 02 |
| 파일 형식·상태 | `file 경로`, `stat 경로` | 02·05 |
| inode·링크 확인 | `ls -li`, `readlink 경로` | 02 |
| 고정 문자열 찾기 | `grep -Fn '문자열' 파일` | 04 |
| 필드 집계 | `awk -F '\t' '프로그램' 파일` | 04 |
| 안전한 파일 전달 | `find 경로 -type f -exec 명령 {} +` | 04 |
| 사용자·그룹 | `id`, `getent passwd 사용자` | 06 |
| 경로 전체 권한 | `namei -l /절대/경로` | 05·17 |
| 프로세스와 부모 | `ps -eo pid,ppid,user,stat,args` | 07 |
| 정상 종료 요청 | `kill -TERM PID` | 07 |
| 패키지 소유 확인 | `dpkg -S /파일경로` | 08 |
| 서비스 정의·상태 | `systemctl cat 서비스명`, `systemctl status 서비스명` | 09 |
| 서비스 로그 | `journalctl -u 서비스명 -b` | 09·12 |
| 실패한 unit | `systemctl --failed` | 09 |
| 장치·마운트 | `lsblk -f`, `findmnt` | 10 |
| 블록·inode 사용 | `df -h 경로`, `df -i 경로` | 10 |
| 하위 용량 | `du -xhd1 경로` | 10 |
| IP·경로 | `ip -br addr`, `ip route` | 11 |
| 실제 경로 선택 | `ip route get 목적지IP` | 11 |
| 리스닝 소켓 | `ss -lntp` | 11 |
| 이름 조회 | `getent ahosts 이름`, `dig 이름` | 11 |
| HTTP 상태 확인 | `curl -i --max-time 10 URL` | 11 |
| 메모리·구간 지표 | `free -h`, `vmstat 1 5`, `iostat -xz 1 3` | 12 |
| Bash 구문 검사 | `bash -n script.sh` | 13 |
| 백업 목록 보기 | `tar -tzf archive.tar.gz` | 14 |
| 스케줄 확인 | `crontab -l`, `systemctl list-timers --all` | 14 |

상태 조회라도 권한이 부족하면 출력이 제한될 수 있다. 접근 거부를 지표가 0인 것으로 읽지 않는다. 외부 네트워크 명령은 해당 환경의 프록시·통신 정책을 따른다.

## 3. 직접 풀어 볼 최종 문제

1. 공백이 들어간 디렉터리를 만들고 파일 세 개를 생성한다. 스크립트로 이름이 아닌 개수를 안전하게 출력한다.
2. TSV에서 상태 코드 500 이상인 요청 수와 평균 처리 시간을 구한다.
3. 실행 비트 없는 스크립트의 직접 실행과 `bash 스크립트` 결과를 비교한다.
4. 루프백 HTTP 서버를 띄워 200, 404, 연결 실패를 각각 재현한다.
5. 백업 원본 내부를 출력 경로로 주었을 때 스크립트가 실패하는지 확인한다.
6. 서비스가 실행되지만 필요한 파일만 읽지 못할 때의 진단 순서를 적는다.

### 채점 기준

1번은 파일명 분리가 없어야 하며 13장의 `find -printf` 방식이 한 예다. 2번은 04장의 자료 기준 2건, 평균 375ms다. 3번은 직접 실행에는 x가 필요하다는 설명이 있어야 한다. 4번은 HTTP 오류와 전송 실패를 구분해야 한다. 5번은 종료 상태가 0이 아니고 정상 아카이브가 생기지 않아야 한다. 6번은 사용자·경로·DAC·ACL·MAC·서비스 제한을 포함한다.

## 4. 다음 학습으로 이어가기

관심 분야에 따라 한 갈래씩 깊게 공부한다.

- **서버 운영**: 실제 배포판의 네트워크 설정 도구, LVM, RAID, NFS, 인증서 갱신, 모니터링과 장애 복구.
- **개발**: 파일 디스크립터, 소켓, fork/exec, 가상 메모리, strace, 동시성.
- **쿠버네티스**: network namespace, cgroup, OverlayFS, 컨테이너 런타임, DNS와 서비스 경로.
- **자동화**: ShellCheck, 재실행 안전성, 구성 관리, 변경 이력과 복원 절차.

명령을 외우기보다 필요할 때 도움말에서 정확한 옵션을 찾고, 작은 실험으로 가설을 확인하는 습관을 유지한다.
